# BUG-20260528-0930 — `aiplane::ipc::tests::daemon_smoke_run_roundtrip_via_fake_workload` races on socket-bind under high parallelism

## Status
Open. Pre-existing flake first observed in `specs/runs/RUN-2026-05-25T21-15-17Z.md` line 36
(2026-05-25) and re-tripped during the `/march` walk of `sy-file-manager` Step 16
(2026-05-28). Not caused by either roadmap.

## Symptom

```
thread 'aiplane::ipc::tests::daemon_smoke_run_roundtrip_via_fake_workload' panicked at
src/aiplane/ipc.rs:1608:10:
called `Result::unwrap()` on an `Err` value: DaemonDown
```

Reproduces with `make test` (which delegates to `cargo test --workspace --all-targets`
at the default 24-thread parallelism on the dev machine).

## Workaround

`cargo test --workspace --all-targets -- --test-threads=2` runs clean
(1083 passed / 0 failed / 11 ignored as of 2026-05-28).

## Suspected root cause

Socket-bind in the test's daemon-spawn helper races a sibling test that also reaches
into the same `$XDG_RUNTIME_DIR/aiplane.sock` path. Either:

- the test isn't picking a per-test isolated socket path, or
- the daemon-spawn handshake doesn't wait for `bind()` before the client tries to
  `connect()`.

## Out of scope here

Fixing this flake is the responsibility of the aiplane plane's owner / a separate
bug-fix loop. `/march` for `sy-file-manager` continues — Step 16's own surface
(`file::fs::copy::tests::*` + `step16_…` E2E) is green under the workaround and the
flake is unrelated to the file plane.

## Reproduction recipe

```sh
make test   # fails intermittently with the daemon_smoke panic above
cargo test --workspace --all-targets -- --test-threads=2   # green
```
