# BUG-20260927-1500: every daemon ran with half of its log sinks, silently

## Summary

`main` installed the CLI `tracing` subscriber before clap dispatch, so all
six daemon subcommands' `obs::init(Mode::Daemon { .. })` hit `tracing`'s
one-subscriber-per-process rule and degraded to a no-op — no journald layer,
no rolling JSONL — and nothing in `sy doctor` could see the throttled plane
that this silence was hiding.

## Reproduction

- Method: manual, then test.
- Command: `systemctl --user restart sy-knowledge.service && sy knowledge
  status && ls -l $XDG_STATE_HOME/sy/logs/sy-knowledge/`
- Evidence: the dual-sink directory is a zero-byte generator — 375 files
  across the plane directories, none of them non-empty, `du` reports the
  whole tree as 0 bytes:

  ```text
  $ find ~/.local/state/sy/logs -type f | wc -l
  375
  $ find ~/.local/state/sy/logs -type f -size +0c | wc -l
  0
  $ ls -l ~/.local/state/sy/logs/sy-knowledge/ | tail -2
  -rw-r--r--. 1 dmitriy dmitriy 0 Sep 26 sy-sy-knowledge.jsonl.2026-09-26
  -rw-r--r--. 1 dmitriy dmitriy 0 Sep 27 sy-sy-knowledge.jsonl.2026-09-27
  ```

  What `journalctl -u sy-knowledge` shows instead is systemd-captured
  **stderr** from the CLI subscriber (compact/JSON fmt lines, no
  `SY_*` fields, no syslog identifier) — the shape of a process whose
  `tracing_journald` layer was never built.
- Tests: `crates/sy-core/src/obs/mod.rs::tests::{init_cli_unless_defer_skips_the_cli_subscriber,
  deferred_notice_names_the_daemon_only_in_daemon_mode,
  prune_rotated_logs_deletes_only_stale_dated_files}`,
  `src/supervision/log_scope.rs::tests::daemon_subcommands_declare_ownership`.

## Expected

SPEC §4.6 `Mode::Daemon` = stderr **plus** `tracing_journald` (indexed
`SY_*` fields) **plus** a daily-rolling OTel JSONL appender under
`$XDG_STATE_HOME/sy/logs/<plane>/`, kept as the documented mitigation for
the `tracing-journald` silent-drop bug.

## Actual

stderr only. The JSONL appender was constructed (which is why its daily
files exist and why they are empty) and then thrown away with the
discarded subscriber; the journald layer never connected. Any operator
following the SPEC's "dual sink" promise found nothing to read, and
`journalctl` looked healthy because systemd captures stderr regardless.

## Root Cause

`src/main.rs` ran `obs::init(Mode::Cli)` unconditionally at the top of
`main()`, before `run(cli)` knew which subcommand it was dispatching. The
six plane entry points (`src/knowledge/daemon.rs`, `src/agt/daemon.rs`,
`src/stack/bar/app.rs`, `src/aiplane/worker/runner.rs`,
`src/mon/collect/mod.rs`, `src/mon/app.rs`) then call
`obs::init(Mode::Daemon { .. })`, whose `registry.try_init()` fails against
the already-installed CLI subscriber. `obs::init` chose the graceful branch
— return the `WorkerGuard`, keep the daemon alive — and its own comment
described both the symptom and the missing fix ("a future cleanup can defer
init until the subcommand is known so the daemon's journald + rolling
appender layers can win"). Two things kept that visible for months: stderr
traffic made `journalctl` look complete, and `sy doctor` reported
`pass=20 warn=1 fail=0` at the time the plane was being throttled into a
four-day outage (`BUG-20260927-0910`: 347 871 `memory.events high` hits,
PSI `full avg10` 69 %) because no check read a unit cgroup at all.

## Fix

1. **Defer, don't collide.** `Cmd::installs_own_subscriber()`
   (`src/supervision/log_scope.rs`) answers the question clap is best
   placed to answer; `main` calls
   `sy_core::obs::init_cli_unless(..)` and hands the global slot to the
   plane. The predicate lives under `supervision` because "which
   subcommand becomes a supervised unit" is supervision's knowledge, and
   because `src/main.rs` is LOC-budgeted at 1118 lines — the change is
   net-zero there.
2. **Make the drift loud.** `obs::init` now emits a one-line stderr notice
   (`deferred_subscriber_notice`) when a `Mode::Daemon` call loses the slot,
   naming the unit and pointing at the registration list. A future plane
   that forgets to register loses its sinks one restart, not four months,
   and the notice cannot itself use `tracing` — at that instant the
   process's logging is the thing that is broken.
3. **Give the roller a horizon.** `prune_rotated_logs` sweeps
   `<basename>.jsonl.<YYYY-MM-DD>` files older than
   `LOG_RETENTION_DAYS = 7` before opening the appender;
   `tracing_appender::rolling::daily` never deletes anything, so the
   directory only ever grew (76 stale files per plane). Fail-soft: an
   unreadable directory is not worth killing a daemon over.
4. **Close the doctor blind spot.** `supervision.cgroup_memory_throttle`
   (`src/doctor/checks.rs`) enumerates the installed `sy-*.service` units,
   reads each running cgroup's `memory.events`, `memory.pressure`,
   `memory.high`/`peak`/`current`, and reports per-unit numbers in
   `--json`: FAIL on any OOM kill, WARN on `MemoryHigh`/`MemoryMax` events,
   on PSI `full avg10 >= 10 %`, or on a peak within 90 % of the cap.
   Counters are since-unit-start, which is the honest reading — a restart
   clears them, a lingering cap problem does not.
5. **Bound the crash spool.** `configs/systemd/coredump.conf.d/sy.conf`
   sets `ExternalSizeMax=2G`, `MaxUse=2G`, `KeepFree=20G`: systemd-coredump
   defaults on a 64-bit host allow a 32 GiB core and a spool that may run a
   volume down to `min(15 %, 4 GiB)` free, which is an outage generator
   beside a 92 %-full root where the planes' cold start peaks at 19.5 GiB
   (three `sy` cores landed in one morning). Privileged install stays a
   documented one-liner — `sy apply` does not write `/etc`.
6. **Un-break `make docs-lint`** (same class of "the checker's word is the
   truth" bug): a `learn.chatgpt.com` citation that 403s was replaced by
   the canonical Codex reference URL, and the bot-walled OpenAI docs hosts
   are excluded in `lychee.toml` with the verification command recorded.
