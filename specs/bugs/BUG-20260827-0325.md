# BUG-20260827-0325: Signed upgrade leaves legacy Spark state unreadable

## Summary

A signed no-backward-compatibility Spark upgrade accepts stopped legacy instance records but the newly activated agent cannot read any durable model or instance state.

## Reproduction

- Method: real-device manual reproduction plus installer regression test.
- Command: `sy spark dgx-spark upgrade --yes ...`, followed by `sy spark dgx-spark ps --json`.
- Evidence: activation succeeded after legacy instances were stopped; `ps` then failed with `durable Spark state is unavailable` because stored `sy.spark.instance/v1` JSON has no required `artifacts` field.

## Expected

An approved signed no-compatibility upgrade rejects running incompatible state, but after the old workloads are stopped it quarantines only incompatible sy-managed model/instance documents and activates a clean current state with durable evidence.

## Actual

Pre-activation validation reads only running instance rows. Stopped legacy model and instance rows survive activation and make the current agent's state lists undecodable.

## Root Cause

Pre-activation validation decoded only rows whose SQL desired state was `running`. Stopped legacy instance and model JSON therefore survived a no-compatibility release switch even though every current list operation strictly decodes those rows.

## Fix

After release-signature verification, activation now rejects incompatible running rows and authoritatively quarantines only stopped incompatible model/instance rows. It first writes and integrity-checks an exact SQLite backup, removes dependent sy-managed rows in one transaction, and records the removed IDs plus backup name in the durable audit table. No legacy decoder, schema inference, merge, or wire migration was added.

## Traceability

- Failing test: `src/spark/install.rs::tests::upgrade_quarantines_only_stopped_incompatible_state`
- Fixed in: `src/spark/install.rs`
