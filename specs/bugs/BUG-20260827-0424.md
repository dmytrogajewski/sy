# BUG-20260827-0424: llama.cpp completion identifier rejected

## Summary

The real pinned llama.cpp engine returns `chatcmpl-*` from `/v1/completions`, but the semantic publication gate accepted only `cmpl-*` and rejected a valid immutable Qwen generation.

## Reproduction

`sy spark dgx-spark serve qwen3.8:27b --name qwen3-8-27b --json` failed with `semantic completion contract rejected`. An isolated request to the same digest-pinned image returned HTTP 200, `object=text_completion`, exact served model, one choice, valid usage, and identifier `chatcmpl-*`.

## Fix

The generic completion contract accepts non-empty `cmpl-*` and llama.cpp's non-empty `chatcmpl-*` identifiers while retaining every model, shape, finish, usage, size, and character check. No model name or policy was added to Rust.

## Traceability

- Test: `spark::upstream::tests::llama_cpp_completion_accepts_its_chatcmpl_identifier`
