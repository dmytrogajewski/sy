# BUG-20260826-0544: Spark launch clients fail on real agent traffic

## Summary

Claude Code can be rejected by the Anthropic compatibility boundary, while
OpenCode's concurrent title and main requests can crash Ornith's Qwen3.5 GDN
execution on DGX Spark.

## Reproduction

- Method: manual reproduction on `dgx-spark`
- Commands:
  - `sy spark dgx-spark launch claude --model ornith-1.5:9b`
  - `sy spark dgx-spark launch opencode --model ornith-1.5:9b`
- Evidence:
  - Claude Code 2.1.241 recorded HTTP 400: `request headers, query, or beta capability are invalid`.
  - OpenCode started a title request and main request concurrently. The vLLM
    scheduler recorded two running requests with 601 and 7,920 computed tokens,
    then Qwen3.5's GDN output projection failed in BF16 `cublasGemmEx` with
    `CUBLAS_STATUS_INTERNAL_ERROR`.
  - Docker reported `OOMKilled=false`; the kernel recorded no NVIDIA Xid or OOM
    event.

## Expected

Both documented launch commands complete streamed agent turns without exposing
unsupported client capabilities or crashing the serving generation.

## Actual

Claude can fail before model execution, and OpenCode can withdraw the healthy
route after killing the vLLM engine process.

## Root Cause

The real Claude launcher omitted the experimental-beta suppression required by
the pinned 2.1.241 compatibility harness. Separately, the Qwen3.5 profile
allowed vLLM to combine OpenCode's title decode with its large main prefill in
one mixed GDN batch on GB10.

## Fix

Disable experimental Claude Code betas in the real launcher. Keep generic and
Qwen3 serving concurrency in declarative engine configuration, while limiting
Qwen3.5 profiles to one sequence until its GB10 mixed-batch GDN path is durable.
Do not run an unrelated full reconciliation synchronously after an explicit
stop; the periodic/event-driven reconciler already owns recovery, and the extra
pass can monopolize the high-memory transition coordinator before the intended
replacement serve.

## Traceability

- Failing tests:
  - `spark::launch::tests::claude_adapter_uses_native_route_exact_args_and_inference_secret`
  - `spark::engine::tests::qwen35_profile_serializes_mixed_gdn_batches`
  - `spark::engine::tests::qwen3_profile_preserves_parallel_serving`
  - `spark::agent::tests::explicit_stop_completes_one_removal_while_transition_is_busy`
- Fixed in:
  - `src/spark/launch.rs`
  - `src/spark/agent.rs`
  - `configs/sy/spark/engine.toml`

## Verification

- `make lint` and `make test` pass, including 1,101 library tests.
- The pinned Claude Code 2.1.241 Anthropic streaming/tool-round-trip test passes.
- The signed aarch64 release was installed on `dgx-spark` without changing the
  protected platform fingerprint.
- Ornith generation 27 started with vLLM 0.27.1, `--enforce-eager`, and
  `--max-num-seqs 1` selected from the `qwen3_5` configuration profile.
- A real headless Claude launch emitted streamed thinking and text events,
  returned `CLAUDE_SPARK_OK`, and exited successfully.
- A real OpenCode launch emitted its JSON event stream, returned
  `OPENCODE_SPARK_OK`, and exited successfully. Its title and main requests both
  returned HTTP 200.
- After both runs, generation 27 remained healthy with no restart, failure,
  CUBLAS, CUDA, traceback, or EngineCore-failed event; the scheduler returned to
  zero running and waiting requests.
