# BUG-20260921-1148: Installer inherits private umask for executable directories

## Summary and reproduction

During the v0.1.3 migration, baseline qualification passed (median decode
33.8405 tokens/s), state was snapshotted and relocated, and the root executor
started. The agent failed with systemd 203/EXEC: the signed executable was 0555
but its root-owned release directory and three catalog directories were 0700.
The root deployment shell used umask 077. The installer explicitly set parent
directory and file modes but omitted these newly created child directories.

The pinned fallback virtual environment also inherited the private umask.
These trees contain public immutable application code, not credentials.

## Expected and fix

Explicitly assign public executable-tree directory modes, independent of umask;
retain root-only write access. Model data, private configuration, keys, snapshots
and journals remain private. Correct only the exact inspected release directories
on the active host; no signed payload bytes, fence, journal or confinement rules
are changed. This repair unblocked execution, which then exposed the separate
emergency-journal migration defect and required supported transaction recovery.

## Traceability

The private tempfile regression in `spark::install` reproduces the inaccessible
release root before the fix. Extend coverage to nested directories and fallback
code permissions without following symlinks or changing their targets.

## Resolution

Released in Sparkplane v0.1.4 through PR #7. Both public-code regressions and all
lint/test gates pass. The actual root migration under private umask completed
successfully, with the unprivileged agent and root executor active.
