# BUG-20260828-1826 — Responses request without reasoning panics the gateway

## Report

An otherwise valid OpenAI Responses request that omits the optional `reasoning`
object resets its HTTP/2 stream because the Spark gateway indexes the absent map
key and panics.

## Evidence

The real DGX Spark agent panicked at `src/spark/gateway.rs:2119` for a request
containing `model`, string `input`, `max_output_tokens`, and `stream`, but no
`reasoning`. The existing string-input translation test reproduces the panic.

## Acceptance

- Omitted `reasoning` yields no upstream reasoning-effort override.
- An explicit supported effort is still mapped by declarative engine policy.
- Valid Responses requests never panic the HTTPS worker.
- Non-streaming and streaming Responses journeys pass through the real Spark.
