# BUG-20260827-0053: cross-filesystem stream copy can expose an incomplete final write

## Summary

The cross-filesystem byte-stream copy could report completion before Tokio had drained its final asynchronous file write, making its byte-integrity test flaky under full-suite blocking-pool contention.

## Reproduction

- Method: test under the full parallel workspace suite
- Test: `src/file/fs/copy.rs::tests::cross_fs_uses_stream_copy`
- Command: `make test`
- Evidence: the main `sy` test binary failed at `src/file/fs/copy.rs:901` with `byte-stream copy must land src bytes byte-for-byte`; the destination began with the expected `0x42` bytes but differed from the complete 1 MiB source payload.
- Focused reproduction: running 512 pre-fix focused copies across the five binaries that compile `copy.rs`, with 32 processes in parallel, reproduced the assertion. The failed destination contained 946,176 bytes while the source oracle contained 1,048,576 bytes, all `0x42`. The same test passed in normal focused execution and in 20 full high-parallel `sy_file_journey_e2e` runs. This timing sensitivity isolates the failure to blocking-I/O completion under load rather than content transformation.

## Expected

`copy_one_stream` must not return `CopyDone::Completed` until every accepted source byte is visible through the destination file.

## Actual

At source EOF, `copy_one_stream` immediately emitted final progress and returned. Tokio file writes use blocking work internally, so the final accepted `write_all` could still be draining when the caller opened and read the destination.

## Root Cause

Every non-final write is forced to settle when the next write polls the same `tokio::fs::File`. The final write has no successor: after the reader reports EOF, the function returned without polling `AsyncWriteExt::flush`. Under ordinary focused execution the blocking write usually finished first; full-suite blocking-pool contention widened the final-write window enough for the destination assertion to observe incomplete contents. The fixture uses a unique `tempfile::TempDir`, and no test mutates `TMPDIR`, so no shared path or source/destination alias was present.

## Fix

Flush the Tokio destination file after source EOF and before emitting final progress or returning `Completed`. The existing byte-for-byte assertion remains unchanged and now runs only after the final write is drained.

## Traceability

- Failing test: `src/file/fs/copy.rs::tests::cross_fs_uses_stream_copy`
- Fixed in: `src/file/fs/copy.rs`
- Verification: 512/512 post-fix concurrent focused runs; `make lint` and `cargo fmt --check`; two complete `make test` runs at 1,857 passed, 0 failed, 13 ignored each
