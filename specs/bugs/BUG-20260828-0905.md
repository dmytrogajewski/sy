# BUG-20260828-0905: Control upgrade loses routes for healthy engines

## Summary

After a signed control-plane upgrade, durable instances still report healthy
but their public inference routes are absent.

## Reproduction

- Keep the healthy `qwen38-flash-next-nvfp4` generation running.
- Activate a signed sy release side by side.
- The container ID, generation, restart policy, and restart count are unchanged,
  while `/openai/qwen38-flash-next-nvfp4/v1/models` returns the sy route 404.
- A direct executor probe sends 11 durable instances in 45,509 bytes and receives
  `NotReady`; several entries are stopped records with deliberately unsupported
  historical engine fingerprints.

## Expected

Startup reconciliation validates and republishes desired-running generations.
Stopped records do not require current engine support; any unexpected remaining
container for such a record is untrusted and quarantined.

## Actual

`reconcile_once` sends every durable instance as a required current-catalog
expectation. The executor rejects the whole scan when any stopped historical
record no longer matches the authoritative engine catalog.

## Root Cause

The expected-container set was derived from inventory rather than desired
intent. This coupled route recovery for current workloads to compatibility with
all historical stopped records.

## Fix

Build executor expectations only from `desired=running` instances. The executor
still scans every sy-managed container, so a container outside that expected set
is quarantined. Redeploy without restarting the engine and verify exact route
republication plus protocol recovery.
