# BUG-20261018-1627: PolicyKit bypasses sudo authenticators; phone pairing fails

## Summary

Desktop privilege prompts use a different PAM stack from sudo, and phone
authentication has no active bond after failed attempts to pair again.

## Reproduction

- Host: Fedora 44, BlueZ adapter hci0, Samsung phone connected over ADB.
- `/etc/pam.d/sudo`: sufficient pam_syauth, sufficient pam_u2f, system-auth.
- `/usr/lib/pam.d/polkit-1`: auth include system-auth; no local override.
- `syauth list`: three records, all explicitly revoked.
- `syauth status --json`: daemon up, peers empty.
- Prior daemon journal: `notifier_slot=None`, outcome transport-error.
- Installed CLI and daemon date from May 21; Android app from May 28.
- Upstream local bug report: `../syauth/specs/bugs/BUG-20261018-0120.md`.

## Expected

PolicyKit uses sudo's authentication factors while retaining its own account
and session checks. Pairing asks the operator to verify matching codes,
creates a new active bond, and permits a real phone unlock.

## Actual

PolicyKit skips phone and FIDO. Stored revoked bonds cannot unlock. The old
installed CLI predates the upstream fix that wires the numeric confirmation
handler before radio access.

## Root Cause

PolicyKit is an independent PAM consumer; configuring sudo does not configure
polkit-1. The syauth daemon correctly excludes revoked bonds. Pairing and
phone challenge transport require separate verification against the real phone.

## Fix

Managed polkit-1 configuration includes only sudo's auth stack and keeps
system-auth for account, password, and session management. Installation must
preserve an existing override, support dry run, and be repeatable. Validate
the repaired upstream CLI before using it for fresh pairing; never reactivate
revoked records without a successful pairing.

## Traceability

- Regression tests: `crates/sy-auth/tests/polkit.rs`.
- Managed configuration: `configs/pam/polkit-1`.
- Deployment and live phone verification: recorded after execution below.

## Live verification

2026-10-18 MSK:

- Installed the managed `/etc/pam.d/polkit-1` configuration.
- `pkexec /usr/bin/true` passed; audit recorded `grantors=pam_syauth`.
- Repaired and installed the companion APK from `../syauth`; completed the
  matching four-symbol confirmation over ADB and the repaired desktop CLI.
- Phone displayed `Paired with fedora`; app reopening retained the paired card.
- Replaced idle lxpolkit with enabled `sy-polkit-agent.service`. A live request
  showed the real action and account in the sy dialog and completed successfully
  with phone authentication at 16:55:22 (`pam_syauth: unlock success`).
- The syauth daemon remained running; revoked bonds were not reactivated.

The deployed PAM phone timeout is 8000 ms. Later live challenges reached the
phone immediately but were approved after 18–28 seconds, after the daemon had
already recorded response-timeout. pkexec still completed through the remaining
PAM chain. Pairing is retained; late phone responses do not authorize expired
requests. The 16:55 successful phone request completed within its deadline.
