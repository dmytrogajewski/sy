# BUG-20260828-1900 — Anthropic token counting assumes a tokenizer route

## Report

`POST /anthropic/{instance}/v1/messages/count_tokens` always translated the
request to the engine-specific `/tokenize` shape. FreeToken exposes Anthropic's
native `/v1/messages/count_tokens` route instead, so Claude Code could generate
normally but its context-accounting request failed as unavailable.

## Evidence

The pinned FreeToken engine advertises native Anthropic token counting and the
real `dgx-spark` returned `{"input_tokens":13}` for a messages request. The
gateway's route inventory can distinguish that native route from llama.cpp's
private `/tokenize` route without inspecting an engine or model name.

## Acceptance

- The gateway preserves the Anthropic request shape and rewrites only the
  served-model identity when the selected engine declares the native route.
- Engines that declare only `/tokenize` continue to receive the private
  tokenizer request shape.
- Both upstream response shapes become Anthropic's
  `{"input_tokens":<integer>}` public document.
- Unit, integration, and real Spark token-count requests pass without embedding
  an engine-family branch in Rust.
