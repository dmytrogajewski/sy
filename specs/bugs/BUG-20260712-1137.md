# BUG-20260712-1137: pinned-arm INFINITY score serialises to JSON null, breaking status decode and log tail

## Summary
While a manual pin is active, the daemon records the pinned arm's ranked
score as `f32::INFINITY`. `serde_json` emits `null` for a non-finite
float, and `AuditEntry.ranked_actions: Vec<(String, f32)>` has no
null-tolerant deserialiser — so every pinned audit line fails to parse.
This surfaces as two symptoms with one root cause:

- **E** — `sy power status --json` (while pinned) fails with
  `decode: invalid type: null, expected f32`, is mis-reported as
  `sy-powerd unreachable` (exit 4) even though the daemon answered.
- **F** — `sy power log --since=<short>` returns "no entries in window"
  for windows that contain only pinned lines, while a longer window that
  reaches back to unpinned lines returns entries. The tail scanner
  silently `continue`s past every unparseable (pinned) line.

## Reproduction
- Method: manual (live daemon) + hermetic unit tests
- Tests:
  - `crate::power::log::tests::audit_entry_with_nonfinite_score_round_trips`
  - `crate::power::cli::tests::decode_error_is_not_reported_as_unreachable`
- Command (live):
  ```
  sy power profile flat-out
  sy power status --json      # -> exit 4 "sy-powerd unreachable: decode: invalid type: null, expected f32 at line 1 column ~1946"
  sy power log --since=5s      # -> "no entries in window"
  sy power log --since=10m     # -> 446 entries (reaches pre-pin unpinned lines)
  ```
- Evidence: raw IPC status frame at column 1946:
  `"ranked_actions":[["flat-out",null]]`. Recent NDJSON lines while
  pinned carry `"ranked_actions":[["flat-out",null]]`; clearing the pin
  and waiting makes `--since=5s` return entries again.

## Expected
Pinned audit lines round-trip: `sy power status --json` prints and exits
0 while pinned; `sy power log --since=<short>` returns the recent pinned
entries. A frame that genuinely fails to parse is reported as a decode
error, not as "daemon unreachable".

## Actual
`f32::INFINITY -> null` on serialise; `null -> f32` is rejected on
deserialise, so the whole `AuditEntry` fails to parse. The IPC path
propagates this as an `io::ErrorKind::InvalidData`, which the CLI maps
onto `EXIT_DAEMON_UNREACHABLE` with a misleading "unreachable" message.

## Root Cause
`AuditEntry.ranked_actions` violates the codebase's H1 non-finite-float
convention (see `snapshot::deserialize_features_null_as_nan`): the
serialiser emits `null` for non-finite floats but the field's default
deserialiser cannot read `null` back. The pin path
(`daemon.rs` `format!("pin:{name}")` branch) records
`(name, f32::INFINITY)`.

## Fix
1. Add `deserialize_ranked_null_as_nan` and attach it to
   `AuditEntry.ranked_actions` (`null -> f32::NAN`), mirroring the H1
   feature-array shim. Pinned lines now parse: the tail scanner keeps
   them (fixes F) and the IPC `last_audit` decodes (fixes E).
2. `cli::classify_dial_error` distinguishes an `InvalidData` decode
   failure (daemon answered, frame unparseable -> `EXIT_DECODE_ERROR`,
   message names the parse failure) from an unreachable socket
   (`EXIT_DAEMON_UNREACHABLE`). `status` and `profile` dials use it.
