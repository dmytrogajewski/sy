# BUG-20260827-0851: Launch rejects an installed instance name

## Summary

`sy spark launch --model` rejects a stopped instance name copied from `sy spark ps` even though that instance's immutable model is installed.

## Reproduction

- Method: manual and unit test.
- Test: `spark::launch::tests::stopped_instance_name_resolves_its_installed_model`.
- Command: `sy spark dgx-spark launch claude --model ornith-1-5-35b --dry-run --json`.
- Evidence: exit 2 with `Spark model "ornith-1-5-35b" is not installed` while `ps` lists that stopped instance and its installed model.

## Expected

An exact instance name resolves its installed model and is retained as the managed instance name when launch must serve it again.

## Actual

Launch resolves only model IDs, canonical identities, repositories, and aliases before fetching instances, then emits false download remediation.

## Root Cause

`launch::run` resolved the explicit value against the model inventory before it
requested the instance inventory. Consequently, an exact instance name could
not map through its persisted `model_id`. Even if only the model had been
resolved, launch would have generated a different `launch-*` name instead of
re-serving the selected stopped instance. The first correction also exposed a
second boundary error: admission and serve requests reused the user's instance
name in their `model` field, which accepts model references only and returned
HTTP 404.

## Fix

Fetch both inventories before resolution. An exact instance-name match now
resolves the installed model through `model_id` and becomes the preferred name
when launch must serve the model. Admission and serve requests use that
resolved immutable model ID, while the original value remains the instance
name. All existing model reference forms retain their prior behavior.

## Traceability

- Failing tests:
  `src/spark/launch.rs::tests::stopped_instance_name_resolves_its_installed_model`
  and `stopped_instance_serve_uses_resolved_model_id`.
- Fixed in: `src/spark/launch.rs`.
- Real verification: the exact instance-name dry-run selected action `serve`,
  then a headless Claude Code 2.1.241 launch streamed a response of `OK` from
  Ornith and exited 0; the instance remained healthy under
  `ornith-1-5-35b`.
