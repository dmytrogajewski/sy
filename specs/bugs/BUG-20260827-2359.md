# BUG-20260827-2359: Spark model profiles cannot bound pathological reasoning

## Symptom

A fresh `sy spark dgx-spark launch codex --model ornith-1.5:9b-q4-k-m`
Tetris run inspected the correct empty workspace, then generated about 26,200
reasoning tokens for 786 seconds without creating a file or making a second
tool call. The engine remained healthy at roughly 34 tokens per second.

## Expected

Recommended models may select a declarative engine profile from
`models.toml`. Ornith keeps reasoning enabled, but its coding profile bounds a
single reasoning phase and injects an explicit transition to tool use.
Unconfigured models continue using the engine's unrestricted generic default.

## Root cause

Engine profiles could only be selected from `config.json:model_type`. GGUF
catalog entries intentionally download exact weight/projector artifacts and do
not necessarily include `config.json`, so every GGUF fell into the generic
profile. There was no declarative connection between a recommended model entry
and a model-specific engine profile.

## Reproduction evidence

- Worktree: `~/sources/testbed/spark-tetris-fresh-20260827/ornith9-codex-fixed2`
- Wall time: 786.41 seconds
- Generated tokens before cancellation: approximately 26,200
- Files created: zero
- Engine health: healthy; no restart and no 503

## Fix

Add an optional `engine_profile` to the signed model artifact declaration and
wire document. Engine selection validates and resolves that explicit profile
before falling back to embedding, `model_type`, or the engine default.
Configure Ornith's coding profile with reasoning preservation, a 16,384-token
reasoning budget, and an action-transition message; do not disable reasoning.

## Verification

- Catalog test proves Ornith resolves to the configured profile.
- Engine test proves explicit selection, unknown-profile rejection, and
  unrestricted fallback for unconfigured artifacts.
- A signed Spark upgrade and fresh real Codex run must create and verify the
  Tetris project without a 503 or `max_output_tokens` truncation.
