# BUG-20260525-2353: bandit posterior + FTRL classifier state is in-memory only; every daemon restart wipes accumulated learning

## Summary
`BanditTickState` and `ActivityTickState` (`src/power/daemon.rs`) are constructed fresh on daemon startup and never persisted. The CLUCB bandit's per-arm count / mean / variance accumulators, the conservative baseline mean, and the FTRL classifier's per-class weight vectors all live in `Arc<RwLock<...>>` slots that hold zero-initialised structs after every `sy-powerd` process boot. The daemon has restarted ~7+ times over the 4-day collection window (different PIDs in `journalctl --user -u sy-powerd.service`: 4419, 4150, 4144, 4151, 4173, 1857644, 4138, 4139 — each restart is a fresh `Main PID`). Nothing on disk under `~/.local/state/sy/power/` carries the learned state — only the NDJSON telemetry log (which is read-only audit, not state). After the day-14 first-train fires and the bandit unfreezes, every `sy apply` / `systemctl restart` / crash / suspend-resume cycle will throw away the CLUCB posterior and the FTRL weights. The system will perpetually behave as if it's on day 14, never accumulating multi-restart experience. This bug is latent during onboarding (both structs are frozen per Step 26 — the bandit doesn't `update` and the classifier doesn't `partial_fit` until pins or — once BUG-20260525-2351 is fixed — rules-baseline labels start producing signal), but becomes the dominant failure mode the moment onboarding ends.

## Reproduction
- Method: code audit + journal restart count (test repro lands with the fix).
- Live evidence (restart count over the collection window):
  ```
  $ journalctl --user -u sy-powerd.service --since '4 days ago' \
      --output=cat | grep -oP 'sy-powerd\[\K[0-9]+' | sort -u | wc -l
  8                                  # 8 distinct PIDs ⇒ ≥ 7 restarts in 4 days
  ```
- Code-level evidence:
  - `src/power/bandit/clucb.rs::Clucb::new` — zero-initialised counts/means/variances; no `from_state` / `from_disk` constructor.
  - `src/power/activity.rs:179-193` — `OnlineClassifier::new()` ships all-zero weights.
  - `src/power/daemon.rs::run_async` — both states constructed via `Default::default()` / `new()`; no read-from-disk before tick loop, no write-to-disk on shutdown.
  - `grep -rE '(save|persist|reload|load_state|state_file|bincode|posterior.*save)' src/power/bandit/ src/power/activity.rs src/power/daemon.rs` → zero matches (other than `Powersaver` enum noise).
  - No `~/.local/state/sy/power/` artefacts besides NDJSON telemetry, reports, and the (currently absent) `forecaster.onnx`:
    ```
    $ ls -la ~/.local/state/sy/power/
    drwxr-xr-x ... reports/
    -rw-r--r-- ... telemetry-2026-05-20.ndjson
    ... (six telemetry files, nothing else)
    ```
- Reproducible cycle (manual, post-fix would catch it):
  1. `systemctl --user restart sy-powerd`.
  2. `sy power status --json | jq '.bandit.{ucb_score, top3, baseline_arm}'` → all baseline / zero.
  3. Let daemon run, accumulate ticks, observe `ucb_score` drift away from 0.
  4. `systemctl --user restart sy-powerd`.
  5. `sy power status --json | jq '.bandit.{ucb_score, top3, baseline_arm}'` → back to zero. Confirmed loss.

## Expected
1. CLUCB posterior (per-arm `count`, `mean`, `M2` for Welford variance, plus the conservative baseline accumulator) is checkpointed to a small file under `~/.local/state/sy/power/` at controlled cadence: at minimum on graceful shutdown, ideally also every N ticks (default N=300, i.e. once per 5 minutes at 1 Hz) so a SIGKILL loses at most 5 minutes of learning.
2. FTRL classifier's per-class weight vectors are checkpointed alongside.
3. On daemon startup, both structs are loaded from disk if the checkpoint exists and matches the current `arms` schema (config hash); otherwise zero-init as today.
4. Schema drift (arm added / removed / renamed in `configs/sy/power.toml`) invalidates the checkpoint cleanly — start from zero with an INFO log "checkpoint schema mismatch, re-learning".
5. Checkpoint format is versioned + self-describing (NDJSON or a single bincode blob with a `version: u32` field), atomic-write (tmp + rename) per the trainer's `FileSink::commit` precedent.

## Actual
1. No persistence anywhere. Every PID transition resets both structs.
2. The bandit's `baseline_mean()` resets to NaN/0 → the conservative gate is re-bootstrapped from scratch every restart, biasing arm selection toward whichever arm picks first.
3. The classifier's weights reset to zero → `activity_label` returns to `Idle` even if BUG-20260525-2351 is fixed.
4. The system has no way to accumulate experience across `sy apply` cycles, which on this host happen multiple times per day.

## Root Cause
- **Persistence layer simply doesn't exist** for either struct. The roadmap (Step 20: CLUCB, Step 29: FTRL classifier) shipped each as an in-memory primitive without a checkpoint contract. The trainer's ArcSwap'd ONNX is the only "model state" with a disk anchor; the bandit + classifier are treated as ephemeral.
- **Onboarding's "frozen state" design masks the bug.** Because both structs don't mutate during the 14-day onboarding (per Step 26's `if !onboarding_active { bandit.update(...) }` gate), the lack of persistence is invisible during the period when restarts are most common (rebuild + install cycles during development). It only bites once onboarding ends.

## Fix
1. **Add a checkpoint module** `src/power/checkpoint.rs`:
   - `pub struct DaemonCheckpoint { schema: u32, arms_hash: u64, bandit: ClucbState, classifier: ClassifierState, saved_at: DateTime<Utc> }`.
   - `ClucbState` mirrors `Clucb`'s private fields verbatim (counts, sums, M2s, baseline accumulator, conservative_alpha).
   - `ClassifierState` mirrors `OnlineClassifier`'s per-class FTRL weight vectors.
   - `pub fn save(checkpoint: &DaemonCheckpoint, path: &Path) -> Result<()>` — atomic write (tmp + rename), JSON for human-debuggability.
   - `pub fn load(path: &Path, expected_arms_hash: u64) -> Result<Option<DaemonCheckpoint>>` — returns `Ok(None)` if absent or arms-hash mismatch (the latter logs INFO and rotates the file to `.stale-<ts>`).
2. **Wire load on daemon startup** (`src/power/daemon.rs::run_async`):
   - After config load, compute `arms_hash = hash(serde_json::to_string(&cfg.arms))`.
   - `checkpoint::load(&state_dir.join("checkpoint.json"), arms_hash)?` — if `Some(c)`, hydrate `BanditTickState.bandit.restore(c.bandit)` and `ActivityTickState.classifier.restore(c.classifier)`.
   - Add `Clucb::restore(&mut self, state: ClucbState)` and `OnlineClassifier::restore(&mut self, state: ClassifierState)` — public surface limited to deserialise-then-overwrite, no other mutation.
3. **Wire save** at two cadences:
   - **Periodic:** every `CHECKPOINT_INTERVAL_TICKS = 300` ticks (5 minutes at 1 Hz), inside the tick loop. Cheap — both structs are < 1 KB serialised.
   - **Graceful shutdown:** on SIGTERM / SIGINT, after the tick loop exits but before `run_async` returns. Use `tokio::signal::ctrl_c` + the existing `SystemNotifier` shutdown path.
4. **Tests** (`src/power/checkpoint.rs::tests`):
   - `round_trips_bandit_state_through_disk` — populate Clucb with synthetic counts/means, save, load, assert deep equality.
   - `round_trips_classifier_state_through_disk` — same for OnlineClassifier.
   - `schema_mismatch_rotates_stale_file` — write a checkpoint with `schema=1`, bump `CHECKPOINT_SCHEMA` to 2 in test cfg, assert `load` returns `Ok(None)` AND the original file moved to `.stale-<ts>`.
   - `arms_hash_mismatch_treated_as_absent` — same as above but with arms list mutated; assert clean re-init.
5. **Integration test** `tests/power_checkpoint_survives_restart.rs`:
   - Spawn daemon under hermetic state_dir + `SY_SYSFS_ROOT` (existing pattern from BUG-2026-05-21-sy-power-hotfix Step H2 retry).
   - Drive 10 ticks via synthetic snapshots that produce non-trivial bandit updates (requires test-mode bypass of onboarding gate — or simply use the post-onboarding path).
   - Kill the daemon, restart, assert `sy power status --json | jq '.bandit'` reflects the pre-restart accumulators.
