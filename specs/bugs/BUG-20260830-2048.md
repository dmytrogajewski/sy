# BUG-20260830-2048: Responses fragments assistant turns

## Summary

The Spark Responses adapter encodes one logical Codex assistant turn as
multiple Qwen chat messages, allowing progress commentary to terminate before
the tool call that should follow it.

## Reproduction

- Method: unit test and captured live DGX Spark session
- Test: `src/spark/gateway.rs::responses_coalesces_one_assistant_turn_for_qwen_history`
- Command: `cargo test --features spark-agent responses_coalesces_one_assistant_turn_for_qwen_history`
- Evidence: the rewritten assistant message contained only
  `reasoning_content`; its commentary and function call occupied two additional
  assistant messages. In the live session, Codex recorded `task_complete`
  immediately after non-terminal progress commentary and no tool call.

## Expected

A contiguous Responses sequence of reasoning, assistant commentary, and
function calls is encoded as one Qwen assistant message containing
`reasoning_content`, `content`, and `tool_calls`.

## Actual

Each Responses item becomes an independently terminated assistant chat
message.

## Root Cause

`response_messages` maps each Responses input item one-to-one into a chat
message. The adapter merges system messages but does not coalesce adjacent
assistant items into the single assistant turn required by Qwen's chat
template.

## Fix

Coalesce adjacent assistant items while preserving reasoning text, visible
content, and every function call. User and tool messages remain turn
boundaries.
