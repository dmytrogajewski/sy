# BUG-20260829-0812: stop verification rejects legitimate placeholder identifiers

## Summary

The stop-verification hook blocks completed code when a legitimate identifier contains the word `placeholder`.

## Reproduction

- Method: integration test
- Test: `tests/stop_verify_hook.rs::legitimate_validation_identifier_does_not_block_stop`
- Command: `cargo test --test stop_verify_hook legitimate_validation_identifier_does_not_block_stop -- --exact`
- Evidence: the hook returned `decision: block` for `pub fn validate_placeholders() {}`.

## Expected

The hook permits legitimate domain identifiers while continuing to reject explicit deferred-work markers and stub macros.

## Actual

The hook's unbounded plain-word matcher treats every occurrence of `placeholder` as deferred code, including identifiers and tests.

## Root Cause

Both verification-hook scans include the bare word `placeholder` in the same regular expression as explicit markers such as `TODO`, `FIXME`, `todo!`, and `unimplemented!`. They therefore cannot distinguish a legitimate identifier from stub language.

## Fix

Remove the ambiguous bare-word alternative from both hooks while retaining the explicit marker and macro alternatives. Cover both the legitimate-identifier case and an explicit deferred-work marker with isolated fixtures.

## Traceability

- Failing tests: `tests/stop_verify_hook.rs::legitimate_validation_identifier_does_not_block_stop`, `tests/stop_verify_hook.rs::legitimate_validation_identifier_does_not_trigger_post_edit`
- Fixed in: `.claude/hooks/stop-verify.sh`, `.claude/hooks/post-edit-check.sh`, `tests/stop_verify_hook.rs`
