# BUG-20260921-1152: Executor emergency journal is missing namespace migration

## Reproduction and cause

After the installer permission fix allowed execution, the new agent rejected
`emergency record is invalid`. The separately stored executor JSONL journal had
12 legacy `sy.spark.emergency-record/v1` entries; its nested decisions also use
legacy schemas. Database emergency evidence was deliberately preserved, but
the migration omitted the executor's replay journal outside SQLite.

## Expected and fix

Preflight must validate every legacy journal entry against its already imported
database evidence before fencing. The snapshot stages a typed namespace-only
conversion. Activation retains the exact original file in the private snapshot;
recovery restores that file and retains any failed-generation journal separately.
No event, evidence, suppression state or signed payload is discarded or edited.
Unknown schemas, unmatched evidence and symlinks fail closed.

## Live handling

The runner was terminated while waiting for health (never committed), then its
supported `--recover` command restored the original deployment and exact engine.
No new engine started during the failed activation. Public release-directory
mode repairs moved back into the failed staging tree during recovery. The old
engine then encountered the separate cold-start service timeout recorded in
BUG-20260921-1220. Its managed replacement was approved through the signed
recovery handoff; no audit evidence was discarded.

## Resolution

PR #7 and signed v0.1.4 include evidence-matched conversion, exact reversible
exchange and real DbActor replay coverage. The live v0.1.4 transaction committed;
the agent successfully replays the converted journal. All appliance/client tests,
lint and audit gates passed, followed by complete live inference qualification.
