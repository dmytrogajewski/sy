# BUG-20260927-0119: wiped NPU model cache kills the knowledge plane and hides its bar applet

## Summary

Deleting the embed/rerank ONNX artifacts out of `~/.cache/sy` makes
`sy knowledge daemon` exit(1) at start-up, which latches
`sy-knowledge.service` into `failed` after five fast retries and — because
the waybar tile renders *invisible* rather than *broken* — leaves the
`custom/sy-knowledge` applet looking like it was never configured, while
`sy doctor` still reports `fail: 0`.

## Reproduction

- Method: manual (live host, Fedora 43, Strix XDNA2) + unit tests below.
- Command:
  ```
  systemctl --user status sy-knowledge.service      # failed since Sep 25 20:21
  sy knowledge waybar                              # {"class":"hidden","text":"",...}
  sy doctor --json | jq .summary                   # {"pass":14,"warn":3,"fail":0,"skip":3}
  ```
- Evidence:
  ```
  sy-knowledge[7612]: ERROR worker load failed kind=embed reason="embed model not found
    at /home/dmitriy/.cache/sy/aiplane/multilingual-e5-base/multilingual-e5-base.bf16.onnx"
  sy-knowledge[7597]: Error: init aiplane supervisor
  systemd[4234]: sy-knowledge.service: Start request repeated too quickly.
  systemd[4234]: Failed to start sy-knowledge.service.
  ```
  `~/.cache/sy/aiplane/multilingual-e5-base/*.onnx*` were symlinks into
  `~/.cache/sy/npu-embed/`, whose multi-GiB blobs were removed on
  2026-09-19 08:19 alongside `bge-reranker-v2-m3` and `whisper-medium`
  blobs (disk at 91 %). Dirs survived, so the plane looks "prepared".

## Expected

* A plane that is configured but dead is **visibly** dead in the bar.
* Losing an optional-but-required on-disk artifact degrades the plane
  (search over an existing index keeps answering; embed-dependent calls
  error) instead of killing every consumer of the shared IPC socket.
* A rebuilt artifact heals the plane without a human running
  `systemctl --user reset-failed`.
* `sy doctor` names the missing artifact and the exact rebuild command.

## Actual

* `sy knowledge waybar` emits `{"class":"hidden","text":""}` and
  `configs/waybar/style.css:126` collapses `.hidden` to zero width — the
  applet disappears, indistinguishable from "plane not installed".
* `init_aiplane_supervisor` (`src/knowledge/daemon.rs:179`, `:891`, `:912`)
  treats any worker-not-Ready as fatal → `exit(1)` before the first status
  write, so `status.json` went stale 645 397 s ago and even
  `sy aiplane status` shows workloads as `loaded=true` from a dead process.
* `RestartSec=5s` + `StartLimitIntervalSec=60s` + `StartLimitBurst=5` burns
  the burst in 25 s; systemd then refuses further starts indefinitely.
* `EmbedWorkload::load` bails on the missing `bf16.onnx` **before** the
  `try_cpu` fallback three lines later, so the CPU path is unreachable.
* `sy doctor` has no artifact check; missing IPC sockets are `Skip`, not
  `Fail` (`src/doctor/checks.rs:313`); and the generated fix hint points at
  `sy-aiplane.service` / `sy-agt.service`, neither of which exists.

## Root Cause

Four independent amplifiers, each defensible alone:

1. **Cache is load-bearing and `sy` itself deletes it.** The 08:19 wipe was
   not a hand-run `rm`: `sy disk`'s `user-cache` strategy ran
   `find ~/.cache -type f -mtime +30 -delete`, and model blobs written once
   by `prep_npu_workload.py` are never re-touched, so at 30 days old their
   mtime makes multi-GB ONNX weights look like prime stale cache — the very
   thing `ReclaimableRanker` advertises first when the root fs is tight (it
   is at 92 % here). Nothing pre-flighted or rebuilt them, and `sy apply`
   does not own them.
2. **Prep/daemon cache-key drift.** `prep_npu_workload.py` wrote the VAIP
   partition under `compiled_<stem>_bf16_seq512_b1`, while
   `embed.rs:257` asks ORT for `compiled_<stem>_bf16_seq512_o1` (the `_o1`
   tail versions ORT's pre-pass optimisation level). Prep-time compile was
   therefore orphaned and the daemon recompiled cold at every wiped cache.
3. **Fail-fast with no operator surface.** The deliberate "refuse to start
   rather than degrade silently" decision has no *loud* half: the only
   signal is journald, and the one UI that could have screamed is
   designed to hide on exactly that condition.
4. **Restart budget sized for transient failures** applied to a permanent
   config error, converting a crash loop into a permanently dead plane.

## Fix

1. `sy knowledge waybar`: daemon-down now emits `class:"down"`,
   `text:"🧠 !"` and a tooltip naming the age + `sy doctor`; `class:"hidden"`
   is reserved for "no status file ever written" (plane not installed).
   CSS gained `#custom-sy-knowledge.down` in the warning colour.
2. New `aiplane::degraded::DegradedWorkers` gate. `init_aiplane_supervisor`
   returns the worker kinds it could not bring up instead of failing; the
   daemon serves IPC/qdrant, records the reason in `status.last_error`, and a
   recovery thread re-`ensure()`s the missing kinds every 60 s so a rebuilt
   model heals the plane on its own. `SY_KNOWLEDGE_REQUIRE_WORKLOADS=1`
   restores fail-fast for the NPU test gate.
3. `EmbedWorkload` picks its model file before deciding the backend: bf16 →
   VitisAI-with-CPU-fallback, bf16-missing-but-fp32-present → CPU, neither →
   the original actionable bail. `required_paths()` is now shared with doctor.
4. `sy-knowledge.service`: `RestartSec=30s`, `StartLimitIntervalSec=900s`,
   `StartLimitBurst=10` — slow self-heal beats a latched `failed`.
5. `sy doctor`: new `aiplane.model_artifacts` check (Fail + exact prep
   command, detects dangling symlinks); missing-socket checks report `Warn`
   when the owning unit is `enabled` but unreachable; `IpcEndpoint::unit()`
   replaced the `sy-{endpoint}.service` string interpolation (aiplane rides
   on `sy-knowledge.service`, agt is `sy-agentd.service`).
6. `prep_npu_workload.py`: `cache_key_for()` mirrors the Rust keys
   (`_o1` for embed) and `--cache-key` overrides, so a prep run warms the
   partition the daemon will actually look up.
7. `sy disk`'s `user-cache` strategy now spares the `PROTECTED` subtree
   (`~/.cache/sy`) in *both* the probe and the delete through one shared
   `find_args()`, so a cleanup can never amputate the plane again and the
   fuzzel menu can no longer promise 5.8 GB of provisioning as "reclaimable".
   Generic caches (`~/.cache/mozilla`, …) are still swept exactly as before.

## Rebuild outcome (2026-09-27 02:06)

| Artifact | Result |
| --- | --- |
| `embed` (multilingual-e5-base) | rebuilt in 86 s, `.rai` written under `compiled_multilingual-e5-base_bf16_seq512_o1` — the key the daemon requests, so the worker reached `Ready` 3 s after `systemctl --user restart` |
| `rerank` (bge-reranker-v2-m3) | prep's warm step aborts (`SIGABRT`, `onnx.ModelProto exceeded maximum protobuf size of 2GB: 2274207492`) because the un-shrunk BF16 graph must be serialized whole; with the shrink default now on, the **daemon** compiled a 339 MB partition and one `TextPair` dispatch measured 0.34 s (CPU fallback is ~11 s/pair, so the partition is real) |
| `stt` (whisper-medium) | blobs were pruned by the same sweep and are not pre-flighted (the daemon raises STT lazily); re-run `prep_npu_workload.py --workload stt` before enabling transcription on a manifest |

Post-fix host state: `sy-knowledge.service` `active (running)`,
`embed=vitisai` + `rerank=vitisai` on the NPU, `sy doctor --json` =
`{pass: 19, warn: 1, fail: 0}` with `aiplane.model_artifacts: 2/2 present`,
and the bar tile back as `🧠 ⟳ 113k` mid-pass. 3.2 GiB of orphan
per-tensor exports and the redundant `~/.cache/sy/npu-embed` farm were
deleted; artifacts now live only under `~/.cache/sy/aiplane/<stem>/`.

## Follow-ups (not in this fix)

- ~~`#custom-sy-knowledge.down` lands at next login.~~ Resolved on
  2026-09-27 02:37: `sy apply` renders `configs/waybar/*` **and** calls
  `waybar::reload()`, which `pkill -TERM`s the bar and respawns it via
  `setsid waybar` with the env snapshotted from the dying process (`NIRI_SOCKET`
  included — a whitelisted env drop is what previously blanked the workspace
  tiles). The rule is live; the `style.css` drift had simply never been
  deployed. Operators deploying CSS by hand instead of `sy apply` still wait
  for a bar restart, because waybar 0.14's `SIGUSR2` reload does not re-apply
  module membership.
- `aiplane.model_artifacts` covers the start-up workloads
  (`embed`, `rerank`). STT/VAD/OCR are raised on demand; their absence is
  reported by the worker that needs them, not by doctor.
- ~~The `rerank` worker SIGSEGVs once per daemon start.~~ **Misdiagnosed
  here, fixed in BUG-20260927-0400.md**: the `sy` coredumps are not cold-compile
  crashes at all. The timestamps sit in the *stop* window of each restart and
  the trace ends in `_dl_call_fini`, i.e. AMD's VitisAI EP finalizer faults
  while the process leaves `main`. Both workers, every orderly shutdown,
  ~330 MB of cores per restart — the `python` `SIGABRT`s in the same window are
  the separate, genuinely prep-side event.
- Root fs is at 92 % (168 G free), which is the precondition that made the
  sweep attractive in the first place. Clearing the retained coredumps needs
  operator approval; `whisper-medium`'s blobs were pruned by the same wipe
  and are unrebuildable without `prep_npu_workload.py --workload stt`.
- The rerank rebuild still cannot complete inside
  `prep_npu_workload.py --skip-warm`-less runs: VAIP serializes the whole
  graph at the 2 GiB protobuf cap. `rerank.rs`'s `BATCH_SIZE` note covers
  the same cap from the batch>1 side; the prep-side warm step needs either
  a shrink-before-serialize or an accepted `--skip-warm` + daemon-side
  compile (which is what happened here).
