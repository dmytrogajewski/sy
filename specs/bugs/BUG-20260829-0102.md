# BUG-20260829-0102: Disconnected SGLang stream becomes scheduler zombie

## Summary

A client disconnect from a streamed SGLang generation removes tokenizer state
but does not abort the scheduler-owned request. With a one-request profile, the
orphan keeps decoding and blocks the next agent request.

## Reproduction

- Engine: the signed, digest-pinned SGLang Qwen3.8 qualification image on the
  real `dgx-spark` appliance.
- Send a long streamed Responses request through the authenticated sy gateway.
- Disconnect the client after streamed bytes arrive.
- Immediately send a bounded Chat request.
- Evidence: the follow-up waits for the five-second upstream deadline and
  returns 503, while SGLang repeatedly logs `state was deleted in
  TokenizerManager` for one still-running request.

## Expected

Disconnecting a streamed client aborts scheduler work promptly, frees the
single running-request slot, emits no deleted-state log flood, and permits the
next request to complete normally.

## Actual

Tokenizer cleanup removes the request identity before the delayed disconnect
abort runs. The abort path suppresses scheduler delivery when local state is
missing, so decoding continues until the request reaches its output limit.

## Root Cause

Pinned SGLang commit `d91c3682b0b429e4c70df63cd57f819588ce29b0`
contains the lifecycle regression reported upstream as
`sgl-project/sglang#36333`. Cancellation is handled by the broad
`BaseException` cleanup, which discards dispatched request state; two seconds
later, `create_abort_task` calls an abort method whose missing-state guard
returns without notifying the scheduler.

## Fix

Apply the reviewed upstream lifecycle approach from
`sgl-project/sglang#36418` as a content-addressed image patch: record request
IDs only after scheduler dispatch, retain their state on cancellation, and
force the delayed disconnect abort to reach the scheduler. Normal completed
streams must not record forced-abort identities.

## Traceability

- Contract test: `tests/spark_engine_image_contract.rs`.
- Real-device acceptance: disconnect a long stream, observe scheduler release,
  then complete a bounded generation without restarting the container.
- Image definition: `configs/sy/spark/engines/sglang-qwen38-mmap.Dockerfile`.

## Verification

Generation 9 on `dgx-spark` ran the content-addressed patched image. A
Responses stream delivered 2,750 bytes before the client deliberately closed
at 801 milliseconds. After the upstream two-second abort window, a separate
reasoning-enabled Chat request completed with HTTP 200 in 1.08 seconds. Engine
logs contained no deleted-tokenizer-state flood, the container had zero
restarts and was not OOM-killed, and the instance remained healthy.

A separate Responses stream completed normally in 1.36 seconds with its full
terminal event sequence. It produced no abort/error log, proving normal
completion does not enter the forced-disconnect path.
