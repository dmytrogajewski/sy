# BUG-20260829-2341: Long-context prefill exceeds the fixed stream-idle timeout

## Summary

A healthy vLLM 262K request is reported as `response.failed` when its prefill
produces no upstream SSE event within the gateway's fixed 120-second idle
deadline.

## Reproduction

- Method: manual on `dgx-spark`, followed by a focused regression test
- Command: `python3 scripts/benchmark-spark-engine.py --fixture specs/runs/qwen38-vllm-262k-plan.json ...`
- Evidence: the public Responses stream ended with `response.failed` while the
  engine logged HTTP 200, remained healthy, and showed no PSI pressure. The
  request began at `20:37:20`; the first long-prefill kernel ran at `20:37:21`,
  and no upstream event arrived before the 120-second connector deadline.

## Expected

An engine profile sized for 262K context can declare a bounded stream-idle
deadline long enough for its worst-case prefill, and the public stream remains
open until the first upstream event arrives.

## Actual

All translated OpenAI and Anthropic streams use one compiled 120-second idle
deadline, regardless of the selected engine profile or context window.

## Root Cause

`CompletionStream::next` always applies `STREAM_IDLE_TIMEOUT`. The engine
profile reaches the gateway with context and sampling policy, but has no
declarative translated-stream idle policy, so long prefills cannot override the
global safety default.

## Fix

Add a bounded `stream_idle_timeout_seconds` engine-profile setting, propagate it
through `GatewayProfile`, and use it for translated chat, Responses, and
Anthropic completion streams. Keep the existing bounded default for profiles
that omit the setting.
