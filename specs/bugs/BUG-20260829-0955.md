# BUG-20260829-0955: Runtime hardening removes required CUDA JIT toolchain

## Summary

The clean SM121 candidate imports SGLang successfully but cannot compile its
first Triton kernel because the final image removes every compiler.

## Reproduction

- Method: source-backed GB10 probe in the final image under UID 65534, offline,
  read-only root, and declared tmpfs caches.
- Fixture: `tests/fixtures/spark-engine/sm121_runtime_jit.py`.
- Evidence: Triton raises `RuntimeError: Failed to find C compiler` before
  compiling its CUDA driver helper.

## Expected

The immutable runtime retains the minimal toolchain required for SGLang,
Triton, TorchInductor, and TileLang JIT while mutable installers and network
fetch tools remain unavailable.

## Actual

The image labels all build tools absent and removes C, C++, CUDA, CMake,
Ninja, and Make executables along with package managers.

## Root Cause

Image hardening treated runtime JIT compilers as development-only tooling even
though Triton compiles a driver helper on first use and TileLang compiles CUDA
kernels at runtime.

## Fix

Declare and retain a JIT-only toolchain in OCI metadata; independently declare
and reject package managers, network fetchers, SCM clients, and mutable source
metadata. Generic Rust contracts derive the classification and both tool sets
from the labels rather than repeating operational values. Prove the toolchain
by executing all three JIT paths on GB10.

## Traceability

- Failing test: `tests/spark_engine_image_contract.rs::contracted_runtimes_attest_their_jit_tool_policy`.
- Real-device fixture: `tests/fixtures/spark-engine/sm121_runtime_jit.py`.
- Fixed in: `configs/sy/spark/engines/sglang-qwen38-mmap.Dockerfile`.
