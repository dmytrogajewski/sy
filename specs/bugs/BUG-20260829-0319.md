# BUG-20260829-0319: Late QSA prefill JIT terminates the Spark engine

## Symptom

The managed SGLang generation became healthy and passed its semantic and
startup protocol probes. After several successful authenticated OpenAI and
Anthropic requests, a new tool-request prompt returned HTTP 503. The container
then restarted its otherwise healthy engine process.

## Reproduction

1. Serve the NVFP4 checkpoint through the ordinary signed Spark lifecycle.
2. Exercise sequential chat, Responses, Anthropic, and tool requests whose
   input lengths cross several prefill-shape buckets.
3. Observe the scheduler fail in `_sparse_gqa_chunk_prefill` while Triton calls
   `driver.active.utils.load_binary` for a previously unseen specialization.
4. The CUDA driver returns `operation not permitted`; SGLang terminates the
   scheduler, the gateway returns 503, and Docker restarts the container.

## Root cause

QSA prefill is intentionally eager while decode uses CUDA graphs. The Triton
prefill kernel still has multiple launch configurations selected from request
shape. Normal startup and sy's bounded protocol probes exercised only some of
those configurations. A later prompt therefore attempted its first device
module load after serving had begun. This is unsafe on the GB10/SM121 driver
path: a late `cuModuleLoad` can collide with graph-managed execution and return
`CUDA_ERROR_NOT_PERMITTED` even though compilation and the cache directory are
otherwise valid.

The pinned SGLang revision already includes its engine-neutral
`prefill_shapes` startup warmup. It sends power-of-two and intermediate input
sizes through 32K before the server declares readiness, which compiles the
prefill, attention, and fused-MoE specialization families at the correct
lifecycle boundary. The Spark profile had not enabled it.

## Fix

Declare `--warmups prefill_shapes` in the SGLang engine TOML. This is runtime
policy, so it remains in signed configuration rather than Rust. No model or
engine dispatch is introduced.

## Acceptance

- Startup logs complete every declared prefill warmup before the instance
  becomes healthy.
- Replaying the authenticated request sequence that crossed the failing shape
  bucket no longer performs a late compile/load and does not return 503.
- OpenAI Responses and Anthropic tool-result continuation both complete.
- The managed generation remains healthy with no additional container restart.
- `make lint` and `make test` pass.
