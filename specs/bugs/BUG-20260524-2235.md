# BUG-20260524-2235: every interactive shell prints a 4-line XRT setup banner

## Summary
`/etc/profile.d/ryzenai.sh` (shipped by `ryzenai-1.7.1-1.fc43`) sources `/opt/xilinx/xrt/setup.sh` without a `>/dev/null` redirect, so every interactive shell prints a four-line banner (`Autocomplete enabled… / XILINX_XRT / PATH / LD_LIBRARY_PATH / PYTHONPATH`). The host previously had a silent, idempotent version of the same script (preserved as `/etc/profile.d/ryzenai.sh.rpmsave`); the ryzenai rpm upgrade clobbered it. Per CLAUDE.md "no snowflakes" the silent shape has to live in this repo so it can be restored idempotently after any ryzenai rpm refresh.

## Reproduction
- Method: manual + asset-content test
- Test: `tests/profile_d_ryzenai_is_silent.rs::ryzenai_profile_d_sources_xrt_silently_and_dedupes_path`
- Commands (live host):
  - `bash -ic 'true'` → prints the banner verbatim.
  - `bash -c 'true'` → silent (the loop in `/etc/profile` redirects to `/dev/null` for non-interactive shells; for interactive ones it does not).
  - `cat /etc/profile.d/ryzenai.sh` → 8-line noisy script: `. /opt/xilinx/xrt/setup.sh` (no redirect, no guard).
  - `cat /etc/profile.d/ryzenai.sh.rpmsave` → original silent shape: `[ -z "$XILINX_XRT" ] && … . /opt/xilinx/xrt/setup.sh >/dev/null`, with `case ":$PATH:"` dedupe.
  - `rpm -qf /etc/profile.d/ryzenai.sh` → `ryzenai-1.7.1-1.fc43.x86_64`.
- Side-symptom captured during the repro: `$PATH` already contains `/opt/xilinx/xrt/bin` three times, `$LD_LIBRARY_PATH` contains `/opt/xilinx/xrt/lib` three times, `$PYTHONPATH` three times — every interactive shell re-prepends because the new ryzenai.sh dropped the `case`-based dedupe the `.rpmsave` had.

## Expected
1. An interactive shell prints **nothing** from `/etc/profile.d/ryzenai.sh`.
2. `XILINX_XRT`, `LD_LIBRARY_PATH`, `PYTHONPATH`, and `PATH` end up with the XRT directories present **exactly once**, no matter how many login + interactive shells nest.
3. The silent shape lives in the repo (`configs/profile.d/ryzenai.sh`) and is installed by `scripts/install-system-npu.sh` (which already owns the other NPU/XRT system files: dracut conf, sy-amdxdna-load, sy-npu-perf). Re-running the installer after a ryzenai rpm upgrade restores the silent shape.

## Actual
1. Banner fires on every interactive shell (the `for i in /etc/profile.d/*.sh; do … . "$i"; done` loop in `/etc/profile` only redirects to `/dev/null` for non-interactive shells, gated by the `${-#*i}` test).
2. XRT dirs accumulate in `$PATH` / `$LD_LIBRARY_PATH` / `$PYTHONPATH` once per nested shell.
3. Nothing in `sy`/`configs/` owns the silent shape — the rpm upgrade silently regressed it and only the `.rpmsave` proves the user ever had it.

## Root Cause
- **Upstream:** `ryzenai-1.7.1-1.fc43`'s `/etc/profile.d/ryzenai.sh` is sloppy — sources `xrt/setup.sh` unguarded and unredirected.
- **Loader:** Fedora's `/etc/profile` runs `for i in /etc/profile.d/*.sh; do if [ "${-#*i}" != "$-" ]; then . "$i"; else . "$i" >/dev/null; fi; done` — interactive shells get the raw output, non-interactive ones don't. So the banner is interactive-shell-only by design of the loader.
- **Distal (sy):** sy's NPU plane depends on the XRT env vars but did not own the profile.d snippet that establishes them. When the ryzenai rpm shipped a new (noisy, non-idempotent) version, there was no repo-owned canonical replacement and `sy apply` had nothing to restore.

## Fix
1. **New repo file `configs/profile.d/ryzenai.sh`** with the silent + idempotent shape recovered from `.rpmsave`:
   - `export RYZEN_AI_INSTALLATION_PATH=/opt/AMD/ryzenai`
   - `[ -z "$XILINX_XRT" ] && [ -f /opt/xilinx/xrt/setup.sh ] && . /opt/xilinx/xrt/setup.sh >/dev/null`
   - `case ":$PATH:" in *":$venv:"*) ;; *) PATH="$venv:$PATH" ;; esac` for the venv prepend.
2. **Extend `scripts/install-system-npu.sh`** to `install_if_changed` the new file to `/etc/profile.d/ryzenai.sh` alongside the existing dracut / sy-amdxdna-load / sy-npu-perf entries.
3. **Asset-content test** `tests/profile_d_ryzenai_is_silent.rs` asserts the repo file: (a) sources `xrt/setup.sh` with `>/dev/null`, (b) guards on `XILINX_XRT` being empty, (c) prepends `$venv/bin` to `$PATH` via `case` dedupe, (d) does not contain the offending unguarded `. /opt/xilinx/xrt/setup.sh` line.
4. **One-shot recovery on this host:** run the extended installer; verify with `bash -ic 'true'` (no banner) and `bash -ic 'echo $PATH'` (each XRT dir present exactly once).

## Traceability
- Failing test: `tests/profile_d_ryzenai_is_silent.rs`
- Fixed in: `configs/profile.d/ryzenai.sh` (new), `scripts/install-system-npu.sh` (one new dst + install_if_changed call).
