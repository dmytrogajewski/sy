# BUG-20261017-2345: AI IPC tests depend on installed RPMs

## Summary

The combined knowledge and aiplane IPC tests fail after the standalone aiplane RPM is installed on the test host.

## Reproduction

- Run `make test` on Fedora 44 with `/usr/libexec/sy/sy-system-aiplane` installed.
- `aiplane_ipc_v1_run` returns `BadRequest: method belongs to another plane`; other IPC tests fail in the same way, followed by poisoned test locks.

## Expected

Hermetic IPC tests exercise their selected combined wire mode on both clean CI runners and installed sy hosts.

## Actual

`serve_with_dispatch` derived its mode from the presence of a system RPM, even when a fake dispatcher and a temporary socket were supplied.

## Root Cause

The bridge constructor read the host's package installation state instead of receiving the mode selected by its caller.

## Fix

Pass the aiplane method availability into the bridge. Production determines it from the installed package; tests explicitly select the combined mode.

## Traceability

- Failing run: `/tmp/sy-f44-r16-test.log` on the upgraded host.
- Fixed in: `crates/sy-aiplane/src/aiplane/ipc.rs`.
- Verification: `cargo test -p sy-aiplane --lib`, then `make test` and `make lint`.
