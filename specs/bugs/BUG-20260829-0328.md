# BUG-20260829-0328: Stop leaves the startup admission lease held

## Summary

Stopping a managed generation while its serve task waits for health removes
the container but leaves the high-memory transition lease held until the full
startup deadline.

## Reproduction

- Method: real-device reproduction plus focused regression test.
- Test: `src/spark/agent.rs::tests::stopped_intent_interrupts_engine_readiness_wait`.
- Command: stop a generation in `creating`, then immediately dry-run the same
  serve request.
- Evidence: the instance reaches stopped/absent, but admission returns
  `another high-memory transition owns the admission lease` because the old
  serve task is still polling health for an absent container.

## Expected

Durable stopped intent interrupts readiness polling promptly, lets the serve
task drop its transition lease, and permits the next high-memory transition.

## Actual

Readiness polling only observes HTTP health and its deadline. It cannot observe
operation cancellation or stopped instance intent, so a removed startup
generation retains the in-memory lease for up to 1,800 seconds.

## Root Cause

`run_serve` moves its `TransitionLease` into the background task, while
`wait_until_engine_ready` has no cancellation input. Explicit stop updates the
instance and removes the container independently, but cannot wake the health
loop.

## Fix

Make readiness waiting observe a generic durable interruption guard containing
the operation and instance identities. A cancelled serve or stopped instance
ends the health loop; explicit stop remains responsible for its own container
removal, while operation cancellation retains the existing cleanup path.

## Traceability

- Failing test: `src/spark/agent.rs::tests::stopped_intent_interrupts_engine_readiness_wait`.
- Fixed in: `src/spark/agent.rs`.
