# BUG-20261101-0511: Maximized windows extend behind the right panel

## Summary

The right stack panel reserves space for ordinary tiled windows but does not
reserve space for windows maximized to edges.

## Reproduction

- Method: live desktop inspection and the user's screenshot.
- Environment: Niri 26.04, eDP-1, 3840 × 2400 physical pixels at scale 2;
  logical size 1920 × 1200.
- Commands: `niri msg --json outputs`, `niri msg --json windows`,
  `niri msg windows`, and `niri msg layers`.
- Evidence: Firefox window 19 (`org.mozilla.firefox`) has tile and window
  size 1920 × 1176 with offset 0 × 0. Ordinary full-width terminal tiles
  measure 1892 × 1176, with windows 1890 × 1174 and offset 1 × 1.
- The 1176-pixel height leaves Waybar's 24-pixel top reservation intact;
  the browser consumes the right panel's 28-pixel strip.
- Both `sy-stack` and Waybar namespace `top` are on the Top layer.

## Expected

Ordinary and maximized windows leave the visible right panel unobstructed.
Waybar continues to span the full top edge. Fullscreen behavior remains a
separate compositor state.

## Actual

The browser extends underneath the panel, hiding its rightmost controls and
content. Ordinary tiled terminals leave the panel's strip clear.

## Root Cause

Before the fix, `configs/niri/config.kdl` reserved `right 28` through layout
struts, while `crates/sy-desktop-shell/src/stack/bar/app.rs` set `exclusive_zone: 0`
both at startup and when showing the panel again.

Niri's maximize-to-edges mode deliberately ignores layout struts, gaps and
borders, while respecting layer-shell exclusive zones. Firefox's measured
geometry matches that mode; the inspected IPC window record does not expose
an explicit maximized-state flag. This explains the difference from the
ordinary full-width terminal columns.

Upstream references:

- [Niri fullscreen and maximize](https://niri-wm.github.io/niri/Fullscreen-and-Maximize.html)
- [Niri 26.04 layout source](https://github.com/niri-wm/niri/blob/v26.04/src/layout/scrolling.rs)

The zero exclusive zone was deliberate in
[BUG-20261017-2340](BUG-20261017-2340.md): a positive right reservation
previously shortened Waybar. Replacing that reservation with a strut fixed
the top-bar geometry but left maximized windows unprotected.

## Fix

The panel now reserves its 28 logical pixels with a layer-shell exclusive zone
at startup and when shown. Hiding it releases the zone. The Niri right strut
is zero, avoiding double reservation. Hover previews ignore exclusive zones
because their existing margins already include the panel and Waybar offsets.

The stack service waits for Waybar's actual `top` layer surface via Niri IPC
and jq, replacing the process check and arbitrary delay. Every Waybar service
start asynchronously remaps an active stack panel, including crash recovery.
This ensures Waybar registers its full-width top reservation first. The
asynchronous request avoids waiting on a panel ordered after Waybar.
The apply path delegates panel remapping to that service hook instead of
restarting it twice. The desktop RPM declares the jq dependency.

## Traceability

- Manual evidence: supplied screenshot and live Niri IPC geometry above.
- Failing unit test: `visible_panel_reserves_its_width_for_maximized_windows`
  reported actual zone 0, expected 28 before the fix.
- Regression coverage: `crates/sy-desktop-shell/src/stack/bar/app.rs` unit tests
  and `tests/stack_panel_layout.rs` cover reservations and service ordering.
- End-to-end recipe: build `sy-desktop-shell`, then run
  `python3 scripts/check-stack-panel-layout.py` from the repository root.
  It uses real Niri, Waybar, Foot and panel processes in Xvfb and disposable
  user services; the live desktop is untouched. It checks tiled-column and
  maximize-to-edges geometry, hide/show, fullscreen, full-width Waybar and
  panel remapping after two Waybar restarts. `--scale 1` checks unscaled output;
  the default is scale 2, matching the reported host.
- Negative end-to-end control: running the recipe with
  `--binary /usr/libexec/sy/sy-desktop-shell` against the installed older binary
  failed the expected maximized-width check.
- Fixed files: `configs/niri/config.kdl`, both panel user units,
  `crates/sy-desktop-shell/src/{stack/bar/app.rs,waybar.rs}`, and
  `packaging/sy.spec`. Usage and verification are documented in the shell README.
- Gates: `make lint`, `make test`, `make lint-spark`, and `make test-spark`
  passed after the implementation changes. The end-to-end recipe passed at
  scale 2 (612/640 logical pixels) and scale 1 (1252/1280), including repeated
  Waybar restarts and full-width Waybar in both cases.
- Activation requires installing the updated desktop RPMs and applying the
  managed desktop configuration. Live verification measured Firefox at
  1892 × 1176 logical pixels while Waybar retained its full 1920-pixel width.
