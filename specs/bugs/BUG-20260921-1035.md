# BUG-20260921-1035: Transient executable writer breaks the bridge protocol probe

## Summary

A parallel bridge test intermittently fails with Linux `ETXTBSY` while probing
an otherwise valid signed executable.

## Reproduction

- Original: `make test-spark`, during `canonical_environment_overrides_legacy_environment`.
- Deterministic regression: install a signed fixture, hold a writable descriptor
  without changing its bytes, restore read-only permissions, then release the
  descriptor after 100 ms while invoking `bridge::prepare`.
- Error: `inspect Sparkplane bridge protocol: Text file busy (os error 26)`.

## Expected

Handle the short writer-descriptor lifetime without activating unverified bytes,
retrying protocol failures, or waiting without a deadline.

## Root Cause

Linux refuses exec while a writable descriptor remains open; concurrent process
creation can briefly inherit one. The protocol probe treated this transient
pre-exec condition as a permanent incompatibility.

## Fix

Retry only `ETXTBSY`, at 10 ms intervals for at most one second. Preserve
signature/hash verification and the exact protocol check. Other execution
errors and nonzero/incompatible protocol responses are not retried.

## Traceability

- `tests/sparkplane_bridge.rs::protocol_probe_waits_for_a_transient_executable_writer_to_close`.
- `src/sparkplane_bridge.rs::verify_protocol`.
