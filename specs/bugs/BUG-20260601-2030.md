# BUG-20260601-2030 — `bandit_status_block_schema_matches_spec_v1` fails (baseline_arm "call" ≠ "browse")

## Status
RESOLVED 2026-06-02. Root cause was non-hermetic intent: the CLI
`power status` probe dialled live D-Bus intent (logind/portal/mpris) via
`live_intent`, so a call/screen-cast/media stream on the operator's
desktop set `call_active` → shield DFA `Meeting` → `baseline_arm="call"`.
`SY_SYSFS_ROOT` only isolated sysfs sensors, never intent. Fix: added
`probe_intent` (src/power/cli.rs) — when `SY_SYSFS_ROOT` is set, the
one-shot probe (`status` + `build_live_status_value`) uses an isolated
Intent with no live channels, so `call_active` stays false and the DFA
falls through to `CoolAc`. `bandit_status_block_schema_matches_spec_v1`
now passes 3/3 in isolation and the full `make test` is green (1623/0).
Test comment updated to document the real mechanism.

## Root cause (hypothesis)
The test documents its own fragility (tests/power_bandit_floor.rs ~line 116):
a hot host (CPU > ~75 °C) tips the shield DFA out of `CoolAc`, flipping
`baseline_arm` away from `"browse"`. It mitigates by pointing
`SY_SYSFS_ROOT` at an empty tempdir so sensors return `Err → None →
CoolAc`. Two compounding factors appear to defeat that mitigation now:
1. **Host thermal state** — an hour of continuous `cargo build`/`make
   test` during the march heated the CPU; the binary still reads some
   live thermal signal not covered by `SY_SYSFS_ROOT`.
2. **Uncommitted power WIP** — the entire `src/power/*` tree
   (`bandit/clucb.rs`, `checkpoint.rs`, `sensors/power.rs`, `shield`,
   `forecast`, …) is modified in the working tree; that WIP likely
   changed the sensor/shield path so the empty-sysfs isolation no longer
   forces `CoolAc`, and/or changed the COOL_AC baseline mapping.

## Reproduction
`cargo test --test power_bandit_floor bandit_status_block_schema_matches_spec_v1`
→ FAILED (5/5 while host is warm). Passed earlier in the same session
when the host was cooler.

## Proposed fix (future `/bug` run, power-plane owner)
- Make the test fully hermetic: ensure ALL thermal/sensor reads honor
  `SY_SYSFS_ROOT` (or inject a fixed shield state) so host temperature
  cannot tip the DFA; assert against a pinned COOL_AC fixture.
- Reconcile the COOL_AC `baseline_arm` expectation (`browse`) with the
  current `src/power/*` WIP — either the WIP changed the baseline mapping
  intentionally (update the test) or it's a regression (fix the logic).
- Until then, the uncommitted power WIP should be committed/stashed so
  the workspace has a clean `make test` baseline for the knowledge march.
