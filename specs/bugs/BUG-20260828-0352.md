# BUG-20260828-0352: Qwen Flash coding-agent requests fail on Spark

## Summary

Qwen3.8-Flash-Next cannot complete current coding-agent journeys on DGX Spark. The original profile rejected the agents' initial prompts; after correcting that configuration, real requests exposed a llama.cpp CUDA MMQ failure on Blackwell.

## Reproduction

- Method: manual DGX Spark reproduction plus configuration regression test
- Command: `sy spark dgx-spark launch claude --model qwen3.8:flash-next -- --no-session-persistence -p --dangerously-skip-permissions <tetris-prompt>`
- Evidence: llama.cpp first rejected the request with `request (27796 tokens) exceeds the available context size (16384 tokens)`. After raising context and bounding preserved reasoning, the server aborted real agent requests in `launch_mul_mat_q` at `mmq.cuh:1408` when `cudaFuncSetAttribute` returned `CUDA error: operation not permitted`.

## Expected

The shipped model profile accepts the initial request, preserves reasoning, and completes coding-agent tool calls without restarting the engine.

## Actual

Short health probes pass, but a real coding-agent request crashes the inference process. The supervisor restarts it and transiently reports healthy again, so health alone does not qualify this model/engine combination.

## Root Cause

There were two independent causes:

1. The declarative Qwen3.8-Flash-Next profile set `--ctx-size 16384` and did not select the model's supported reasoning-effort control. The later token-budget message was only advisory and the model continued reasoning after it. These settings had not been qualified against current agent prompts.
2. The pinned llama.cpp CUDA build uses the native SM121 MMQ path. On GB10, that path requests a dynamic shared-memory configuration the CUDA runtime rejects. Disabling CUDA graphs and prompt caching does not change the failing kernel path.

## Fix

Keep all runtime policy in the declarative engine profile: use a 65,536-token context, retain Q8 key/value caches and preserved reasoning, select the model's official `low` reasoning effort, and use its published thinking-mode sampling. Rebuild the same pinned llama.cpp revision with a stable Blackwell CUDA backend, then qualify fresh Claude, Codex, and OpenCode Tetris journeys on the real Spark.

## Traceability

- Profile correction: `configs/sy/spark/engines/llama-cpp.toml`
- Engine build evidence: llama.cpp issues 18331 and 24218 describe the same Blackwell MMQ failure family.
