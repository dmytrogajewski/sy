# BUG-20260828-1733: Early-bound engine health starts semantic probe too soon

## Summary

FreeToken intentionally binds HTTP while weights are loading and reports that
lifecycle in the JSON body of `GET /health`. Spark treated any 2xx response as
ready, sent its semantic probe during `status=loading`, received 503, and tore
down a healthy cold start after six seconds.

## Reproduction

- Method: real `dgx-spark` serve of `qwen3.6:35b-a3b-nvfp4` with FreeToken.
- Evidence: FreeToken logged a live frontend with `maintenance_state=loading`;
  Spark immediately failed `semantic completion contract rejected` instead of
  waiting for the backend-ready acknowledgement.

## Expected

Each engine declaration can define its own readiness contract. Spark waits
until both the HTTP status and the configured response-body predicate match,
then runs semantic and protocol probes.

## Actual

Readiness is hard-wired to HTTP 2xx and cannot express lifecycle-aware engine
health.

## Root Cause

Engine schema v3 carries the health method and path but no declarative body
predicate. The generic readiness loop therefore cannot distinguish liveness
from readiness.

## Fix

Add an optional, validated JSON-pointer equality predicate to engine config,
carry it through the executor observation, and apply it in the generic health
loop. FreeToken declares `/status == "ok"`; other engines retain their existing
2xx-only contract.

## Traceability

- Failing test: `spark::agent::tests::configured_health_body_rejects_loading_and_accepts_ok`
- Fixed in: `src/spark/engine.rs`, `src/spark/executor.rs`, `src/spark/agent.rs`, `configs/sy/spark/engines/freetoken.toml`
