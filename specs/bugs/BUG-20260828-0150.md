# BUG-20260828-0150: Startup protocol probes poison llama.cpp MTP generation

## Summary

The fixed startup protocol-probe sequence can leave a healthy Qwen3.8 MTP
llama.cpp process unable to execute its first reasoning request on DGX Spark.

## Reproduction

- Method: deterministic manual reproduction on `dgx-spark`.
- Command: stop and freshly serve `qwen3.8:27b`, then immediately stream an
  OpenAI Responses request through `/openai/qwen3-8-27b-mtp/v1/responses`.
- Evidence: generation 3 passed startup tasks 0, 5, and 9, then task 20 emitted
  `CUDA error: operation not permitted` at
  `cudaFuncSetAttribute(...cudaFuncAttributeMaxDynamicSharedMemorySize...)` and
  the public stream ended with `response.failed` / `upstream stream failed`.
- Control: after Docker restarted the same container without replaying the
  startup protocol probes, OpenAI Responses streaming, preserved reasoning,
  cancellation, and an immediate follow-up all succeeded.

## Expected

A configured engine startup probe must not make the first user generation less
reliable. Engines whose stateful protocol probes are unsafe can disable those
probes declaratively while retaining the normal readiness and semantic probe.

## Actual

`semantic_probe_result` always runs the streamed text and tool protocol probes
after the configured semantic or vision probe. Engine configuration cannot
disable that stateful sequence.

## Root Cause

The gateway treated every engine startup as stateless and always replayed its
full protocol probe sequence. llama.cpp's MTP CUDA path survives readiness and
semantic generation, but the additional startup requests can leave the next
GB10 kernel attribute setup failing. The probe policy therefore belonged to
the selected engine profile rather than unconditional gateway code.

## Fix

Add a required declarative `startup_protocol_probe` profile field, propagate it
through the generic gateway profile, and skip only the stateful protocol probe
sequence when the selected profile disables it. Qwen3.8 MTP disables the
sequence; readiness and the semantic probe still run. Other profiles retain
the complete sequence.

## Traceability

- Failing tests: `qwen_mtp_profile_disables_stateful_startup_protocol_probe`
  and the gateway startup-probe policy regression.
- Live fix evidence: fresh generation 4 returned HTTP 200 with the exact text
  `fresh probe passed`, completed 48 SSE events, and kept restart count zero.
- Fixed in: signed Spark release
  `0.1.0-0bd8ec827ec88134bbbf23d3d9f023d1d2c23924706b6bf3fdf744253b364031`.
