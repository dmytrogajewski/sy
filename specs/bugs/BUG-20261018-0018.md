# BUG-20261018-0018: Scheduler test fails under CPU load

## Summary

The scheduler priority test depended on the test thread waking within a few milliseconds and failed during simultaneous RPM builds.

## Reproduction

- Method: full `make test` under concurrent Fedora 44 and 45 RPM compilation.
- Evidence: `higher_class_never_starves_to_lower` saw Interactive at index 3 instead of below 3; a poisoned shared test lock then caused a second failure.

## Expected

The test verifies strict queue priority regardless of host scheduling delays.

## Actual

Its 8 ms sleep allowed the dispatcher to drain several Background requests before the test thread admitted Interactive.

## Root Cause

The test synchronized independent threads using elapsed wall time.

## Fix

Admit the entire Background backlog and Interactive request before starting the dispatcher, then assert Interactive runs first. The separate hard-escape test covers preemption of an active lower-priority request.

## Traceability

- Fixed in: `crates/sy-aiplane/src/aiplane/scheduler.rs`.
- Verification: the focused test and `make test` pass.
