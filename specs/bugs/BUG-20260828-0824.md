# BUG-20260828-0824: Patched vLLM module is unreadable at runtime

## Summary

The patched-vLLM container starts as the configured non-root UID but exits
before model inspection because its PLE mmap Python module is root-only.

## Reproduction

- Method: manual reproduction on the real `dgx-spark` appliance
- Command: `sy spark dgx-spark serve qwen3.8:flash-next --name qwen38-flash-next-nvfp4 --json`
- Evidence: operation `01M13D2JFFGB3V2QJHWKRY9SB0` created container
  `c742b61b7a34`, which exited 1. Its log reports `PermissionError: [Errno 13]
  Permission denied: '/usr/local/lib/python3.12/dist-packages/vllm_ple_mmap.py'`.
  Direct inspection reports mode `0600 root:root`, and importing the module as
  `nobody` reproduces the same error.

## Expected

Every Python module needed by the engine is readable by the configured runtime
UID 65534, and model architecture inspection proceeds.

## Actual

The remote URL `ADD` creates the patch module as `0600 root:root`; the root-user
image build checks pass, but the non-root production container cannot import it.

## Root Cause

The pinned image Dockerfile verifies the patched source as root without setting
an explicit installed-file mode or testing the configured non-root identity.

## Fix

Set the installed patch module to mode `0644` in the declarative engine image
before patching vLLM. Preserve the non-root runtime UID. A signed-release
contract test requires that permission step, and the rebuilt image is verified
by importing the module as `nobody` before deployment.

## Traceability

- Manual failing journey: operation `01M13D2JFFGB3V2QJHWKRY9SB0`
- Failing test: `spark::engine::tests::patched_vllm_module_is_readable_by_non_root_runtime`
- Fixed in: `configs/sy/spark/engines/vllm-qwen38-mmap.Dockerfile`
