# BUG-20261017-2325: Packaged apply writes through user unit symlinks

## Summary

`sy --root /usr/share/sy apply --yes` fails after the first packaged apply has linked user units into `~/.config/systemd/user`.

## Reproduction

- Method: Fedora 44 host, after installing the release 14 sy RPMs.
- Command: `/usr/bin/sy --root /usr/share/sy apply --yes`
- Evidence: `Error: write /home/dmitriy/.config/systemd/user/sy-agentd.service` followed by `Permission denied (os error 13)`.

## Expected

Repeated applies update desktop configuration and synchronize user units through the unit manager without writing into the RPM tree.

## Actual

The template pass traverses `configs/systemd/user` and calls `fs::write` on a destination symlink pointing into the read-only `/usr/share/sy` package tree.

## Root Cause

`apply()` and `apply_units()` both manage the same user unit paths. The first apply can create unit symlinks; a later template pass follows them.

## Fix

The template pass skips `systemd/user` files and leaves user unit reconciliation to `apply_units()`. The NPU unit ordering and shell escaping fixes were also verified on the upgraded host.

## Traceability

- Manual failure: `/tmp/sy-f44-user-apply.log` on the Fedora 44 host.
- Fixed in: `src/main.rs`, `configs/systemd/system/sy-npu-perf.service`, and `configs/systemd/system/sy-amdxdna-load.service`.
- Verification: rerun packaged apply after rebuilding RPMs; run `systemd-analyze verify` for both NPU units and the Fedora 44 NPU check.
