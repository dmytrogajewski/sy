# BUG-20261019-2248: Documentation site deployment fails with Pages disabled

## Summary

The documentation site builds successfully, but deployment fails because GitHub Pages is disabled for the repository.

## Reproduction

- Method: GitHub Actions logs and repository API.
- Command: `gh run view 39108130154 --log-failed`.
- Evidence: `actions/deploy-pages@v4` returns `Failed to create deployment (status: 404)`.
- Command: `gh api repos/dmytrogajewski/sy/pages` returns HTTP 404; the repository API reports `has_pages: false`.

## Expected

The documentation workflow builds and publishes the site after a push to `main`.

## Actual

The build succeeds; the deployment job cannot create a Pages deployment.

## Root Cause

The repository has no Pages site. The existing workflow has the required deployment permissions, but its workflow token cannot enable Pages. The one-time repository setup documented in `CONTRIBUTING.md` was missing.

## Fix

Enable Pages with GitHub Actions as its build source using a repository administrator token:

```sh
gh api --method POST repos/dmytrogajewski/sy/pages -f build_type=workflow
```

The desired repository setting is **Pages → Source → GitHub Actions**. Verify it with `gh api repos/dmytrogajewski/sy/pages --jq .build_type`, which must return `workflow`. Deployment remains managed by `.github/workflows/docs-site.yml`.

## Traceability

- Failing run: <https://github.com/dmytrogajewski/sy/actions/runs/39108130154>.
- Workflow: `.github/workflows/docs-site.yml`.
- Setup contract: `CONTRIBUTING.md`, documentation expectations.
- Validation: Pages now reports `build_type: workflow`; both build and deployment passed in [run 39314417803](https://github.com/dmytrogajewski/sy/actions/runs/39314417803).
