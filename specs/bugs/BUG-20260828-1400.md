# BUG-20260828-1400: Launch reuses an unpublished Spark route

## Summary

After a signed engine-policy update restarts the Spark agent, an instance whose
persisted engine fingerprint no longer exists in the active catalog remains
reported as healthy even though its in-memory inference route cannot be
reconstructed.

## Reproduction

- Method: manual reproduction on the real `dgx-spark` appliance plus an API
  regression test
- Command: `sy spark dgx-spark launch claude --model qwen3.8:flash-next -- --effort low --print ...`
- Evidence: Claude exited in 0.83 seconds with HTTP 404 and reported that
  `claude-sonnet-4-5` did not exist. The vLLM access log recorded no request.
  The instance API still returned `observed=healthy`, `healthy=true`, and the
  old engine fingerprint `sha256:1a282c...`; the signed catalog fingerprint was
  `sha256:0da8ba...`, and the Anthropic route registry had no exact generation.

## Expected

An instance is advertised as healthy only while its exact generation has a
published gateway route. A client must never reuse durable database health
after the volatile route has failed reconstruction.

## Actual

`GET /api/sy.spark/v1/instances` returns the durable instance document without
checking the route registry, so `sy spark launch` reuses an endpoint that the
agent answers with 404.

## Root Cause

Engine identity is fail-closed: reconciliation rejects a generation pinned to
an engine-policy fingerprint absent from the newly activated signed catalog.
That correctly prevents an unverified container from being routed, but the
instance-list API treats the database's last healthy observation as current
gateway health. The durable and volatile health states can therefore diverge
after an agent restart or catalog change.

## Fix

Project route-registry state onto instance-list responses. A durable healthy
generation without its exact published route is reported as degraded,
unhealthy, and without an endpoint, so launch clients cannot reuse it. Apply
engine-policy changes by draining and re-serving affected generations; the
real Qwen generation was replaced under the new signed fingerprint before
agent benchmarks resumed.

## Traceability

- Failing test: `spark::agent::tests::instance_list_never_advertises_an_unpublished_route_as_healthy`
- Fixed in: `src/spark/agent.rs`
