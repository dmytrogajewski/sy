# BUG-20260829-0253: Null streaming usage rejected

## Summary

After semantic readiness passed on the real SGLang candidate, the generic
startup protocol probe rejected a successful streamed tool response and
terminated the engine with `engine stream usage is invalid`.

## Reproduction

- Start the declarative SGLang engine for the installed immutable NVFP4 model
  on `dgx-spark`.
- Observe successful HTTP 200 semantic, chat, and streamed tool requests.
- Observe the protocol decoder reject an intermediate tool-call chunk carrying
  `"usage": null` before the final populated usage chunk.

## Expected

Streaming decoders ignore a null usage placeholder and validate the final
non-null usage object. This is the normal OpenAI-compatible stream shape when
usage is requested.

## Actual

The decoder treats the presence of the `usage` key as a populated usage object,
then rejects null because it has no token counters.

## Root Cause

`decode_sse_events` distinguishes only absent and present usage fields. It does
not distinguish a present null placeholder from a populated object.

## Fix

Ignore null usage placeholders while retaining strict validation for every
non-null usage value.

## Traceability

- Failing test: `spark::upstream::tests::null_stream_usage_is_a_placeholder`
- Real device: managed generation 5 protocol publication gate on `dgx-spark`
