# BUG-20260921-1118: Qualification rejects native vLLM reasoning field

## Summary

The v0.1.2 live migration stops safely during baseline qualification because its
reasoning probe recognizes only `reasoning_content`, while this vLLM version
returns the separate text in `reasoning`.

## Reproduction

The full 262144-token probe passed. The next request reports `finish_reason:
stop`, 21 reasoning tokens, a nonempty 78-character `reasoning` string and answer
`\n\n4`. Qualification rejects it as missing reasoning. The journal remained at
`drain`; no engine or service was stopped. Supported `--recover` succeeded and
reopened traffic without a model reload.

## Expected and root cause

Accept either of the native vLLM reasoning field names, still requiring nonempty
separate reasoning and the correct answer. The existing upstream streaming
decoder already supports both; the new migration probe omitted that contract.

## Fix and traceability

Mirror the decoder's two-field handling in `migration::qualification`. Extend the
pinned HTTPS regression to exercise both fields before tool and stream checks.
Retain the release and signature gates; publish a new immutable patch release.
