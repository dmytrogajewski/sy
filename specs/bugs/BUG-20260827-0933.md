# BUG-20260827-0933: Blackwell llama.cpp generation becomes unavailable

## Summary

An Ornith llama.cpp generation on DGX Spark crashes during a cached long-context
turn and its replacement inherits an unrelated image healthcheck for the wrong
port.

## Reproduction

- Method: manual and configuration tests.
- Tests:
  `spark::engine::tests::llama_blackwell_disables_cuda_graph_capture` and
  `spark::executor::tests::executor_disables_image_owned_healthcheck`.
- Command: `sy spark dgx-spark launch claude --model ornith-1-5-35b` followed
  by a second large-context turn.
- Evidence: the client received `503 healthy generation became unavailable`.
  Engine logs recorded `cudaFuncSetAttribute(...MaxDynamicSharedMemorySize...)`
  failing with CUDA `operation not permitted`; Docker then reported its
  inherited `http://localhost:8080/health` probe failing while the configured
  engine listened on port 8000.

## Expected

The configured llama.cpp generation remains available across cached multi-turn
requests, and container metadata does not contradict sy's configured readiness
contract.

## Actual

CUDA graph capture aborts the engine process. Docker restarts it, producing a
temporary upstream gap, and the image-owned wrong-port healthcheck permanently
labels the replacement container unhealthy.

## Root Cause

The Blackwell llama.cpp engine configuration left CUDA graphs enabled even
though this backend can attempt a forbidden kernel-attribute mutation while a
stream is captured. The executor also inherited the image's fixed healthcheck
instead of keeping sy's engine-configured health and semantic probes as the
single readiness authority.

## Fix

The external llama.cpp engine configuration disables CUDA graphs through
`GGML_CUDA_DISABLE_GRAPHS=1`. The generic executor explicitly disables an
image-owned Docker healthcheck; sy continues to use the configured engine port,
path, protocol probe, and route publication checks.

Real-device verification on `dgx-spark` completed fourteen cached Claude turns
with 96,158 input tokens without the CUDA failure or a container restart. After
the embedding-engine verification, Ornith 35B was restored as healthy generation
5 in 4.962 seconds.

## Traceability

- Failing tests: `src/spark/engine.rs::tests::llama_blackwell_disables_cuda_graph_capture`
  and `src/spark/executor.rs::tests::executor_disables_image_owned_healthcheck`.
- Fixed in: `configs/sy/spark/engines/llama-cpp.toml` and
  `src/spark/executor.rs`.
