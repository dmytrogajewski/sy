# BUG-20260921-0903: plugin runtime-directory test leaks process environment

## Summary

A plugin sandbox precedence test mutates process-wide runtime-directory variables
while parallel plugin preview tests are launching subprocesses.

## Reproduction

- Method: test, first observed during `make test` for Sparkplane bridge acceptance.
- Test: `tests/sy_file_plugin_preview.rs::pdf_dispatched_to_pdf_plugin_fixture`.
- Evidence: `SpawnFailed("mkdir workdir /run/user/9999/sy-plugins/sy-plugin-fake-pdf: Permission denied (os error 13)")`.
- Deterministic regression: `cargo test --test sy_file_plugin_preview runtime_precedence_probe_preserves_the_callers_environment -- --nocapture`.
  The child starts with a known `XDG_RUNTIME_DIR`; the precedence probe removes it,
  and the preservation assertion fails with `NotPresent`.

## Expected

Testing environment precedence must not change runtime-directory selection for
unrelated concurrent tests or remove their inherited environment variables.

## Actual

The sandbox test temporarily installs `/run/user/9999` and then removes
`XDG_RUNTIME_DIR`. Preview-process creation can observe that temporary directory.

## Root Cause

`runtime_dir_precedence_env_xdg_fallback` incorrectly assumes Cargo tests are
single-threaded. Its process-wide environment mutations are visible to async
preview tests; a registry-only lock does not protect runtime-directory reads.

## Fix

Run the existing three precedence assertions in an exact-test child process.
The parent never mutates its environment. Add a deterministic regression proving
that the caller's inherited `XDG_RUNTIME_DIR` survives the probe. Production
runtime-directory selection and plugin supervision remain unchanged.

## Traceability

- Failing test and fix: `src/plugin/sandbox.rs` test module, also included by the
  plugin preview integration binary.
- Acceptance passed: the deterministic regression, all 67 preview integration
  tests, `make lint`, `make fmt-check`, and two complete `make test` runs.
- Status: fixed locally; no production plugin behavior changed and no sy commit
  was made.
