# BUG-20260829-0921: Declared compile-cache root is absent at image self-test

## Summary

The non-root image self-test cannot initialize its configured runtime compiler
cache because the declared persistent writable root does not exist yet.

## Reproduction

- Method: clean ARM64 Docker build under UID 65534.
- Test: `tests/spark_engine_image_contract.rs::non_tmpfs_writable_roots_exist_before_non_root_self_tests`.
- Evidence: Torch attempts to create its cache below `/compile-cache` and fails
  because the root is neither present nor owned by the runtime UID.

## Expected

Every non-tmpfs writable root declared by the engine exists with the runtime
UID before any non-root import or self-test.

## Actual

The runtime mount contract was present in TOML and OCI labels, but the build
stage never materialized the mountpoint.

## Root Cause

The image relied on the executor to create a runtime mount without accounting
for build-time tests that execute under the same final UID and cache paths.

## Fix

Create the declared root with UID/GID 65534 and mode 0700 before the first
non-root boundary, and enforce the ordering generically for contracted images.

## Traceability

- Failing test: `tests/spark_engine_image_contract.rs::non_tmpfs_writable_roots_exist_before_non_root_self_tests`.
- Fixed in: `configs/sy/spark/engines/sglang-qwen38-mmap.Dockerfile`, `tests/spark_engine_image_contract.rs`.
