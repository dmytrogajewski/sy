# BUG-20260828-0942: Unbounded reasoning delays the first coding-agent tool call

## Summary

The Qwen3.8 Flash-Next engine profile leaves reasoning unbounded, allowing a
single coding-agent turn to consume its entire output allowance before using a
tool.

## Reproduction

- Launch Claude in a fresh empty directory against `qwen3.8:flash-next`.
- Ask it to implement and test a browser Tetris game.
- The first request produces 32,000 reasoning tokens, stops at `max_tokens`,
  and uses no tool. A continuation eventually begins writing files.
- The engine has no queue or memory pressure and decodes at 19–32 tokens/s.

## Expected

Reasoning remains enabled, but the model-specific serving profile provides a
finite default thinking budget so an agent reaches tools promptly. A client
with an explicit budget retains control.

## Actual

The profile configures sampling quality but no `thinking_token_budget`, so the
request's full 32,000-token output allowance can be spent entirely on thought.

## Root Cause

The declarative sampling schema has no generic field for the vLLM
`thinking_token_budget` sampling parameter.

## Fix

Add the bounded field to the generic engine sampling schema and propagate it as
a default through Chat, Responses, and Messages rewrites. Configure and verify
the Flash-Next profile on the real Spark without disabling reasoning.
