# BUG-20260828-0805: Patched vLLM instance fails during preparation

## Summary

The exact configured NVFP4 image and managed network pass independent Docker
inspection, but `sy spark serve` fails before container creation with a generic
preparation error.

## Reproduction

- Method: manual reproduction on the real `dgx-spark` appliance
- Command: `sy spark dgx-spark serve qwen3.8:flash-next --name qwen38-flash-next-nvfp4 --json`
- Evidence: operation `01M13BYSGD1JN829QNQ0W68783` failed with `exact image or
  network preparation failed`; the immediately preceding dry-run admitted the
  instance and selected engine `vllm-qwen38-mmap-arm64`, image
  `sha256:6de22b9186cbe400670fea217b7e78d2f7463852d43b0f5c44e2085a25fc8e5d`,
  and a 114,000,000,000-byte envelope.

## Expected

The executor validates the exact local image and managed network, creates the
isolated generation, and proceeds to vLLM startup.

## Actual

The durable serve operation fails in `PrepareInstance` before Docker container
creation. Direct Docker inspection reports the configured image ID as ARM64 and
the `sy-spark-internal` bridge as internal, managed, and valid.

## Root Cause

The executor's length-delimited JSON transport accepted at most 16 KiB per
request, while the signed model catalog permits up to 511 auxiliary artifacts.
The valid `PrepareInstance` request for this checkpoint contains 206 auxiliary
weight shards and exceeds 16 KiB. The executor codec therefore rejected the
frame and reset the connection before deserializing the typed action or
inspecting Docker. The agent mapped that transport failure to its generic
preparation error, which made the independently valid image and network appear
responsible.

## Fix

Keep the executor transport bounded, but raise its request limit to 512 KiB so
it covers valid catalog artifact sets. A regression serializes the real exact
Qwen checkpoint and patched-vLLM `PrepareInstance` request and requires it to
fit the executor frame. The existing fail-closed oversized-frame test continues
to verify rejection beyond the bound.

## Traceability

- Manual failing journey: operation `01M13BYSGD1JN829QNQ0W68783`
- Failing test: `spark::executor::tests::configured_model_prepare_request_fits_executor_frame`
- Fixed in: `src/spark/executor.rs`
