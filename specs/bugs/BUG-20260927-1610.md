# BUG-20260927-1610: the retrieval gate scored a corpus that does not exist

## Summary

`make eval` reported recall@1 0.056 / abstain accuracy 0.292 against floors of
0.30–0.50 and exited 3 forever, because the checked-in golden set encodes the
anecdote from `specs/knowledge-feedback-iter1/FEEDBACK.md` (a guy from X5 or
Магнит, met over New Year 2024) rather than the content this host actually
indexes.

## Reproduction

- Method: manual, against the live index.
- Command: `make eval`
- Evidence:

  ```text
  { "recall_at_1": 0.0556, "recall_at_5": 0.0556, "mrr": 0.0556,
    "abstain_accuracy": 0.2917, "n": 24 }
  error: eval regression: recall_at_1 0.056 < tolerance 0.300
  ```

  The old set asked for `Магнит`, `Сбербанк`, `Ozon`, `Wildberries`, `Лента`
  and six date-windowed "New Year / майские / лето" lookups. In the whole
  25 MB Telegram export `Магнит` occurs **6 times**; `notes`, `code` and
  `email` kinds return **0 points** from Qdrant (`~/Документы` and
  `~/Загрузки` are registered sources but contribute no visible chunks), and
  `agent-history` / `claude-transcripts` — 94 % of the collection — are
  excluded from default search by `DEFAULT_EXCLUDED_KINDS`.

## Expected

REQ-9's gate separates a retrieval regression from noise: floors that the
system can meet, measured on the corpus that exists, refreshed when the
corpus or the chunker contract changes.

## Actual

A permanently red gate. Nine of fifteen answerable rows were unsatisfiable in
principle, so the metric measured the golden set instead of the pipeline — and
a gate that is always red is indistinguishable from no gate.

### Claimed structural finding: no per-message dates — **retracted**

This section originally asserted that a chunk payload is
`{chunk_index, chunk_text, content_hash, file_mtime, file_path, kind, source,
tags}` — no temporal field but `file_mtime` — and that `date_from`/`date_to`
therefore cannot discriminate inside Telegram, so the `date-range` category
could only test filter *mechanics*. That was **wrong**, and it was the
load-bearing premise for a proposed multi-hour re-embed that was never needed.

Verified on the live collection (2026-09-27): the payload schema *does* carry
`date`, and qdrant indexes it natively —
`payload_schema: { "date": { "data_type": "datetime", "points": 6141 } }`,
alongside `from` (keyword), `has_media` (bool), `kind` and `tags`.
`pipeline/telegram/json.rs` reads each message's `date` and
`qdrant::build_filter` compiles `date_from`/`date_to` to
`{key: "date", range: {gte, lte}}`. A 2021-only count over `kind: telegram`
returns 482 points, and the four date-scoped rows below resolve against real
message dates once the windows are corrected.

What was true in the claim: the export stamps every *file* with mtime
2026-06-04, and the `date-range` rows **in this very file** had been authored
from that mtime rather than from the per-message `date` — which is precisely
why they looked unsatisfiable and why the mechanism was misdiagnosed as
absent. See BUG-20260927-1910 for the correction, the evidence, and the
repairs applied to this golden set (rows 6-9 re-windowed onto the gold's real
message date, three negatives moved to periods with no data, one mislabelled
negative replaced).

## Fix

1. Re-authored `specs/knowledge-feedback-iter1/eval/queries.jsonl` (24 rows,
   roadmap Step 13 counts: 6 named-entity, 7 date-range, 5 cross-source,
   6 abstain; 15 answerable / 9 not). Derivation was sample-first, not
   cherry-picked: scroll 300 points per kind in id order, take every 25th, and
   write one natural query per sampled chunk with `expected` copied verbatim
   from it — `Альпина Паблишер`, `Кениг`, `Сабсан`, `бойлер`,
   `офицер милиции`, `каршеринг`, `зарплатки`, `диз делать`. The abstain rows
   are topics a personal chat/voice archive genuinely lacks (k8s Helm
   annotations, PostgreSQL bloat, RFC 7231 etags, ГИБДД fees, borscht, mortgage
   refinancing).
2. Re-baselined `DEFAULT_EVAL_TOLERANCE` to the measured numbers minus one
   answerable query, with the measurement recorded in the constant's doc:
   recall@1 / recall@5 / MRR **0.400**, abstain accuracy **0.583** (was
   0.056 / 0.292). Measured shape noted honestly: `recall@1 == recall@5`
   because e5 + the reranker either rank the gold chunk first or drop it out
   of the top 5 entirely.
3. Stopped claiming CI runs it. `src/knowledge/eval.rs`, the `Makefile`
   `eval:` comment, and `EVAL_DRIFT`'s doc all said GitHub Actions gates on
   `make eval`; it does not — scoring needs a live index, and
   `.github/workflows/docs.yml` runs `make lint`, `make docs-lint` and
   `cargo test --doc`. They now say "on-host pre-push gate".
