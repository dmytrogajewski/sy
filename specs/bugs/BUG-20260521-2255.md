# BUG-20260521-2255: `RUSTDOCFLAGS=-D warnings cargo doc` fails with 52 rustdoc errors

## Status: CLOSED (2026-05-31)

Fixed via doc-comment-only edits across ~50 files. By the time the fix
landed the count had grown past the 52 originally triaged below (code
added since) to **107 individual errors** — 75 broken intra-doc links,
16 unclosed HTML tags, 4 public→private links, and 8
ambiguous/redundant-link/non-hyperlink — plus four `could not
document` rollups. All categories closed with the fix shapes described
here (escape config/math brackets, backtick HTML placeholders,
fully-qualify or demote-to-backticks broken links, disambiguate or
demote ambiguous links). Acceptance verified:

- `RUSTDOCFLAGS="-D warnings" cargo doc --no-deps --document-private-items --workspace` → exit 0.
- `RUSTDOCFLAGS="-D warnings" cargo doc --no-deps --workspace` (docs.rs shape, Batch-C gate) → exit 0.
- `cargo test --doc --workspace` → exit 0 (still 0 doctests authored).
- `.github/workflows/docs.yml` `rust-doc` job flipped from
  `continue-on-error: true` to a hard gate.
- `PLAN-full.md` Item 26 DoD bullet 1 ticked.

No runtime logic changed; doc comments only. (The `src/file/ipc.rs`
integration-test compile error seen during `make lint` is unrelated
pre-existing WIP on the `fix/knowledge-mcp-bounded-responses` branch,
not part of this BUG.)

## Summary
`RUSTDOCFLAGS="-D warnings" cargo doc --no-deps --document-private-items --workspace`
exits 101 with 52 individual errors (plus two `could not document <crate>`
rollups), blocking the `rust-doc` CI gate added under
`specs/archive/docs-audit/PLAN-full.md` Item 26. Errors split three ways:

- **37 broken intra-doc links** (`rustdoc::broken_intra_doc_links`,
  implied by `-D warnings`) where `///` / `//!` comments reference
  identifiers that are not in scope at the link site, or escape `[…]`

  placeholder syntax such as `<id>`, `<uuid>`, `<name>`, `<N>`,
  `<unix>`, or `Vec<Item>` inside doc comments is parsed as a real
  HTML tag because it is not fenced with backticks or escaped.

  (`rustdoc::private_intra_doc_links`) where
  `crates/sy-core/src/obs/trace_ctx.rs` exposes a public
  `with_trace_id` whose docs link to a private `TRACE_SPAN_NAME`
  constant — link works under `--document-private-items` but breaks
  for `docs.rs` consumers.

`cargo test --doc --workspace` currently exits 0 (no doctests authored
in any workspace member at this point), so the `R-ECO-03` side of
PLAN Item 26 is already satisfied. This bug is scoped to `R-ECO-01`
only — making `RUSTDOCFLAGS="-D warnings" cargo doc` clean — so the
`rust-doc` CI job that Item 26 wires in starts passing.

This BUG is the deferred work hand-off from `/documenter` Item 26 per

## Root Cause

### Category A — 37 broken intra-doc links

Every entry below is `file:line:col → link target`. Targets fall into
three sub-categories:

1. **Identifier not in scope at the link site** — fix is to switch
   the link to a fully qualified path (`crate::…`) or drop the link
   syntax and wrap the bare name in backticks.
2. **Escape needed** — `[0,1]`, `argv[0]`, `[knowledge]`,
   `[colors]`, `[ui]`, `[predict]` etc. are math/config-section
   notation, not rustdoc link syntax. Fix: prefix `[` with `\` per
   rustdoc's own hint, or wrap the whole expression in backticks.
3. **Stale rename** — the linked item was renamed or removed
   (`Scheduler::inflight_snapshot`, `Clucb::arm_update_count`,
   `Clucb::arm_count`, `ShieldState::index`). Fix: update the link
   to the current name, or drop the link if the referenced API was
   intentionally removed.

## Fix

Three independent `/implement` batches, each with its own micro-TDD
loop and its own commit:

1. **Batch B (unclosed HTML, 14 sites, 8 files)** — lowest risk,
   purely mechanical. Wrap each `<placeholder>` in backticks.
   Verifier: `RUSTDOCFLAGS="-D warnings" cargo doc --no-deps
   --document-private-items --workspace 2>&1 | grep -c 'unclosed HTML'`
   must drop from 14 to 0.

2. **Batch A (broken intra-doc links, 37 sites, ~25 files)** —
   group by sub-category. Most sites fix with `\[…\]` escapes or
   `crate::…` paths; the four stale-rename sites
   (`Scheduler::inflight_snapshot`, `Clucb::arm_update_count`,
   `Clucb::arm_count`, `ShieldState::index`,
   `crate::power::clock::MockClock`) require code archaeology — the
   referenced API moved or was deleted. Fix shape: either rewire the
   link to the new name, drop the link, or restore the referenced
   item if its removal was inadvertent.
   Verifier: `RUSTDOCFLAGS="-D warnings" cargo doc --no-deps
   --document-private-items --workspace 2>&1 | grep -c 'unresolved link'`
   must drop from 37 to 0.

3. **Batch C (private-item link, 1 site, 1 file)** — promote
   `TRACE_SPAN_NAME` to `pub(crate)` so `crates/sy-core/src/obs/trace_ctx.rs`'s
   public `with_trace_id` doc link is valid under
   non-`--document-private-items` builds (the `docs.rs` default).
   Verifier: `RUSTDOCFLAGS="-D warnings" cargo doc --no-deps --workspace
   2>&1 | grep -c 'private item'` (NOTE: no `--document-private-items`
   on this verifier — that's the docs.rs build shape) must be 0.

Final acceptance: `RUSTDOCFLAGS="-D warnings" cargo doc --no-deps
--document-private-items --workspace` exits 0 after all three batches,
and the `rust-doc` CI job in `.github/workflows/docs.yml` turns green.
