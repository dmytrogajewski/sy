# BUG-20260829-0915: PLE allocator self-test omits helper dependencies

## Summary

The real ARM64 image build cannot execute the PLE mmap self-test after the
persistent allocator patch because the test extracts only the allocator body.

## Reproduction

- Method: real-device clean Docker build.
- Command: `docker build --pull=false --no-cache --progress=plain --file sglang-qwen38-mmap.Dockerfile --tag sy-spark/sglang-qwen38-mmap:step8-20260829 .`.
- Evidence: `_alloc_ple_table` raises `NameError: name '_ple_cache_state' is not defined` from the content-addressed PLE self-test.

## Expected

The synthetic mmap test executes the complete patched allocator contract and
fails only when its persisted mmap semantics are wrong.

## Actual

The test compiles the allocator function in isolation even though the durable
transformer makes it depend on source-binding and publication helpers.

## Root Cause

The original self-test's AST extraction boundary was not expanded when the
persistence transformer added allocator helper functions and constants.

## Fix

Extract the allocator's private PLE helper functions and constants as one
generic AST contract while retaining the existing mmap and gather assertions.

## Traceability

- Failing test: clean ARM64 Docker build step 12.
- Fixed in: content-addressed PLE mmap self-test asset and its Docker labels/COPY invocation.
