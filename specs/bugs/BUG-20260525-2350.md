# BUG-20260525-2350: EPP actuator silently degrades on hybrid-core hosts — tmpfiles.d covers only policy0-policy11; actuator aborts on first unwritable policy

## Summary
`configs/systemd/tmpfiles.d/sy-power.conf` chmods `energy_performance_preference` for `policy0`-`policy11` only, but this HX 370 host has 24 cpufreq policies (policy0-policy23). Policies 12-23 stay `0644 root:root`, unwritable by the user-level `sy-powerd`. The EPP actuator (`src/power/apply/epp.rs:84-112`) iterates policies in lexicographic order and uses `?`-propagation on `write_if_changed`, so the first unwritable policy in sort order (`policy12`) aborts the whole call; policies 13-23 are never even attempted. Every shield transition that lands a new EPP value triggers a `WARN actuator failed lever=epp error=write /sys/devices/system/cpu/cpufreq/policy12/energy_performance_preference` line, the daemon's lever-B output is effectively partial (whatever policies 0-11 picked, with 12-23 frozen at whatever the kernel last wrote), and the bandit's reward signal includes phantom drift from the half-applied EPP.

## Reproduction
- Method: manual + sysfs probe (test-based repro lands with the fix per `/implement`).
- Live host evidence:
  ```
  $ ls /sys/devices/system/cpu/cpufreq/ | grep -c '^policy'
  24
  $ grep -c '^z /sys/devices/system/cpu/cpufreq/policy' \
      configs/systemd/tmpfiles.d/sy-power.conf
  12                                  # policy0..policy11 only
  $ ls -l /sys/devices/system/cpu/cpufreq/policy{0,11,12,23}/energy_performance_preference
  -rw-rw-r--. 1 root wheel ... policy0/...
  -rw-rw-r--. 1 root wheel ... policy11/...
  -rw-r--r--. 1 root root  ... policy12/...    # unwritable by sy-powerd
  -rw-r--r--. 1 root root  ... policy23/...    # ditto
  ```
- Journal evidence (recurring across 4 days of telemetry, every restart + every shield transition):
  ```
  $ journalctl --user -u sy-powerd.service --since '4 days ago' \
      -p warning -g 'actuator failed' --output=cat | sort -u | wc -l
  14
  $ journalctl --user -u sy-powerd.service --since '4 days ago' \
      -p warning -g 'actuator failed' --output=cat | head -1
  WARN actuator failed lever=epp error=write /sys/devices/system/cpu/cpufreq/policy12/energy_performance_preference
  ```
  (Every line names `policy12` — never policy13+ — confirming first-failure abort.)

## Expected
1. `configs/systemd/tmpfiles.d/sy-power.conf` enumerates EVERY `policy<N>` directory the kernel exposes on a Ryzen AI 300-series host (24 entries for HX 370 — 12 physical × 2 SMT).
2. After `systemd-tmpfiles --create`, all 24 EPP files are `0664 root:wheel` and `sy-powerd` (in `wheel`) can write them.
3. The EPP actuator continues across per-policy write failures instead of aborting on the first one — partial coverage is better than zero coverage if a future kernel/hardware exposes a policy that's intentionally read-only.
4. No `actuator failed lever=epp` lines in the daemon journal under steady-state operation.

## Actual
1. `tmpfiles.d/sy-power.conf` hardcodes 12 entries (policy0-policy11), matching the SPEC §4-era assumption of a 12-core / 12-policy CPU.
2. Policies 12-23 stay `0644 root:root`; only root can write them.
3. `set_epp` (`src/power/apply/epp.rs:97-104`) uses `?` on `write_if_changed`, so the FIRST unwritable policy in sort order (`policy12` lexicographically follows `policy11`) raises `Err(WriteFailed)` and the actuator returns without touching policies 13-23.
4. The daemon's `apply_arm` path catches the Err and logs `actuator failed` (`src/power/daemon.rs:~620`), one line per shield-driven EPP change.

## Root Cause
- **Productisation gap:** the tmpfiles.d list was authored against the per-step hardware in `sy-power-hotfix` (12 policies) and never extended when the deployment moved to a 24-policy hybrid CPU. CLAUDE.md "no snowflakes" requires the config to be expressed once and apply universally, but the per-policy enumeration in `sy-power.conf` is a static list, not generated.
- **Actuator robustness gap:** `set_epp` treats per-policy write failure as fatal for the whole actuator call. The kernel intentionally exposes per-policy EPP because writes are per-policy, so the actuator should follow suit: aggregate failures, log warnings, but try every policy before returning. The current code's `?` short-circuits before policies 13+ are ever touched.

## Fix
1. **Replace the static `policy0..policy11` block in `configs/systemd/tmpfiles.d/sy-power.conf` with a wildcard or full-coverage enumeration.** Two options:
   - `z /sys/devices/system/cpu/cpufreq/policy*/energy_performance_preference 0664 root wheel - -` (single line, tmpfiles supports globs).
   - OR generate the 24 explicit lines via the installer / `sy apply` so the file matches the live policy count exactly.
   Prefer the glob — survives a kernel upgrade that adds or removes policies.
2. **Make `set_epp` resilient to per-policy write failure** (`src/power/apply/epp.rs:84-112`):
   - Collect per-policy results into a `Vec<Result<Applied, EppError>>`.
   - Return `Applied::Wrote { path: <first_ok>, value }` if any policy succeeded, else `Err(EppError::NoPolicyWritable { failed: Vec<PathBuf> })`.
   - `WARN` once per call with the count + list of failed policies (rate-limit at the daemon's `apply_arm` log site so the daemon journal doesn't spam 24 lines per tick).
3. **Tests** (`src/power/apply/epp.rs::tests`):
   - `aggregates_per_policy_failures_without_aborting` — fixture with 4 policies: policy0/1 writable, policy2 ENOPERM, policy3 writable; assert `set_epp` returns `Wrote{path: policy0/...}` AND policy3's leaf was written.
   - `errors_only_when_every_policy_fails` — all-read-only fixture asserts `Err(NoPolicyWritable)` with all four paths in the list.
4. **Installer test** (`src/power/apply/installer.rs::tests` or new `tests/tmpfiles_policy_coverage.rs`):
   - Parse `configs/systemd/tmpfiles.d/sy-power.conf`; assert the EPP entry uses the glob OR enumerates ≥ `num_cpus::get()` policies. Prevents the next CPU upgrade from regressing silently.
5. **One-shot recovery on this host:** after the fix, `sudo systemd-tmpfiles --create configs/systemd/tmpfiles.d/sy-power.conf` to flip permissions on policy12-policy23 without reboot.
