# BUG-20260829-0514 — warm engine restart double-counts durable storage

## Symptom

A stopped, previously qualified Spark engine cannot be started when the host
has 127 GiB free. Admission subtracts the engine image and full compile-cache
capacity again, reports `spark.disk.reserve`, and rejects before Docker even
though the exact local image and instance-scoped cache already occupy the
filesystem reflected by the free-space sample.

## Reproduction

1. Start and stop a managed engine whose local image and compile cache exceed
   the disk reserve margin.
2. Serve the same instance name, model, engine image, profile, and artifact
   identity again.
3. Observe that `disk_available_after_start_bytes` subtracts
   `image_bytes + compile_cache_bytes` as if both were absent.

On `dgx-spark`, 136,453,222,400 bytes were available. Admission projected only
55,645,361,872 bytes after start by subtracting 80,807,860,528 bytes already
present on that same filesystem.

## Root cause

The agent always treats configured image and compile-cache capacities as new
allocations. It does not ask the privileged executor whether the digest-pinned
local image exists or how many allocated bytes already belong to the exact
instance-scoped compile-cache namespace. The first executor implementation also
treated an engine-owned mode-0700 temporary directory as a fatal scan failure.
The hardened executor intentionally has no `CAP_DAC_OVERRIDE`, so such a
directory is unreadable even though its parent namespace is trusted and the
engine is stopped.

## Expected behavior

The executor reports candidate-specific durable storage using the same generic
container specification used for launch. Admission subtracts only remaining
growth: zero for an existing local image and
`max(compile_cache_capacity - allocated_cache_bytes, 0)` for the exact cache
namespace. A different model, engine identity, profile, or instance must not
receive this credit. If a child directory cannot be read, only its already
measured directory inode is counted; its unseen contents remain uncredited.

## Acceptance

- A warm restart of the same immutable instance is admitted when its measured
  remaining storage growth preserves the configured reserve.
- A different instance with an empty namespace is still rejected under the
  same free-space conditions.
- Missing cache state receives zero credit. Unreadable subtrees remain
  uncredited. Symlinked, duplicate-inode, malformed, or oversized walks fail
  closed.
- Image presence is proven by the container runtime; no filename or engine
  family is embedded in Rust.
- The real `dgx-spark` launch passes without deleting caches or lowering the
  100 GiB reserve.
