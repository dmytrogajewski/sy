# BUG-20260827-1005: Arbitrary Spark models disappeared behind catalog metadata

## Summary

The multi-engine download path accidentally turned the optional recommendation
catalog into a privileged path: arbitrary repositories required an exact
`--artifact`, vLLM accepted only FP8 metadata, and valid installed records were
hidden when they predated the new artifact field.

## Reproduction

- `sy spark dgx-spark ls` omitted the previously installed Ornith 9B and Qwen
  embedding registrations even though their Hugging Face snapshots remained.
- `download owner/model` failed unless the operator supplied `--artifact`.
- A safetensors model with BF16 or unspecified quantization matched no engine.

## Expected

Any Hugging Face repository can be installed. Optional model configuration pins
recommended artifacts and tuning, while generic inspection selects complete
safetensors snapshots for vLLM or a deterministic GGUF default for llama.cpp.
Schema upgrades retain installed model inventory.

## Actual

Catalog entries received capabilities unavailable to arbitrary repositories,
vLLM was artificially limited to FP8, and missing new metadata caused otherwise
valid model records to be quarantined during upgrade.

## Root Cause

Artifact identity and engine selection were implemented as a closed catalog
boundary instead of a generic default with configuration overrides. The state
decoder also used field presence as a compatibility boundary even though the
artifact field is optional and can be re-indexed from immutable cached data.

## Fix

- Missing selectors invoke deterministic repository-tree inspection.
- Complete safetensors snapshots default to vLLM regardless of quantization.
- GGUF-only repositories prefer Q4_K_XL, then Q4_K_M; ambiguity still requires
  an explicit selector.
- Model records without artifact metadata remain visible and recoverable.
- The recommendation catalog remains an optional alias/configuration layer.
- Hugging Face pipeline metadata distinguishes generation from embedding
  snapshots. Embeddings select a declarative vLLM pooling profile, derive vector
  dimensions from `config.json`, and leave model context length to vLLM unless a
  profile explicitly overrides it.

## Real-device verification

- The retained Ornith 9B safetensors snapshot was re-indexed through the generic
  vLLM path with zero transferred bytes.
- The retained Qwen3 Embedding 0.6B snapshot was re-indexed with
  `text_embeddings` capability and zero transferred bytes.
- vLLM 0.27.1 automatically converted Qwen to its embedding architecture, used
  its native 32,768-token context, and exposed the OpenAI-compatible embeddings
  route.
- An authenticated workstation request returned a canonical model identity, a
  1,024-dimensional vector, and token usage. Qwen was then stopped and the
  preceding Ornith service restored.

## Traceability

Coverage lives in the Spark model, engine, agent, wire, and state unit tests for
automatic selection, generic vLLM matching, arbitrary repositories, and model
record discovery without artifact metadata. Executor coverage additionally
asserts vLLM's `--runner pooling` selection, model-derived embedding dimensions,
and absence of a global context-length override.
