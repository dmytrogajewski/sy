# BUG-20260601-1943 — `plugin_crash_falls_back_to_built_in_text` flakes under parallel `make test`

## Status
Open — flaky test (not a product bug). Filed by `/march` per the "unrelated
failing test exposed during work" decision default; does NOT block the
knowledge-retrieval-iter1 roadmap.

## Symptom
During Step 4 verification, `make test` (`cargo test --workspace --all-targets`)
failed once on:

```
test plugin_crash_falls_back_to_built_in_text ... FAILED
thread 'plugin_crash_falls_back_to_built_in_text' panicked at tests/sy_file_plugin_preview.rs:521:18:
expected PluginCrashed, got SpawnFailed("mkdir workdir /run/user/9999/sy-plugins/sy-plugin-crash: Permission denied (os error 13)")
```

Re-running the test in isolation passes; re-running the full `make test`
passes (1619/0). `/run/user/9999` does not exist between runs.

## Root cause (hypothesis)
The test uses a fake `XDG_RUNTIME_DIR` under `/run/user/9999/sy-plugins/`.
Under parallel test execution, another test (or a prior parallel shard)
appears to create/own `/run/user/9999` with perms that deny this test's
`mkdir`, then removes it — a test-isolation race on a shared fixed-UID
runtime path, not a code defect. The plugin-preview spawn path itself is
fine (the fallback works; the test just couldn't set up its workdir).

## Reproduction
Intermittent under `cargo test --workspace --all-targets` (parallel). Not
reproducible in isolation (`cargo test --test sy_file_plugin_preview
plugin_crash_falls_back_to_built_in_text` → ok).

## Proposed fix (for a future `/bug` run)
Give the test a unique, process/test-scoped runtime dir (e.g. a `tempfile`
TempDir as `XDG_RUNTIME_DIR`) instead of the fixed `/run/user/9999`, so
parallel tests cannot collide on the same path. Audit other tests under
`tests/sy_file_plugin_preview.rs` for the same shared-path pattern.
