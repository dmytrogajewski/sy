# BUG-20260830-2227: Codex Working indicator disappears mid-turn

## Summary

The Spark Responses adapter omits assistant message `phase` metadata. Codex
therefore cannot distinguish progress commentary from a final answer and hides
its Working status row while the turn is still active.

## Reproduction

- Launch Codex through `sy spark dgx-spark launch codex`.
- Run a multi-step task that emits progress text before a tool call.
- Observe that the progress text and tool call execute, but the Working shimmer
  disappears during the next inference interval.
- The captured session records the progress message with `phase: null`, followed
  by an `exec_command` in the same response and no `task_complete` event.

## Expected

Messages followed by tool calls are emitted with `phase: "commentary"` so
Codex keeps the active-turn status visible. Terminal text-only messages are
emitted with `phase: "final_answer"`.

## Actual

`ResponsesEncoder` omits `phase` from streamed message completion items and
from the final Responses document.

## Root Cause

The chat-completions upstream does not provide Responses message phases. The
adapter reconstructs Responses items but does not derive the phase from the
completed generation, even though it knows whether the response contains tool
calls.

## Fix

At generation completion, classify message text as commentary when the same
response contains one or more tool calls; otherwise classify it as the final
answer. Preserve the phase in both `response.output_item.done` and the final
response document.
