# BUG-20260723-2210: all-or-nothing coverage gate deadlocks the trainer forever

## Summary
The trainer's per-class coverage gate rejects the whole retrain unless
EVERY activity class has ≥ 16 labelled rows, but training labels derive
from the *applied arm's* reason chain — so classes the rules baseline
never applies (`call`, `build`) can never accrue rows, the model never
replaces the rules baseline, and the drift alarm never clears.

## Reproduction
- Method: test
- Test: `power::trainer::tests::trains_when_uncovered_classes_can_be_excluded`
- Evidence:
  ```
  thread '...trains_when_uncovered_classes_can_be_excluded' panicked:
  covered classes must train despite zero-row classes:
  InsufficientClassCoverage { counts: [67, 67, 0, 66, 0],
  missing: ["call", "build"], required: 16 }
  ```
- Live-host sighting (2026-07-23, sy-powerd journal): 16 days after
  first telemetry, every retrain (cause=Onboarding and cause=Drift)
  skipped with
  ```
  trainer: insufficient per-class coverage: missing ["call", "build"]
  (need ≥ 16 rows each; counts=[3622, 57149, 0, 1162, 0])
  ```
  `sy power status` shows `model.version_sha = "rules-baseline"`,
  `params = 0`, `drift.adwin_alarm = true` latched since the gate
  tripped, and the human CLI exits non-zero with
  "error: sy-powerd reports drift alarm (model degraded)".

## Expected
Classes below the row floor are *excluded* from the train (their rows
dropped from the corpus) rather than blocking it, as long as at least
two classes clear the floor — a softmax over < 2 classes is degenerate.
The report names the excluded classes; the daemon keeps surfacing them
on `sy power status` (`model.missing_classes`) after a successful
partial train so the blind spots stay visible.

## Actual
`retrain_with_sink` (src/power/trainer.rs) returned
`InsufficientClassCoverage` whenever ANY class was under
`MIN_ROWS_PER_CLASS`, permanently pinning the daemon to the
rules-baseline warmup model on any host whose baseline heuristics
don't reach all five arms.

## Root Cause
Circular dependency between labelling and training. Labels come from
the applied arm (`labels::extract_label`); pre-model, arms are applied
only by the rules baseline; the baseline's heuristics on this host
never fire the `call`/`build` arms; the Step T3 gate
(BUG-20260525-2352) then treats those structurally-unreachable classes
as a fatal coverage deficit. The gate was designed to stop a silently
bad head from shipping, but as an all-or-nothing check it also stops
any model from *ever* shipping — and because a successful retrain is
what clears the ADWIN drift alarm, the alarm latches and the status
CLI reports the plane as failed indefinitely.

## Fix
`retrain_with_sink` now partitions classes into covered
(≥ `MIN_ROWS_PER_CLASS`) and excluded. If fewer than
`MIN_COVERED_CLASSES` (2) are covered the old
`InsufficientClassCoverage` error stands. Otherwise the excluded
classes' rows are dropped from the corpus (same treatment as
unlabelled rows), training proceeds on the covered classes, and
`TrainerReport.excluded_classes` carries the exclusion list. The
5-class ONNX head shape is unchanged — excluded heads simply receive
only negative gradient, so they never win argmax, and the per-class
recall floor still guards every class that *is* trained. The daemon's
retrain success path publishes `report.excluded_classes` as
`ModelStatus.missing_classes` (previously it cleared the slot), and
`sy power train` prints `excluded=<list>` when non-empty.

## Follow-up landed with this fix
The daemon also WARNed on every IPC tick that the 7-day telemetry
retention horizon starves the 14-day onboarding window
(`onboarding::retention_guard`). `DEFAULT_RETENTION_DAYS` is now 14 so
a stock install never boots into that mismatch; pinned by
`power::onboarding::tests::default_retention_covers_default_onboarding_window`
(src/power/log.rs, src/power/onboarding.rs).
