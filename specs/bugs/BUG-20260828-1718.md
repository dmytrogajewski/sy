# BUG-20260828-1718: Resolved Spark quarantine keeps doctor degraded

## Summary

Spark records quarantine evidence durably, but never distinguishes active
Docker quarantine from resolved historical evidence. Removed containers can
therefore keep `sy spark <host> doctor` degraded forever.

## Reproduction

- Method: real `dgx-spark` reconciliation after stopping an engine generation
  rejected by a newer signed engine catalog.
- Evidence: Docker no longer contains the stopped generation, while doctor
  reports twelve old container IDs plus the stopped instance as quarantined.

## Expected

Evidence remains durable for audit, but only containers present in the latest
successful full managed-container scan are active doctor failures. Once the
container disappears, its evidence is resolved and the matching instance is
released from quarantine.

## Actual

`quarantine_evidence` has no resolution lifecycle. Every row and every
instance quarantine is reported as a current failure indefinitely.

## Root Cause

Reconciliation only appends quarantine observations. It does not atomically
synchronize the active set after a successful full Docker scan.

## Fix

Add a nullable resolution timestamp, atomically synchronize the active
quarantine set after each successful scan, retain resolved rows as audit
evidence, and clear instance quarantine only when no active observation still
references that exact generation.

## Traceability

- Failing test: `spark::state::tests::reconcile_quarantine_resolves_absent_evidence_and_instance_state`
- Fixed in: `src/spark/state.rs`, `src/spark/agent.rs`
