# BUG-20260829-0047: Engine metadata changes orphan compile caches

## Summary

Changing non-execution engine metadata creates a new compile-cache namespace and strands large reusable artifacts.

## Reproduction

- Method: real DGX Spark failure followed by a deterministic unit test
- Test: `src/spark/executor.rs::tests::scheduling_metadata_preserves_compile_cache_namespace`
- Command: `cargo test --features spark-agent spark::executor::tests::scheduling_metadata_preserves_compile_cache_namespace`
- Evidence: changing only engine priority changes the `/compile-cache` source path; the real SGLang qualification stranded a completed 47.7 GiB PLE file after a resource-only correction.

## Expected

Cache namespaces change only when engine execution compatibility, image identity, model identity, profile, or verified artifacts change.

## Actual

The namespace includes the SHA-256 of the complete engine TOML, so priority, admission estimates, health policy, and sampling changes invalidate it.

## Root Cause

`build_generic_container_spec_with` uses `EnginePolicy::fingerprint()`, which hashes the complete declaration, as the engine component of `compile_identity`.

## Fix

Build the generic cache identity from the schema, engine ID/version/image/architecture/runtime UID, model repository/commit, selected profile, and verified artifact fingerprint. Declarative scheduling, admission, health, and sampling metadata no longer participates.

## Traceability

- Failing test: `src/spark/executor.rs::tests::scheduling_metadata_preserves_compile_cache_namespace`
- Fixed in: `src/spark/executor.rs`
