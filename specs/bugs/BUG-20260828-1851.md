# BUG-20260828-1851 — FreeToken coding session exhausts the declared token pool

## Report

A fresh Claude Code Tetris journey reaches 65,577 input tokens and then retries
the public Anthropic route as `503 healthy generation became unavailable`.
The FreeToken engine remains healthy, but its Qwen3.6 profile has only 65,536
total KV tokens, below the checkpoint's native long-context capability and the
262,144-token qualification target in the Spark specification.

## Evidence

On the real `dgx-spark`, FreeToken served the journey at approximately 48–51
decode tokens per second until its log reported `Input sequence length 65577
exceeds 65536`. The container stayed up and `sy spark dgx-spark ps` continued to
report the instance Healthy. Before the limit, the same journey performed more
than forty successful streamed tool cycles and caught its own constructor bug.

## Acceptance

- The Qwen3.6 FreeToken profile declares a 262,144-token shared scheduler pool.
- The change is shipped as engine configuration, without a model or engine
  branch in Rust.
- The real Spark starts healthy with the larger pool while preserving the
  protected-stack fingerprint and admission reserve.
- Fresh Claude, Codex, and OpenCode Tetris journeys complete with passing tests.
