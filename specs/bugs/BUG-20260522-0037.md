# BUG-20260522-0037: `sy power show` cannot reach 86,400-entry thick report

## Summary
`sy power show` is structurally unable to produce a 24-h "thick" report because the daily audit-log file caps at ~40K entries instead of 86,400. Three contributors compound:
(a) `DEFAULT_MAX_SIZE_BYTES = 50 MiB` is too small for 24 h × 1 Hz at the current entry size,
(b) `reason_chain` entries swallow the full `xrt-smi` stderr block (build hash, PID, host, exe path) every tick, inflating one audit line from ~600 B to ~1.3 KB,
(c) `parse_since` rejects the `d` suffix despite CLI help, the SPEC §RV.2 example, and `DEFAULT_SHOW_SINCE = 7*24*3600` all advertising `--since=7d` / `--since=1d`.

## Reproduction

- Tests:
  - `src/power/log.rs::tests::parse_since_accepts_day_suffix` (new)
  - `src/power/log.rs::tests::default_max_size_fits_one_day_at_1hz` (new)
  - `src/power/daemon.rs::tests::npu_skipped_reason_is_single_line_and_bounded` (new)
- Command: `cargo test --workspace power::`
- Live-host evidence (Fedora 43, sy-powerd active since 2026-05-21 23:51 MSK):
  - `wc -l ~/.local/state/sy/power/telemetry-2026-05-21.ndjson` → 46,820 (46,818 entries + 2 `rotated:size_cap` markers)
  - `stat -c%s` on same file → 52,428,479 B (50 MiB − 1)
  - `tail` shows `{"marker":"rotated:size_cap",...}`
  - `head -1 | wc -c` → 1,256 B/entry; substring contains:
    ```
    "npu: skipped (xrt-smi configure --pmode failed: XRT build version: 2.21.75
    Build hash: 4eb1f4392a012b4e6eca759762389c612537f7c7
    Build date: 2026-03-09 20:30:37
    Git branch: HEAD
    PID: 1807365
    UID: 1000
    ```

  - `journalctl --user -u sy-powerd.service --since "10 min ago"` → `"tick append failed"` / `"audit log size cap reached for today"` once per second.
  - `sy power show --since=1d` (per CLI help text) → exits 2: `--since="1d" unparseable (expected e.g. 30s, 15m, 1h, 7d)`.

## Expected
1. `parse_since("1d") == Some(86_400 s)` and `parse_since("7d") == Some(7 × 86_400 s)`.
2. A typical audit entry stays under ~1 KB; the multi-line `xrt-smi` stderr (build hash / PID / host / exe path) does NOT leak into the persistent `reason_chain` string.
3. `DEFAULT_MAX_SIZE_BYTES` is large enough that 86,400 entries fit in one day with realistic headroom.

## Actual
1. `parse_since("1d") == None` → CLI exits 2.
2. NPU failure mode embeds a ~600 B multi-line stderr block in every audit entry where the actuator returns `Err`.
3. 50 MiB / ~1.3 KB ≈ 40,329 entries — file caps ~14 h before the 86,400-entry threshold.

## Root Cause
1. **`parse_since` suffix table is incomplete** — `src/power/log.rs:495-500`:
   ```rust
   let secs_per_unit: u64 = match suffix {
       "s" => 1,
       "m" => 60,
       "h" => 3600,
       _ => return None,
   };
   ```
   No `"d"` arm. The existing test at `log.rs:767` even pins the wrong behaviour (`assert_eq!(parse_since("1d"), None)`). Docstring of `parse_since` at `log.rs:481` calls out "three suffixes", but every caller's help text + the SPEC's own example contradicts it.
2. **`NpuError::XrtSmiFailed::Display` stringifies untrimmed stderr** — `src/power/apply/npu.rs:56-58`:
   ```rust
   NpuError::XrtSmiFailed { stderr } => {
       write!(f, "xrt-smi configure --pmode failed: {stderr}")
   }
   ```
   The `stderr` field is the raw captured xrt-smi stderr block (npu.rs:86, npu.rs:113), and the daemon at `src/power/daemon.rs:611` shoves the full `{e}` Display string straight into the audit `reason_chain`. The audit log is meant for compact, single-line tokens — multi-line operator-debug context belongs in `tracing::warn!` (already emitted at daemon.rs:610), not in the persistent NDJSON.
3. **50 MiB cap predates the current entry size** — `src/power/log.rs:48`:
   ```rust
   pub const DEFAULT_MAX_SIZE_BYTES: u64 = 50 * 1024 * 1024;
   ```
   With the trimmed entry size (~700 B), 86,400 entries ≈ 58 MiB. We need realistic headroom (variance from `top3`, `ranked_actions`, reason chains during high churn) to clear the threshold reliably.

## Fix
1. Add `"d" => 86_400` to `parse_since`. Update the existing test to assert `parse_since("1d") == Some(Duration::from_secs(86_400))` and `parse_since("7d") == Some(Duration::from_secs(7 * 86_400))`.
2. Sanitize the NPU reason at the audit-write boundary: in `src/power/daemon.rs`'s `apply_arm`, replace `format!("npu: skipped ({e})")` with a `short_npu_reason(&e)` helper that:
   - takes only the first non-empty line of the error,
   - strips known boilerplate ("XRT build version", "Build hash", "Build date", "Git branch", "PID:", "UID:", "HOST:", "EXE:", "[" timestamp lines),
   - caps total length at 160 chars.
   The full stderr stays in `tracing::warn!` for live debugging.
3. Raise `DEFAULT_MAX_SIZE_BYTES` to `200 * 1024 * 1024` (200 MiB). At the post-fix entry size (~700–1000 B) this fits ≥200K entries — comfortable headroom for 86,400 with bursty reason chains.
