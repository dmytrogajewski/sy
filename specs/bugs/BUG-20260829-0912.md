# BUG-20260829-0912: Non-root image self-test has no writable home

## Summary

The clean ARM64 candidate build fails before publication because its non-root
SGLang import resolves the image user's home to an unwritable path.

## Reproduction

- Method: real-device clean Docker build plus generic contract test.
- Test: `tests/spark_engine_image_contract.rs::non_root_image_self_tests_receive_the_declared_home`.
- Command: `docker build --pull=false --no-cache --progress=plain --file sglang-qwen38-mmap.Dockerfile --tag sy-spark/sglang-qwen38-mmap:step8-20260829 .`.
- Evidence: Torch import raises `PermissionError: [Errno 13] Permission denied: '/nonexistent'` while creating its compile cache under UID 65534.

## Expected

Every build-time import self-test runs as the declared runtime UID with the
declaratively configured writable home already active.

## Actual

The Dockerfile declares `HOME` only after the non-root build self-test, so the
base image's passwd entry supplies `/nonexistent`.

## Root Cause

The final-runtime environment boundary was placed after the first `USER`
boundary instead of before every non-root import.

## Fix

Move the declarative `HOME` assignment before the first non-root self-test and
enforce that ordering for every contracted image.

## Traceability

- Failing test: `tests/spark_engine_image_contract.rs::non_root_image_self_tests_receive_the_declared_home`.
- Fixed in: `configs/sy/spark/engines/sglang-qwen38-mmap.Dockerfile`, `tests/spark_engine_image_contract.rs`.
