# BUG-20260825-0208: File CLI unit dispatch starts winit off main thread

## Summary

The bare `sy file` unit dispatcher panics when the test harness has a PTY because terminal detection alone routes a worker thread into winit initialization.

## Reproduction

- Method: test
- Test: `file::cli::tests::dispatch_routes_bare_form_to_scaffold`
- Command: `cargo test file::cli::tests::dispatch_routes_bare_form_to_scaffold -- --exact --nocapture` from a PTY
- Evidence: winit 0.30 panics that initializing the event loop outside the main thread is a cross-platform compatibility hazard.

## Expected

The unit dispatcher exercises bare-form routing without process-global GUI side effects; the normal `sy` binary still launches iced when stdout is a terminal.

## Actual

The test harness's PTY stdout satisfies the production TTY gate, so the test worker attempts to initialize winit.

## Root Cause

`run_gui_if_tty` distinguished GUI and headless execution only through `stdout.is_terminal()`. Rust unit tests execute on harness worker threads, and a PTY-backed test run makes that condition true even though winit must be initialized by the process main thread.

## Fix

Short-circuit GUI launch in a unit-test harness before terminal detection. Normal binaries retain the existing TTY launch behavior, while integration tests continue to exercise the normally compiled binary.

## Traceability

- Failing test: `src/file/cli.rs::tests::dispatch_routes_bare_form_to_scaffold`
- Fixed in: `src/file/cli.rs`
