# BUG-20260921-1030: Migration rejects the managed healthy restart policy

## Summary

The migration preflight accepts only Docker's `no` restart policy, but the
appliance deliberately promotes healthy engines to `unless-stopped`.

## Reproduction

The signed live dry-run rejects the healthy Qwen generation with
`container must be running without an independent restart policy`.
Exact-container inspection reports `Running: true` and
`RestartPolicy.Name: unless-stopped`.

## Expected

Accept managed `no` and `unless-stopped` policies, retain them, and use an
explicit exact-ID stop whose stopped state is verified before relocation.
Reject `always`, unknown policies and restart-policy drift before mutations.

## Root Cause

The preflight predicate did not match the production executor's
`PromoteRestartPolicy` behavior. `unless-stopped` respects an explicit stop even
after daemon restarts, unlike `always`:
[Docker restart policy contract](https://docs.docker.com/engine/containers/start-containers-automatically/).

## Fix

Use one allowlist predicate in preflight and exact-container lifecycle actions.
No Docker policy update, daemon restart, or host reboot is needed. Regression
tests cover the managed policy and reject unsupported policies before stopping.

## Traceability

- Sparkplane `src/migration/appliance.rs`, `src/migration/docker.rs`.
- Sparkplane `tests/migration_host.rs`, `tests/migration_docker.rs`.
