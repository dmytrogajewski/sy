# BUG-20260829-1644: Responses could publish malformed tool arguments

## Summary

The OpenAI Responses stream encoder accepted an incomplete upstream function
argument document when the stream completed.

## Reproduction

- Feed a `ToolCallDelta` whose arguments contain only `{` to the generic
  Responses encoder.
- Complete the upstream stream with `Done`.
- Observe the encoder publish a completed function call instead of rejecting
  the malformed JSON.

## Expected

Every completed Responses function call has a non-empty call ID and name and
contains a valid JSON argument document.

## Actual

`ResponsesEncoder::done` finalized accumulated tool fragments without
validating their identity or JSON syntax.

## Root Cause

The Anthropic encoder already guarded tool completion, but the parallel
Responses completion path lacked the same engine-neutral validation.

## Fix

Validate every accumulated tool call at Responses completion and return the
existing invalid-request problem when identity is missing or arguments are
not valid JSON. No engine-, model-, or checkpoint-specific branch is added.

## Traceability

- Failing regression first:
  `responses_rejects_malformed_function_arguments_at_completion` in
  `tests/spark_openai_e2e.rs`.
- Implementation: the generic `ResponsesEncoder::done` path in
  `src/spark/gateway.rs`.
- Protocol qualification: valid one- and two-tool streams remain covered by
  the engine-neutral OpenAI gateway suite and the authenticated real-device
  matrix.
