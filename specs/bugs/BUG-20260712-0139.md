# BUG-20260712-0139: onboarding-retention deadlock — 7-day NDJSON retention makes the 14-day onboarding gate structurally unreachable

## Summary
The power daemon's onboarding gate can never trip. `onboarding.days = 14` (SPEC §2/§4, Apple Optimized-Battery-Charging mirror), but `compute_onboarding_status` derived `days_collected` from the OLDEST *surviving* `telemetry-YYYY-MM-DD.ndjson` entry, while `Logger::rotate_retention` deletes every telemetry file older than `DEFAULT_RETENTION_DAYS = 7`. So the onboarding anchor is pinned to "≤ 7 days ago" forever: `days_collected` plateaus around 7, never reaches 14, `active` never flips to `false`, the bandit stays frozen at the rules baseline, and the day-14 first-train never fires. The learning story is fully blocked. A June-8 `arms_hash` rotation independently reset the (already-doomed) progress once more — both causes are real, in sequence.

## Reproduction
- Method: code audit + live daemon state on the audit host.
- Live evidence (`sy power status --json`, 2026-07-12):
  ```
  onboarding.days_collected = 4          # daemon started collecting ~May
  onboarding.ready_at        = 2026-07-21   # keeps sliding forward every day
  model.version_sha          = "rules-baseline"
  ~/.local/state/sy/power/forecaster.onnx  → has never existed
  ```
  The daemon has been collecting telemetry since ~May, yet `days_collected` reads 4 and `ready_at` slides forward day-by-day (a clean signature of an anchor pinned to the retention horizon rather than to first collection). `model.version_sha` is still the frozen `"rules-baseline"` and no forecaster model has ever been trained.
- Code-level evidence:
  - `src/power/onboarding.rs::compute_onboarding_status` (pre-fix) anchored on `oldest_ndjson_entry_ts(...).or(mtime_fallback)` — the oldest *surviving* file.
  - `src/power/log.rs::DEFAULT_RETENTION_DAYS = 7`; `Logger::rotate_retention` deletes files older than 7 days on every boot (`daemon.rs` calls it once at startup).
  - `src/power/config.rs::DEFAULT_ONBOARDING_DAYS = 14`.
  - Net: `retention_days (7) < onboarding.days (14)` ⇒ the anchor can never age past ~7 days ⇒ the gate is unreachable.
  - The pre-fix test `handles_rotated_state_where_oldest_file_younger_than_first_run` even *documented* the plateau as "the intended onboarding-gate bound" — the deadlock was baked into the contract.
- Second, independent cause: a June-8 `arms_hash` rotation (`configs/sy/power.toml` arm-table edit) invalidated the checkpoint (`checkpoint::load` ⇒ `Ok(None)`), which — even had the anchor been correct — would have reset onboarding progress once. That reset is *by design*; it is only a problem when compounded with the retention deadlock.

## Expected
1. `days_collected` is anchored on when telemetry collection *first began*, not on the oldest file that survives the retention sweep, so it grows monotonically to 14 and beyond.
2. The anchor survives deletion of older NDJSON files.
3. The day-14 gate is reachable: with 14 days elapsed since first collection, `active` flips to `false`.
4. An `arms_hash` rotation intentionally resets the anchor (progress restart is accepted on an arm-vocabulary change).
5. A retention horizon shorter than the onboarding window is impossible-by-construction or, at minimum, surfaces a loud startup WARN.

## Actual
1. `days_collected` tracked the oldest surviving file (≤ retention_days), so it plateaued at ~7 and read 4 live.
2. Deleting old NDJSON slid the anchor forward, sliding `ready_at` forward with it — the countdown never lands.
3. The gate never trips; the bandit is frozen at `"rules-baseline"` forever; no model is ever trained.
4. (arms rotation reset already worked as designed — not the primary defect.)
5. No guard rail existed; `retention_days (7) < onboarding.days (14)` shipped silently.

## Root Cause
- **The onboarding anchor was derived from a resource the retention sweep actively destroys.** `days_collected` = `now − oldest_surviving_ndjson`, but `oldest_surviving_ndjson` is clamped to `now − retention_days` by `rotate_retention`. With `retention_days < onboarding.days` the anchor can never age to the gate — a structural deadlock, not a tuning issue.
- **No persisted "first telemetry" fact.** The system had no durable record of when collection began, so it reconstructed the anchor every tick from whatever files happened to survive.

## Fix
Implemented per the trainer-prep T4 checkpoint plumbing (`checkpoint.json` is the natural durable home for daemon-scoped learning facts):
1. **Persist a `first_telemetry_at` anchor** in `DaemonCheckpoint` (`src/power/checkpoint.rs`), `#[serde(default)]` so pre-fix checkpoints load with `None`. Added `checkpoint::read_anchor` for the read-only status paths (it ignores schema/arms drift — a schema bump must not blank the operator's countdown).
2. **`src/power/onboarding.rs`**: `compute_onboarding_status` takes a `persisted_anchor`; `resolve_anchor` gives it precedence over the oldest-NDJSON fallback. The daemon (`daemon.rs::run_async`) resolves the anchor once (`is_none()` guard freezes it), threads it through `compute_onboarding_status`, and persists it via `save_checkpoint_best_effort` so it stops sliding. The read-only callers (`status.rs`, `cli.rs`) read the persisted anchor so `sy power status` matches the daemon.
3. **Anchor reset on `arms_hash` rotation**: `checkpoint::load` already returns `Ok(None)` on an arms-hash mismatch; the daemon then leaves `first_telemetry_at = None` and re-derives — the by-design reset.
4. **Guard rail**: `onboarding::retention_guard(retention_days, onboarding_days)` returns a warning when `retention_days < onboarding_days`; `daemon.rs` logs it loudly at startup (`Logger::retention_days()` exposes the horizon). The persisted anchor makes the deadlock non-fatal, so a WARN (not a hard clamp) is the right severity.
5. **Hermetic tests**: `persisted_anchor_survives_ndjson_deletion` (anchor 10d old, only a 2d file survives ⇒ `days_collected == 10`), `gate_trips_with_persisted_anchor_14_days_old`, `resolve_anchor_prefers_persisted_over_ndjson`, `retention_guard_flags_short_retention`; plus checkpoint round-trip / `read_anchor` drift tests. The arms-rotation reset is covered by the existing `arms_hash_mismatch_returns_none_and_rotates_stale`.

## Migration
On first run with the fix, `first_telemetry_at` is absent from the existing checkpoint, so the daemon initialises the anchor from the oldest *surviving* NDJSON entry (currently `telemetry-2026-07-07`, i.e. the retention floor) and persists it. `days_collected` becomes honest from that instant and grows monotonically thereafter — it does not retroactively recover the ~May–July history the retention sweep already deleted, but it will never plateau again. The gate lands 14 days after the persisted anchor (≈ 2026-07-21 for this host), after which onboarding completes and the first train can fire. Operators wanting the full raw-telemetry window available during onboarding should set `retention_days >= onboarding.days`; the new startup WARN flags the mismatch.
