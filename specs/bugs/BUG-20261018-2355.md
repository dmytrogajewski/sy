# BUG-20261018-2355: PolicyKit helper fixture intermittently fails to execute

## Summary

Parallel PolicyKit tests intermittently fail before authentication begins because their generated executable returns `ETXTBSY`.

## Reproduction

- Method: Existing tests, repeated with the default parallel runner.
- Tests: `polkit::backend::tests::helper_receives_cookie_over_stdin_and_authenticates` and `cancellation_terminates_a_waiting_helper`.
- Command: Repeat `cargo test -p sy-desktop-shell --lib polkit::backend::tests::`.
- Evidence: Full workspace rerun failed both tests; focused test-binary repetition reproduced on iteration 2: `Start PolicyKit PAM helper: Text file busy (os error 26)`.

## Expected

The generated helper starts reliably, accepts its cookie and either authenticates or handles cancellation.

## Actual

Executing the generated helper sometimes fails before its script runs.

## Root Cause

The fixture keeps writable script descriptors in the multithreaded test process while other tests spawn subprocesses. Concurrent process creation can inherit such descriptors until exec closes them. Linux refuses to execute a script while any process retains a writable descriptor, even after the fixture closes its own handles.

## Fix

Close the initial temporary-file descriptor before creating the helper body in a separate shell process, then wait for that writer to exit. No writable script descriptor is held in the test runner during population. Keep the production PolicyKit helper unchanged.

## Traceability

- Failing tests and fixture: `crates/sy-desktop-shell/src/polkit/backend.rs`.
- Validation: 100 consecutive focused parallel repetitions passed. `make lint`, two consecutive `make test` runs (1,658 tests each), `make lint-spark` and `make test-spark` passed.
