# BUG-20260830-1238: Responses accepts reasoning-only completion

## Summary

A Spark Responses stream can report `completed` after the upstream model emits
reasoning, whitespace-only text, no tool call, and `finish_reason: stop`.

## Reproduction

- Method: integration test and live DGX Spark trace
- Test: `tests/spark_openai_e2e.rs::responses_rejects_reasoning_without_actionable_output`
- Command: `cargo test --features spark-agent --test spark_openai_e2e responses_rejects_reasoning_without_actionable_output -- --exact`
- Evidence: the assertion requiring `GenerationEvent::Done` to fail instead
  observed `Ok(())`. The live Codex trace completed with
  `last_agent_message: null` after 1,173 output tokens.

## Expected

The translated Responses stream terminates as failed so the client cannot
mistake an unfinished agent turn for success.

## Actual

The encoder emits `response.completed`, and Codex ends the turn without a final
message or the tool call described by the model's reasoning.

## Root Cause

`ResponsesEncoder::done` validates tool argument structure but does not require
actionable output. Whitespace creates a message output item, so reasoning plus
whitespace passes through as a completed response.

## Fix

The Responses encoder rejects a normal stop when there is no non-whitespace
text and no tool call. Streaming and JSON handlers propagate that rejection as
a failed response rather than discarding it.

## Traceability

- Failing test: `tests/spark_openai_e2e.rs::responses_rejects_reasoning_without_actionable_output`
- Fixed in: `src/spark/gateway.rs`, `src/spark/agent.rs`
