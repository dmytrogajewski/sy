# BUG-20260828-1812 — Semantic probe treats an output budget as an exact count

## Report

FreeToken reaches `status=ok` and returns a structurally valid OpenAI text
completion, but Spark startup rejects it when `usage.completion_tokens` is less
than the requested `max_tokens` budget.

## Evidence

The real DGX Spark response requested `max_tokens: 8` and returned
`finish_reason: "length"` with `completion_tokens: 7`. OpenAI-compatible
`max_tokens` is an upper bound, not an exact-count promise.

## Acceptance

- A completion with one through `max_tokens` computed tokens satisfies the
  semantic compute contract.
- A zero-token response and a count above the requested budget remain rejected.
- The rule remains engine- and model-neutral.
- The real FreeToken generation reaches the subsequent protocol probes.
