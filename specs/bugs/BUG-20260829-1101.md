# BUG-20260829-1101: pre-health container exit leaves a stale serve operation

## Summary

A managed container that exits during the readiness wait can remain durably
reported as `creating` while its serve operation remains `running` until the
full startup deadline expires.

## Reproduction

- Method: real-device manual reproduction followed by a deterministic IPC test.
- Test: `src/spark/agent.rs::tests::exited_container_interrupts_engine_readiness_wait`.
- Command: `sy spark dgx-spark serve qwen3.8:flash-next --name qwen38-sglang-qualification --detach --json`.
- Evidence: generation 12 exited with code 137 and `OOMKilled=false` at
  `2026-08-29T07:57:06Z` after the resource guard observed a red memory floor;
  more than one 30-second reconcile interval later, `ps` still reported
  `desired=running observed=creating`, and operation
  `01M167KY8SVGHTY86622EZM9EF` remained at `state=running stage=creating` with
  its last durable update at `2026-08-29T07:44:17Z`.

## Expected

The active readiness worker detects that its exact managed generation exited,
records a bounded start failure, drains any route, and terminates the serve
operation without waiting for the configured startup deadline.

## Actual

The readiness worker polls only HTTP, holds the transition lease, and prevents
periodic reconciliation from acquiring that generation until the health
deadline expires.

## Root Cause

`run_serve` held the per-generation transition lease while
`wait_until_engine_ready` polled only HTTP, cancellation, and stopped intent.
Periodic reconciliation correctly observed Docker state, but could not acquire
that same lease. An executor resource-guard exit therefore remained hidden from
the active worker until the whole engine startup deadline elapsed. The first
inspection implementation reused the full live-engine observer, which requires
a non-zero init PID and process identity. Docker reports PID zero after a clean
exit, so the inspector returned a transport-level failure instead of the exact
generation's non-running state.

## Fix

The readiness interrupt now asks the existing privileged executor protocol for
only the exact generation's running state. That inspection validates managed
labels without requiring live process metadata. A missing or non-running exact
generation interrupts HTTP readiness immediately; executor transport failures
do not invent an exit. `fail_serve` then performs the existing bounded cleanup,
diagnostic persistence, and terminal operation transition. The regression tests
prove a stopped Docker observation is inspectable and require a non-running
generation returned through real executor IPC to interrupt a five-second
readiness deadline within 100 milliseconds.

## Traceability

- Failing tests: `src/spark/executor.rs::tests::stopped_managed_container_is_an_inspectable_non_running_generation`, `src/spark/agent.rs::tests::exited_container_interrupts_engine_readiness_wait`
- Fixed in: `src/spark/agent.rs`, `src/spark/executor.rs`
