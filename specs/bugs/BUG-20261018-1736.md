# BUG-20261018-1736: Screen unlock repairs transport instead of prompting phone

## Summary

Swaylock can fail to trigger phone approval on Enter, while a later sudo works.

## Reproduction

- Real desktop journal at 17:35:13–17:35:17: swaylock's challenge hit a cached
  notification writer with Broken pipe; GATT rebuilt at 17:35:15, subscription
  restored at 17:35:22. Sudo phone authentication succeeded at 17:35:29.
- `pamtester swaylock dmitriy authenticate`: phone success at 17:36:40.
- Real `/usr/bin/swaylock` in an isolated headless Sway compositor, empty Enter:
  daemon challenge 17:38:48; phone success and locker exit 17:38:51.
- `strace` confirms swaylock loads the managed PAM file, reads the active bond,
  and connects to `/run/user/1000/syauth/auth.sock`.

## Expected

Phone transport recovers independently of authentication. A ready subscription
accepts the first screen-unlock challenge; ordinary disconnect does not rebuild
the GATT application or disconnect unrelated Bluetooth devices.

## Actual and root cause

The PAM module is already installed for swaylock. Desktop transport keeps a
dead notification writer until the next authentication request, then rebuilds
the GATT application and returns transport-error. The next request can succeed
after resubscription. This is the stale-writer finding from the recovery report.

## Fix and traceability

Implementation and lifecycle regression coverage belong in sibling syauth's
`crates/syauth-transport/src/peripheral.rs` and notification-session module.
Observe notification-session closure independently, discard only the closed
session, and keep the GATT registration stable across ordinary disconnects.
Live validation must use the headless locker and confirm no application rebuild
across a phone radio cycle. Pairing confirmation architecture remains separate.

The sibling transport now owns a replaceable notification channel, monitors
closure in the GATT control task, and drops only the failed session on send
error. It no longer rebuilds the application during authentication. Six
socket-backed lifecycle regressions, the workspace suite, Clippy, formatting,
and a release daemon build pass. Dependency lint retains the existing three
unmaintained D-Bus advisory failures. Deployment/radio validation awaits the
phone, which disconnected from USB during the investigation.

Final results: sy 1,638 passing tests / 12 ignored, Spark bridge 17 passing;
syauth 467 passing / 8 ignored on two full runs. sy lint passes. At 17:50 the
desktop authorization request for installing the release daemon timed out.
Installed-binary checksums remain unchanged and the original daemon is active.
The fix is built in the sibling repository but is not deployed. Resume with
authenticated installation, then verify radio recovery and real screen unlock.
