# BUG-20260827-0509: Declarative vision profile was ignored

## Summary

The pinned llama.cpp engine mounted the projector but the generic profile could not declare a vision health contract, so image-capable models were rejected at the gateway.

## Reproduction

A real Qwen image request returned HTTP 400 with `image input requires a vision profile` even though the immutable artifact set contained the verified projector.

## Fix

Engine profiles now deserialize and validate an optional generic vision policy. Capability/policy parity, processor digest, limits, media types, fixture hash, and expected health response are checked before publication; no model identity is encoded in Rust.

## Traceability

- Tests: `spark::engine::tests::catalog_profile_loads_declarative_vision_policy`, `spark::engine::tests::vision_capability_requires_profile_policy`
