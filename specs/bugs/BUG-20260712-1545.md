# BUG-20260712-1545: power trainer is dead on live hosts (reads the telemetry directory as one file, writes the wrong model name, and drops trained models on restart)

## Summary
The retrain scheduler's first-ever dispatch fails immediately because the
daemon hands the trainer the telemetry *directory* as if it were a single
NDJSON file; on top of that the daemon writes the model to `forecast.onnx`
while the CLI + status path expect `forecaster.onnx`, and a trained model
is silently discarded on daemon restart because startup always seeds the
embedded warmup fixture.

## Reproduction
- Method: unit tests (hermetic) + live daemon evidence
- Tests:
  - `crate::power::trainer::tests::reads_directory_corpus_across_segments`
  - `crate::power::trainer::tests::reads_directory_corpus_orders_numeric_overflow`
  - `crate::power::trainer::tests::single_file_corpus_still_trains`
  - `crate::power::trainer::tests::empty_directory_is_insufficient_data_not_panic`
  - `crate::power::daemon::tests::retrain_trigger_writes_forecaster_onnx`
  - `crate::power::daemon::tests::startup_loads_trained_model_over_warmup`
  - `crate::power::daemon::tests::startup_falls_back_to_warmup_on_corrupt_model`
- Evidence (live, 2026-07-12 15:28 local):
  ```
  INFO  "retrain scheduler dispatched (AC + idle + SOC gates open)" cause=Onboarding
  WARN  "trainer retrain failed" error="trainer: read telemetry log failed: Is a directory (os error 21)"
  ```

## Expected
On the first tick where the retrain gates open, the trainer reads the
daily-segmented telemetry corpus under `~/.local/state/sy/power/`, trains a
GRU, and writes `forecaster.onnx`; on the next daemon restart the trained
model is loaded from disk instead of the embedded warmup fixture.

## Actual
The trainer receives `state_root` (a directory) and calls `fs::File::open`
on it, which returns `Is a directory (os error 21)` → `TrainerError::ReadFailed`.
The GRU can never train on a live host. Even if it could, the daemon wrote
`forecast.onnx` (not the `forecaster.onnx` the CLI/status convention pins,
`src/power/cli.rs:1310`), and every daemon start re-seeds
`ForecastTickState::warmup()`, so a trained model would be discarded on the
next restart.

## Root Cause
Three coupled defects, all in `src/power/`:

1. **Corpus reading** — `trainer::read_labelled_rows` (`src/power/trainer.rs`)
   opens `telemetry_path` as a single NDJSON file. Live telemetry is
   daily-segmented: `telemetry-YYYY-MM-DD.ndjson` plus overflow segments
   `telemetry-YYYY-MM-DD.N.ndjson` (commit 22df459). The daemon passes the
   directory, so `File::open` fails with `EISDIR`.
2. **Filename** — `daemon::run` built the trigger with
   `out_path: state_root.join("forecast.onnx")`, diverging from the CLI
   convention `forecaster.onnx` (`src/power/cli.rs:1310`). A trained model
   would land at a path `sy power status` / `sy power train` never read.
3. **Startup reload** — `daemon::run` unconditionally seeds
   `ForecastTickState::warmup()`; there is no path that loads a previously
   trained `forecaster.onnx` from disk, so a trained model is lost on every
   restart.

## Fix
1. **Corpus reading**: `read_labelled_rows` now accepts a directory. When
   given a dir it enumerates every `telemetry-*.ndjson` segment, sorts them
   chronologically by `(date, overflow-index)` — the overflow suffix is
   parsed as an integer so `.10` sorts after `.2` — and concatenates their
   rows; single-file paths keep the original behaviour. Non-matching entries
   (`checkpoint.json`, `forecaster.onnx`, `reports/`, …) are skipped. A
   directory with zero matching segments yields zero rows, which flows into
   the existing `InsufficientData` path (no panic).
2. **Filename**: the daemon builds the trigger via
   `SpawnBlockingRetrainTrigger::for_state_root`, which pins
   `out_path = <state_root>/forecaster.onnx` and `telemetry_path = <state_root>`.
3. **Startup reload**: `ForecastTickState::load_or_warmup(state_root)` loads
   `<state_root>/forecaster.onnx` when present and parseable (preferring the
   trained model over warmup); a missing file falls back to warmup silently
   (fresh host), and a present-but-corrupt file WARNs once and falls back to
   warmup — a bad model file never crashes the daemon.
