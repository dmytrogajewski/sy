# BUG-20260829-1036: Verified persistent cache cannot cross an image identity

## Summary

A content-addressed engine image change correctly creates a fresh JIT-cache
namespace, but that namespace also strands a 47.7 GiB immutable model-derived
artifact. Rewriting the same artifact would violate the Spark disk reserve.

## Reproduction

- Method: ordinary candidate-priority `sy spark serve --dry-run` on the real
  `dgx-spark`, followed by a hermetic promotion regression test.
- Test: `tests/spark_cache_promotion.rs`.
- Evidence: the exact Step 8 image was present locally, but admission projected
  the complete compile-cache envelope again and rejected `spark.disk.reserve`.

## Expected

An operator can promote an immutable cache artifact into a fresh execution
namespace without copying its blocks only after validating it byte-for-byte
against the exact ordered tensors in the immutable model index. The promoted
marker binds source identity, shape, dtype, byte count, transform, and SHA-256,
and publication leaves one read-only shared inode.

## Actual

The lifecycle intentionally isolates all compile-cache contents when image
identity changes and has no bounded way to distinguish a reusable model-derived
artifact from image-specific JIT output.

## Root Cause

PLE persistence originally shared the engine's execution cache namespace.
That is correct for generated kernels but too coarse for a source-derived table
whose content transform is unchanged across a runtime-only image rebuild.

## Fix

`scripts/promote-spark-cache.py` implements a generic, fail-closed promotion
contract. It streams the selected safetensors payloads in declared numeric
order, independently hashes the existing artifact, verifies both hashes and
all marker identities, then atomically hard-links the artifact and publishes
the new marker. Corrupt content is rejected before the destination exists.

## Traceability

- Positive test: `exact_source_validation_promotes_a_cache_inode_without_copying_it`.
- Negative test: `content_mismatch_is_rejected_before_destination_publication`.
- Real-device acceptance: Step 9 candidate admission, cold start, warm restart,
  and filesystem inode evidence in
  `specs/runs/qwen38-sglang-qualification.md`.
