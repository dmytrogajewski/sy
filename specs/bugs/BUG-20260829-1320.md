# BUG-20260829-1320: Admission hides the authoritative compile-cache namespace

## Summary

The dry-run admission report exposes the selected engine and artifact identity
but not the exact compile-cache namespace calculated by the executor. A cache
promotion operator must therefore duplicate a private Rust hash contract.

## Reproduction

- Run `sy spark dgx-spark serve qwen3.8:flash-next --name
  qwen38-sglang-qualification --dry-run --json` for a new engine image.
- Observe that the report contains the engine fingerprint but no candidate
  compile-cache namespace.
- Reimplementing the NUL-delimited identity externally produced a valid but
  unused namespace when one trailing delimiter differed.

## Expected

The admission report carries the exact namespace returned by the executor's
production candidate-storage calculation. Generic cache migration consumes
that opaque value and never reproduces the identity hash.

## Actual

Only the projected disk growth is returned to the admission handler, so the
authoritative namespace is discarded before the public dry-run response.

## Root Cause

`candidate_disk_growth` collapses `CandidateStorage` to a byte count and
`AdmissionSelection` has no field for the executor-calculated namespace.

## Fix

Preserve the executor's relative compile-cache namespace in
`CandidateStorage`, propagate it through admission, and publish it in the
selection document. Serve still derives disk growth from the same storage
record. Promotion treats the namespace as opaque.

## Traceability

- Executor regression: candidate storage reports the same namespace mounted
  into the managed container.
- Agent regression: dry-run admission publishes the executor-reported
  namespace without recalculating it.
- Real-device acceptance: promotion to the emitted namespace changes the
  admission result without copying the shared PLE inode.
