# BUG-20260829-0930: Runtime tool rejection gate succeeds with tools present

## Summary

The clean image build published even though CMake and Ninja survived the
runtime hardening stage.

## Reproduction

- Method: clean ARM64 Docker build followed by final-image tool discovery.
- Test: `tests/spark_engine_image_contract.rs::contracted_runtimes_attest_their_jit_tool_policy`.
- Evidence: the original negated `command -v` loop encountered installed tools
  but the shell continued and returned success from a later absent tool.

## Expected

Every tool declared rejected fails the image build immediately when it remains
discoverable, while every declared JIT tool must remain discoverable.

## Actual

Negation inside the shell loop did not provide a fail-closed per-tool branch,
so an earlier discovery was masked by later iterations.

## Root Cause

The gate depended on aggregate shell exit behavior rather than explicitly
exiting on each rejected tool.

## Fix

Drive both retained and rejected tool lists from OCI policy labels and use an
explicit `if command -v ...; then exit 1; fi` rejection branch.

## Traceability

- Failing test: `tests/spark_engine_image_contract.rs::contracted_runtimes_attest_their_jit_tool_policy`.
- Fixed in: `configs/sy/spark/engines/sglang-qwen38-mmap.Dockerfile`, `tests/spark_engine_image_contract.rs`.
