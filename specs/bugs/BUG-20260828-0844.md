# BUG-20260828-0844: Non-stream Chat requests fail through the Spark gateway

## Summary

The OpenAI Chat compatibility route adds `stream_options` to requests whose
`stream` value is false, so strict vLLM engines reject valid non-stream calls.

## Reproduction

- Serve `qwen3.8:flash-next` with the patched vLLM engine on `dgx-spark`.
- Cancel one streamed Responses request, then issue a non-stream Chat request.
- The engine stays healthy and answers the equivalent direct request, while
  the gateway returns HTTP 503 and vLLM records HTTP 400.

## Expected

Streaming requests ask the engine to include terminal usage. Non-stream
requests omit the streaming-only option and return a normal JSON document.

## Actual

`rewrite_chat_request_with_profile` unconditionally inserts
`stream_options={"include_usage":true}`.

## Root Cause

The Chat rewrite did not bind the upstream `stream_options` field to the
already-computed public `stream` mode. The generic error mapping then obscured
vLLM's validation response as an upstream-unavailable 503.

## Fix

Insert `stream_options` only when `stream` is true, matching the existing
Completions rewrite and the vLLM/OpenAI request contract. Verify both modes in
one public rewrite regression test, redeploy, and repeat live cancellation plus
an immediate non-stream follow-up on the real Spark.
