# BUG-20260828-1039: Patched vLLM is removed during valid cold start

## Summary

The Qwen3.8 Flash-Next NVFP4 engine can finish loading its weights and enter
CUDA-graph warmup, yet the executor removes it when the generic 15-minute
startup ceiling expires.

## Reproduction

- Start `qwen3.8:flash-next-nvfp4` from a cold generation on `dgx-spark`.
- Observe both PLE mmap passes, 79.42 GiB resident model memory, torch compile,
  MTP-head compile, and KV-cache allocation complete.
- The engine remains in final graph capture when the configured 900 seconds
  elapse; the executor removes the container and leaves no serving route.

## Expected

The signed declarative engine profile has enough bounded startup time for a
real single-Spark cold start, while the executor continues to reject
unbounded deadlines.

## Actual

The valid engine generation is destroyed at the 15-minute ceiling before its
health and semantic-readiness probes can complete.

## Root Cause

The global engine startup safety ceiling and the specialized model profile
both assume 900 seconds. Real NVFP4 + PLE mmap + CUDA-graph initialization can
exceed that bound even when every initialization stage is progressing.

## Fix

Raise the generic bounded startup ceiling to 30 minutes from one shared
constant and configure the specialized engine with that declarative deadline.
Verify a cold start and protocol probes on the real Spark.
