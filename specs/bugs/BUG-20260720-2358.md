# BUG-20260720-2358: onboarding countdown overstates remaining time by a day

## Summary
The "learning Xd Yh" countdown (waybar `custom/sy-power` pill and the
`custom/pwr` popup tooltip) double-counts a partial day: the days
component comes from `target_days - days_collected` (a floor of
*elapsed* time, hence a ceil of *remaining*) while the hours component
comes from the true `ready_at - now` residual, so 8.5 hours before the
gate trips the pill reads "1d 8h" instead of "0d 8h".

## Reproduction
- Method: test
- Test: `power::status::tests::onboarding_hint_counts_down_from_ready_at`
  and `power::status::tests::waybar_onboarding_text_counts_down_from_ready_at`
- Evidence:
  ```
  assertion `left == right` failed: 8.5h remaining must render 0d 8h, not double-count the partial day
    left: "learning 1d 8h"
   right: "learning 0d 8h"
  ```
- Live-host sighting (2026-07-20 ~23:45 local): anchor
  `first_telemetry_at = 2026-07-07T05:46:28Z`, `days_collected = 13`,
  `ready_at = 2026-07-21T05:46:28Z` (~8h away) — popup showed
  "sy learning 1d 8h".

## Expected
Both countdown components derive from the single `ready_at - now`
delta: `days = hours_total / 24`, `hours = hours_total % 24` →
"learning 0d 8h" with 8.5 h remaining.

## Actual
`waybar_text` (src/power/status.rs) computed
`days_left = target_days - days_collected` and glued it to
`onboarding_hours_remainder`'s `(ready_at - now) % 24` residual;
`onboarding_hint` duplicated the same shape. Because `days_collected`
floors elapsed whole days, `target - collected` ceils the remaining
days, so the pill overstates by 24 h at every instant except an exact
day boundary.

## Root Cause
Two independent time sources for one countdown. `days_collected`
exists for the *progress* view ("day 13 of 14") and floors the elapsed
delta; the countdown needs the *remaining* delta. Mixing the floored
elapsed count with the true remaining-hours residual double-counts the
fractional day that has already elapsed. The pre-existing fixtures
(`ready_at = now + days(11)` exactly, asserting only `contains("11d")`)
sat on the one boundary where both shapes agree, so the bug was never
pinned.

## Fix
Replaced `onboarding_hours_remainder` with `onboarding_countdown`,
which splits the single `(ready_at - now).num_hours().max(0)` value
into `(days, hours)`; both `waybar_text` and `onboarding_hint` now
render from it. The now-unused `target_days` parameter dropped from
`waybar_text`. Boundary fixtures updated to assert the full "Xd Yh"
shape off `ready_at`.

## Traceability
- Failing test: src/power/status.rs
  (`onboarding_hint_counts_down_from_ready_at`,
  `waybar_onboarding_text_counts_down_from_ready_at`)
- Fixed in: src/power/status.rs (`onboarding_countdown`,
  `waybar_text`, `onboarding_hint`; fixtures
  `waybar_class_onboarding_during_first_14d`,
  `onboarding_hint_renders_only_while_active`)
