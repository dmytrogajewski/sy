# JOURNEY-20260828-1200: Serve Qwen3.8 27B with MTP speculation

## Actor & Goal

- Actor: A sy user launching a coding agent against a DGX Spark.
- Goal: Serve the recommended Qwen3.8 27B Q4 target with its verified Q4 draft and preserve reasoning while llama.cpp performs MTP speculative decoding.
- Hardest constraint: Every runtime choice and artifact remains declarative, immutable, and identity-verified without a model-name branch in Rust.

## Happy Path

1. The user downloads `qwen3.8:27b` → the catalog resolves the pinned Q4_K_M target, Q4_0 draft, and projector through `src/spark/model_catalog.rs` → `ls` reports one installed model identity containing all three artifacts.
2. The user serves the alias → `src/spark/engine.rs` selects the declared Qwen profile and binds the target and draft artifact roles to engine arguments → `ps` reaches `Healthy` with the selected engine and artifact fingerprints.
3. The executor starts llama.cpp → the engine configuration supplies `--model-draft`, `--spec-type draft-mtp`, and `--reasoning-preserve` → engine logs report MTP speculation without downloading files at runtime.
4. The user launches Codex, Claude, or OpenCode → the existing gateway streams reasoning, tools, and answer content → the agent receives a complete reasoning-preserving response with lower decode latency.
5. A fresh benchmark runs on `dgx-spark` → sy records engine throughput and validates tool use → the user receives measured target/draft acceptance and generation speed.

## Edge Cases

- **Draft artifact is missing or its digest differs**: download or admission fails before engine start and identifies the invalid artifact (surfaced via: stderr and nonzero exit code).
- **Selected engine lacks a draft-model binding**: engine planning fails closed instead of silently serving without speculation (surfaced via: operation error and engine log).
- **Target and draft exceed available memory**: the existing memory admission policy rejects the start without disturbing a healthy model (surfaced via: operation error and `ps`).
- **llama.cpp rejects MTP arguments or the draft architecture**: semantic health never publishes the route and the container failure remains visible in bounded logs (surfaced via: `ps` and `logs`).
- **Client cancels a stream**: the route returns to healthy service for a subsequent generation; cancellation must not poison CUDA state (surfaced via: successful follow-up request).

## Acceptance Criteria

- [ ] Wire and catalog tests preserve the `draft_model` artifact role and exact immutable Qwen artifacts.
- [ ] Engine tests prove the draft artifact binds only through declarative role arguments and fails closed when unbound.
- [ ] The installed engine argv contains the target, draft, MTP mode, and reasoning-preservation flags.
- [ ] A real `dgx-spark` download, serve, stream, cancel/retry, and throughput benchmark passes.
- [ ] `make lint` and two `make test` runs are green.
- [ ] Spark reference documentation describes declarative draft artifacts and MTP profiles.

## Out of Scope

- A reasoning token guard is intentionally excluded by the user's decision.
- DGX OS, kernel, driver, CUDA, firmware, Docker, and platform updates remain prohibited.
