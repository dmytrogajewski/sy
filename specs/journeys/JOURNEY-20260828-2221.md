# JOURNEY-20260828-2221: Read compact Spark model and process lists

## Actor & Goal
- Actor: A workstation user operating the remote DGX Spark from an interactive terminal.
- Goal: See runnable downloaded models with `sy spark <host> ls` and only currently active model processes with `sy spark <host> ps`, without operational provenance obscuring the answer.
- Hardest constraint: Preserve stable machine-readable schemas and detailed inspection surfaces while making the default terminal output as scannable as Ollama.

## Happy Path
1. The user runs `sy spark dgx-spark ls` → the client reads the verified model inventory through `SparkClient::list_models` (`src/spark/client.rs:308`) → stdout is one aligned table with a runnable model name, short identity, size, and verification time per installed model.
2. The user runs `sy spark dgx-spark ps` → the client reads instances through `dispatch_instances` (`src/spark/cli.rs:804`) and retains only processes whose observed state is active → stdout is one aligned table containing the instance, model, engine, context, and current state.
3. The user needs provenance or automation data → `show`, `logs`, and `--json` retain the existing detailed documents (`src/spark/cli.rs:951`, `src/spark/cli.rs:868`, `src/spark/cli.rs:662`) → no fingerprints or immutable identities are lost from diagnostic and agent-facing surfaces.

## Edge Cases
- **No downloaded models**: `ls` prints the compact header and no invented rows, then exits successfully (surfaced via: stdout and exit code 0).
- **Only stopped, absent, or failed instances exist**: `ps` prints the compact header with no rows, and `ps --json` returns an empty `instances` array (surfaced via: stdout and exit code 0).
- **An instance is creating, warming, degraded, or stopping**: `ps` keeps it visible because a live lifecycle is still in progress and reports the exact observed state (surfaced via: the `STATE` column).
- **A model has no alias**: `ls` falls back to its repository name while retaining a stable short identity column (surfaced via: stdout).
- **Detailed diagnosis is required**: `show`, `logs`, and JSON output retain full immutable model, artifact, and engine identities (surfaced via: stdout).

## Acceptance Criteria
- [x] Human `ls` output is a single Ollama-style table and contains no fingerprints, canonical revisions, transport details, or repeated per-model blocks.
- [x] Human `ps` output is a single compact table and excludes absent and failed instances.
- [x] `ps --json` contains only active lifecycle instances; `ls --json` retains the complete installed inventory document.
- [x] `show` and the identity prelude of `logs` retain complete provenance.
- [x] Empty and unaliased inventories render deterministically.
- [x] The real `sy spark dgx-spark ls` and `ps` journey succeeds with the freshly built local CLI.
- [x] `make lint && make test` green.
- [x] Spark CLI reference and README describe the compact/default versus detailed/JSON split.

## Out of Scope
- Changing the Spark control-plane wire schema: compactness is a client rendering and command-semantics concern.
- Deleting historical instance records: `ps` filters the view without mutating durable state.
- Adding sorting or filtering flags: the requested everyday commands need useful defaults without new options.
