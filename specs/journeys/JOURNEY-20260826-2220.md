# JOURNEY-20260826-2220: Serve configured GGUF models on DGX Spark

## Actor & Goal

- Actor: A developer using `sy spark` from their workstation against the configured `dgx-spark` host.
- Goal: Download a configured immutable model alias, serve it with the configured optimal engine, and launch Claude, Codex, or OpenCode against complete streamed OpenAI- and Anthropic-compatible APIs.
- Hardest constraint: All model artifacts, runtime selection, and tuning must be declarative while startup remains fail-closed, durable across restarts, and verified on the real Spark without updating its OS, driver, CUDA platform, or firmware.

## Happy Path

1. The user runs `sy spark dgx-spark download <alias>` → the client sends the existing download operation (`src/spark/cli.rs:672`, `src/spark/wire.rs:360`), the agent resolves the alias to an immutable repository revision and exact artifact set, and the user sees resumable progress plus the canonical model identity.
2. The user runs `sy spark dgx-spark serve <alias> --dry-run` → admission reads verified artifact metadata, selects one compatible engine declaration instead of model-name code (`src/spark/engine.rs:85`, `src/spark/executor.rs:350`), and reports the engine, quantization, files, memory envelope, and immutable fingerprints without mutation.
3. The user runs `sy spark dgx-spark serve <alias>` → the executor mounts only the verified snapshot read-only, expands declared artifact placeholders, and launches a digest-pinned non-root CUDA llama.cpp container (`src/spark/executor.rs:350`) while operation progress reports pull, create, warmup, and validation phases.
4. The agent performs identity, semantic, OpenAI-stream, Anthropic-stream, reasoning, and tool-call probes before publishing the route (`src/spark/upstream.rs:157`, `src/spark/upstream.rs:300`) → the serve operation completes only when the advertised capabilities are true.
5. The user runs `sy spark dgx-spark ps` and `logs` → output identifies the model revision, selected engine and config fingerprint, exact artifact/quantization, generation, health, startup duration, and current endpoint (`src/spark/wire.rs:421`).
6. The user runs `sy spark dgx-spark launch claude|codex|opencode --model <alias>` → launch resolves the healthy route (`src/spark/launch.rs:347`), configures an isolated client session, and the user receives streamed reasoning, text, and tool calls through the matching compatibility API.
7. The user stops or restarts the instance → desired state is persisted before executor action, the same immutable configuration is reconciled after agent/Spark restart, and an explicitly selected FP8/vLLM artifact can use the separately configured fallback engine without any silent runtime substitution.

## Edge Cases

- **Unknown alias or absent configured artifact**: download and serve fail before mutation with the missing alias/file named and a stable non-zero exit code; no approximate model or quant is selected (surfaced via: operation error, stderr, JSON error).
- **Ambiguous GGUF files or missing projector**: artifact resolution fails closed unless the catalog or CLI identifies one exact primary file and all required auxiliaries; incomplete files are never mounted (surfaced via: download/serve operation error and journal detail).
- **No compatible or multiple equal-priority engines**: admission rejects the request and lists the conflicting artifact traits and engine IDs; Rust never guesses from the repository/model name (surfaced via: dry-run/serve error).
- **Memory admission fails**: existing reserve and emergency-floor checks reject startup before container creation and leave the currently healthy generation untouched (surfaced via: admission document, stderr, exit code).
- **Container, parser, or protocol probe fails**: the route remains unpublished, the generation is failed/quarantined with bounded logs, and no automatic switch to another engine changes semantics (surfaced via: operation, `ps`, `logs`).
- **Two concurrent serve requests**: idempotency and per-instance reconciliation produce one generation or a deterministic conflict; never two containers for one instance (surfaced via: operation result).
- **Cancellation or agent restart during download/start**: partial Hub content remains resumable, persisted desired state is reconciled, and no unverified artifact or unprobed route becomes active (surfaced via: operation state and journal).
- **DGX platform drift**: deployment aborts if the protected OS/driver/CUDA/firmware fingerprint changes; engine container installation may proceed without platform package upgrades (surfaced via: deploy verification failure).

## Out of Scope

- MTP, DFlash, or other speculative decoding until a pinned engine passes the correctness suite.
- One-million-token context, stress tests, or soak tests; they are not required for this delivery.
- DGX OS, kernel, driver, CUDA platform, firmware, or appliance-stack updates.
- Hardcoded model recipes, built-in model-name branches, or embedding operational catalogs in Rust.
