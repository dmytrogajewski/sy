# JOURNEY-20260825-2123: Preserve Ornith reasoning across Spark APIs

## Actor & Goal

- Actor: A developer launching Codex, Claude Code, or OpenCode against an Ornith instance on DGX Spark.
- Goal: Receive model reasoning, answer text, tool calls, terminal status, and usage through each client's native streaming and non-stream protocol without silent loss or cross-channel mixing.
- Hardest constraint: Preserve protocol-valid ordering and bounded memory while translating one private vLLM stream into three distinct public APIs.

## Happy Path

1. The actor launches a supported client with `sy spark dgx-spark launch ...` → sy creates an inference-only credential and protocol-specific base URL in [`src/spark/launch.rs`](../../src/spark/launch.rs) → the client starts without receiving Spark administrator authority.
2. The client sends a reasoning request → the gateway applies Ornith's coding sampling defaults only where the client omitted values, then rewrites the public alias to the private served identity in [`src/spark/gateway.rs`](../../src/spark/gateway.rs) → an explicit client value always wins.
3. vLLM emits `reasoning_content` (or the vLLM 0.19.1 `reasoning` spelling), answer content, tool-call deltas, usage, and completion → [`src/spark/upstream.rs`](../../src/spark/upstream.rs) converts every supported upstream delta into a protocol-neutral event → no reasoning token is silently discarded.
4. An OpenAI Chat client requests streaming or a final document → the gateway preserves `reasoning_content` separately from `content` → OpenCode receives incremental reasoning, answer, tools, finish reason, and usage.
5. Codex uses the Responses API → [`ResponsesEncoder`](../../src/spark/gateway.rs) emits a reasoning output item and reasoning-summary events before the answer/tool items, then assembles the same information for non-stream mode → Codex can display progress before final answer text.
6. Claude Code uses Anthropic Messages → [`AnthropicEncoder`](../../src/spark/gateway.rs) emits a thinking content block with thinking deltas before text/tool blocks and preserves it in the final document → Claude sees native Messages semantics and a normal `message_stop`.
7. The actor completes the turn → usage includes all generated tokens, including hidden reasoning, and finish status remains native to the selected API → billing/debug data agrees across streamed and assembled representations.

## Edge Cases

- **Reasoning consumes the whole output limit**: return the reasoning item/block plus a native length/max-token finish and usage instead of an apparently empty successful answer (surfaced via: SSE or JSON response).
- **Reasoning and answer arrive in multiple chunks**: preserve chunk order within each channel and emit each start/delta/done lifecycle exactly once (surfaced via: SSE event sequence).
- **Tool call follows reasoning without answer text**: close the reasoning item/block before opening tool input, retain valid indices, and finish with the native tool-call reason (surfaced via: SSE or JSON response).
- **Malformed or oversized upstream reasoning delta**: fail the bounded public stream using the existing protocol-native error path without leaking private engine data (surfaced via: SSE error or HTTP 503).
- **Client supplies sampling parameters**: preserve all supplied values; defaults fill only omitted values and never override the request (surfaced via: behavior and request-contract tests).
- **Client disables thinking where supported**: honor the client request and do not synthesize a public reasoning block when vLLM emits none (surfaced via: response shape).
- **Client disconnects mid-reasoning**: abort the upstream task and release the connection/token permit through existing stream drop semantics (surfaced via: no stuck instance or leaked permit).

## Acceptance Criteria

- [ ] Upstream SSE tests decode fragmented `reasoning_content` into ordered protocol-neutral reasoning events.
- [ ] OpenAI Chat streaming and non-stream tests preserve reasoning separately from answer text.
- [ ] OpenAI Responses streaming and non-stream tests cover reasoning-only, reasoning-plus-text, and reasoning-plus-tool output.
- [ ] Anthropic Messages streaming and non-stream tests cover thinking-only, thinking-plus-text, and thinking-plus-tool output.
- [ ] Sampling tests prove Ornith coding defaults and explicit client overrides for every launch protocol.
- [ ] Bounded malformed/oversized reasoning and disconnect paths remain fail-closed.
- [ ] Real `dgx-spark` OpenAI Chat, Responses/Codex, and Anthropic Messages/Claude probes show native reasoning progress and successful terminal events.
- [ ] `make lint && make test` pass twice.
- [ ] README protocol documentation describes reasoning support and sampling precedence.

## Out of Scope

- Cryptographically signing local-model reasoning as if it were generated by Anthropic; sy emits an explicitly local, deterministic compatibility signature instead.
- Persisting server-side conversations, reasoning, or response objects; the gateway remains stateless.
- Changing DGX OS, driver, firmware, CUDA, or container runtime versions.
- Load, stress, and soak testing; verification uses bounded single-request probes.

## Open Questions

- None. The public model is Ornith, the fallback engine remains vLLM, and the required public protocols are OpenAI Chat, OpenAI Responses, and Anthropic Messages.
