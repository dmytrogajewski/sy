# JOURNEY-20260825-0849: Launch a local coding agent on a Spark model

## Actor & Goal

- Actor: a sy workstation user at a terminal inside the project they want an agent to work on.
- Goal: run Codex, Claude Code, or OpenCode locally while all model inference is served by one verified, healthy model instance on `dgx-spark`.
- Hardest constraint: preserve one-command ergonomics without exposing the Spark administrator credential, weakening pinned TLS, or introducing arbitrary remote command execution.

## Happy Path

1. The user runs `sy spark dgx-spark launch codex --model ornith-1.5:9b` → sy loads the pinned host profile and authenticated HTTPS client through [`SparkClient::load`](../../src/spark/client.rs#L233) and resolves the alias through [`SparkClient::list_models`](../../src/spark/client.rs#L362) → stderr identifies the selected model and whether an existing instance can be reused.
2. No healthy exact instance exists → sy submits the same signed-recipe, resource-admitted lifecycle request used by [`dispatch_serve`](../../src/spark/cli.rs#L828), follows the durable operation through [`SparkClient::follow_operation`](../../src/spark/client.rs#L542), then re-reads [`SparkClient::instances`](../../src/spark/client.rs#L425) → the user sees bounded operation progress and a healthy published instance, or the precise policy refusal.
3. No usable launcher credential exists → sy checks token metadata through [`SparkClient::list_tokens`](../../src/spark/client.rs#L528), creates exactly one `inference`-scoped credential through [`SparkClient::create_token`](../../src/spark/client.rs#L520), and atomically stores bearer material in a private file → output names only the non-secret token ID; the gateway continues to require `TokenScope::Inference` for `/openai/` and `/anthropic/` routes as enforced by [`required_scope`](../../src/spark/agent.rs#L4006).
4. sy prepares the selected local adapter → Claude receives a process-local Anthropic environment, Codex receives sy-owned profile/catalog files, or OpenCode receives inline configuration; every adapter receives the pinned CA and inference-only credential without placing the bearer in argv or output → `--config` stops here and reports a stable launch plan.
5. Without `--config`, sy discovers the known local executable and starts it with inherited stdin/stdout/stderr and the current working directory → the chosen agent opens in the same terminal and operates on the current project while inference requests reach the path-prefixed Spark gateway.
6. The agent exits → sy propagates its numeric exit status, preserves the healthy Spark instance and saved host/integration/model selection, and leaves ordinary Claude, Codex, and OpenCode configuration untouched → a later launch without `--model` reuses the exact validated selection.

## Edge Cases

- **Requested model is absent**: sy performs no implicit mutable download, prints the immutable `sy spark <host> download <repository> --revision <commit> --alias <name>` remediation, and exits 2 (surfaced via: stderr and exit code).
- **Alias or instance resolution is ambiguous**: sy lists only non-secret candidate identities and requires an explicit model/clean state instead of silently choosing an endpoint (surfaced via: stderr and exit 2).
- **Admission rejects a cold start**: sy preserves the existing resource problem code and exits 3; it neither launches an agent nor writes a new selection/token/config (surfaced via: stderr/JSON and exit code).
- **Spark is unreachable or its CA pin differs**: the existing pinned client fails closed, no local child is started, and exit 4 is preserved (surfaced via: stderr and exit code).
- **Saved launch state is stale or malformed**: schema/identity validation rejects it without truncation; an explicitly supplied model can atomically replace stale non-secret selection only after remote validation succeeds (surfaced via: stderr and exit 2).
- **Saved inference token was revoked or its private file is missing**: sy revokes a known orphan when possible, provisions one new inference-only token, and atomically converges token ID plus bearer file; it never falls back to the bootstrap admin token (surfaced via: redacted stderr progress and token metadata).
- **Two launch commands race**: local state locking/atomic creation gives one winner; the loser reloads converged state, while server idempotency/deterministic instance naming prevents duplicate engine transitions (surfaced via: normal reuse output or bounded exit 3 on a genuine lease conflict).
- **Agent executable is missing**: an interactive session offers the same safe installer path Ollama supports for Claude/OpenCode; headless execution and Codex return an actionable install command without running a shell script implicitly (surfaced via: prompt or stderr and exit 2).
- **Forwarded Codex args override managed routing**: profile, model, provider, base URL, credential, and catalog conflicts are rejected before process spawn; unrelated tokens after `--` pass unchanged (surfaced via: stderr and exit 2).
- **User presses Ctrl-C or child exits non-zero**: terminal signals remain attached to the child and sy propagates an ordinary numeric child status; no model stop or user-config rollback is triggered (surfaced via: terminal behavior and exit status).
- **Configuration write fails halfway**: create-new staging/fsync/rename retains the preceding usable file set and no secret appears in the error (surfaced via: redacted stderr and exit 2).
- **`--restore` targets unowned Codex content**: sy refuses deletion unless ownership/schema markers match; normal user config and unrelated files are never removed (surfaced via: stderr and exit 2).

## Out of Scope

- Launching arbitrary executable names or commands on Spark, because it violates the closed appliance boundary.
- Guessing or downloading a mutable Hugging Face model reference, because Spark requires immutable provenance.
- Rewriting primary user/project agent configuration, because process-local or sy-owned isolated configuration is sufficient and reversible.
- Supporting Ollama's other registered integrations, because the requested surface is exactly Codex, Claude Code, and OpenCode and each additional client needs its own audited adapter contract.
