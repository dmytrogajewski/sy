# JOURNEY-20260828-2340: Run Qwen3.8-Flash-Next faster on one DGX Spark

## Actor & Goal

- Actor: A workstation user launching Codex, Claude, or OpenCode against the remote `dgx-spark` appliance.
- Goal: Use `qwen3.8:flash-next` through a qualified SGLang profile with faster code decode and growing-prefix reuse while retaining the current vLLM deployment as a recoverable control.
- Hardest constraint: Serve a 126.0 GiB checkpoint within the Spark's 121.6 GiB usable unified memory without reducing 262K context, reasoning, tool calls, streaming correctness, host reserve, or the generic declarative multi-engine architecture.

## Edge Cases

- **The SGLang image, source patch, engine declaration, or architecture is mutable or mismatched**: signed release validation or engine parsing rejects it before activation; the currently active release and running vLLM instance remain untouched (surfaced via: failed upgrade operation, stderr, and nonzero exit code).
- **The derived PLE file is absent after the exact model was downloaded**: sy creates it in a temporary path from the immutable source shards, verifies its transform identity and SHA-256, then atomically publishes it before engine start; cancellation leaves no trusted partial artifact (surfaced via: operation progress and bounded logs).
- **The derived PLE file is corrupt or belongs to another checkpoint/transform**: sy refuses to map it and regenerates only from the installed immutable snapshot; it never serves unverified embedding rows (surfaced via: operation state and bounded diagnostic log).
- **Available unified memory cannot preserve the configured 8 GiB emergency floor**: dry-run and real admission reject startup before Docker creates the engine; no running model is stopped to make room implicitly (surfaced via: admission report, stable rejection exit code, and status resource snapshot).
- **Two launch commands race for the same model**: idempotent serve and launch-state locking converge on one healthy managed instance and each client receives its own correct local configuration (`src/spark/launch.rs:107`, `src/spark/launch.rs:177`) (surfaced via: both commands identify the same instance).
- **HTTP health passes but reasoning, tools, or generation are unusable**: semantic and protocol probes keep the instance out of `Healthy`, preserve the diagnostic without model output leakage, and do not launch a coding agent (surfaced via: failed operation, `ps`, and bounded logs).
- **A growing-prefix cache path crashes or corrupts a stream**: the request returns a protocol-correct error, the managed instance is marked failed/restarted according to existing lifecycle policy, and the paired qualification fails; sy does not call this a performance win or silently disable reasoning (surfaced via: client error, instance state, restart count, and logs).
- **The user cancels the local coding agent**: the child exits with its original status while the healthy Spark instance and prefix cache remain available for another launch; cancellation does not revoke unrelated tokens or stop the model (surfaced via: terminal exit status and unchanged `ps`).
- **SGLang fails qualification or later regresses**: the user keeps or restores the signed release that selects the existing vLLM profile and serves the already installed snapshot without redownloading weights (surfaced via: rollback result, engine identity in `ps`, and a successful semantic probe).

## Acceptance Criteria

- [ ] The signed release contains a digest-pinned ARM64 SGLang engine declaration, exact source/patch identities, locked dependencies, and no mutable runtime reference.
- [ ] Engine matching and profile selection remain generic and declarative; a boundary test rejects Qwen-, SGLang-, or vLLM-name dispatch in the Rust runtime.
- [ ] The persistent PLE transform has example-first tests for exact layout/dequantization, source binding, atomic publication, corruption recovery, cancellation, and verified warm-start reuse.
- [ ] Resource admission tests cover the declared startup/steady envelopes and preserve the configured 8 GiB floor without changing host swap, clocks, driver, CUDA, kernel, firmware, or power configuration.
- [ ] Black-box gateway tests pass OpenAI Chat, OpenAI Responses, and Anthropic Messages in streaming and non-streaming modes with reasoning, usage, cancellation, and one/two tool calls.
- [ ] A ten-turn growing-prefix trace at 8K, 32K, 64K, and 128K passes without corruption or restart and demonstrates cache reuse; one bounded 240K retrieval plus cached suffix turn preserves the 262K claim.
- [ ] On the real `dgx-spark`, paired measurements use the same checkpoint, prompts, sampling, output limits, and otherwise idle appliance; code decode reaches at least 35 tokens/s and exceeds the matching vLLM median by at least 30%.
- [ ] On the real `dgx-spark`, cached growing-prefix TTFT improves by at least 80% at 32K, 64K, and 128K while cold TTFT is no more than 15% worse than vLLM.
- [ ] Fresh Codex, Claude, and OpenCode Tetris journeys under `~/sources/testbed` all produce runnable games; at least two complete at least 25% faster than their paired vLLM runs.
- [ ] The normal-ring MTP 3/4 candidate preserves reasoning, prose, tool JSON, streaming, and quality; experimental QSA ring widening is not selected.
- [ ] Warm restart reuses the verified read-only PLE artifact, performs no full rewrite, and starts faster than the measured 753,385 ms vLLM baseline.
- [ ] Candidate and control finish healthy with no unexpected restart, OOM, quarantine, or sustained swap growth, and available memory never crosses the 8 GiB emergency floor.
- [ ] `make lint && make test` is green with zero clippy warnings or flakes.
- [ ] README, Spark reference, install guide, engine configuration reference, and benchmark evidence describe SGLang selection, vLLM recovery, and the exact measured limitations.

## Out of Scope

- Updating or tuning the DGX Spark OS, firmware, kernel, NVIDIA driver, CUDA installation, clocks, power limits, swap, or boot configuration.
- Disabling reasoning, shortening the 262K model capability, weakening protocol support, or using a smaller checkpoint to inflate throughput.
- Embedding model recipes or engine-specific conditionals in Rust.
- Enabling the experimental wide QSA ring as the normal agent profile because its published prose result regresses materially.
- Making full-context concurrency above one a requirement on a single 128 GB Spark.
- Exposing SGLang directly outside the existing authenticated sy gateway.
- Adding endurance or overload checks beyond the bounded real-user qualification above.
